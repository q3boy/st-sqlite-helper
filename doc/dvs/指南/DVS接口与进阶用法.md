# DVS 接口与进阶用法

本篇供已有 DVS 卡片的作者按需查询。第一次制卡先按[DVS 作者使用手册](DVS作者使用手册.md)完成[青禾书店最小卡](../../../examples/dvs-minimal-card/README.md)，需要管理数据、调整提示词、增加业务计算或升级旧聊天时再读对应部分。

SQLite Helper 提供数据库和文件保存，DVS 管理每条 AI 回复对应的状态；业务字段、初值、规则及计算由作者决定。下面的代码片段各自说明一种接口用法，不是一张需要全部拼在一起的角色卡。

编辑器使用扩展包的 `types/dvs.d.ts` 及配套 `types/sqlite-helper.d.ts`，不要另外手写一份接口声明。声明与运行插件需配套更新。

## 标签与宏速查

先区分写在哪里：`[DVS:…]` 写在世界书条目名称中，决定条目的用途；`[[DVS_…]]` 写在内容中，用于输出数据或声明筛选、规划要求。例如名称 `[DVS:预处理,正文]人物状态` 的条目，可以在正文中写 `[[DVS_DATA_人物:yaml]]`。

### 世界书名称标签

下表列出当前支持的全部 14 个词组。作者按以下方式组织名称：

- 多个范围用英文逗号 `,` 连接，例如 `[DVS:预处理,正文]`。
- 范围与用途用英文分号 `;` 分隔，例如 `[DVS:正文;可筛选]`；同时写多个范围时用 `[DVS:正文,后处理;可筛选]`。
- 只写用途时直接填写，例如 `[DVS:筛选规则]`。同时声明预处理和后处理两种用途时，用分号分开，例如 `[DVS:筛选规则;变量规则]`；同一用途组内的互斥要求仍须遵守。

`DVS` 和英文 `DDL`／`COT` 不区分大小写，中文词组按表中原文填写。

| 词组 | 作用与适用位置 | 最小名称示例 |
| --- | --- | --- |
| `预处理` | 为正文前的输入增强提供参考，不自动成为可删除候选 | `[DVS:预处理]本轮参考` |
| `正文` | 给酒馆正文生成使用 | `[DVS:正文]文风` |
| `后处理` | 给正文结束后的变量请求提供普通上下文 | `[DVS:后处理]背景` |
| `可筛选` | 允许世界书筛选决定是否保留，自带预处理范围；需要进入正文时加 `正文` | `[DVS:正文;可筛选]雨天设定` |
| `筛选规则` | 世界书与变量行筛选共用的规则，自带预处理范围 | `[DVS:筛选规则]保留原则` |
| `世界书筛选规则` | 只用于世界书条目筛选，自带预处理范围 | `[DVS:世界书筛选规则]设定选择` |
| `变量筛选规则` | 只用于变量表行筛选，自带预处理范围 | `[DVS:变量筛选规则]物品选择` |
| `剧情规划` | 剧情规划的总规则及字段要求，自带预处理范围 | `[DVS:剧情规划]本轮安排` |
| `变量规则` | 变量更新的业务规则，自带后处理范围 | `[DVS:变量规则]变化规则` |
| `变量数据` | 变量请求的本轮起点数据模板，自带后处理范围 | `[DVS:变量数据]当前数据` |
| `变量COT` | 变量更新的可选分析、检查要求，自带后处理范围 | `[DVS:变量COT]核对事项` |
| `DDL` | 创建或迁移数据库结构，不进入模型上下文；名称后接版本 | `[DVS:DDL]v1.0.0` |
| `初始化` | 开场白数据库初值，不进入模型上下文；名称后接开场白编号、编号列表或 `*` | `[DVS:初始化]welcome_0,1,2` |
| `版本` | 主世界书内容版本，不进入模型上下文；使用精确名称 | `[DVS:版本]` |

`DDL`、`初始化`、`版本` 单独使用，按表中的名称格式填写。`可筛选`、三种筛选规则与`剧情规划`属于同一用途组，一条条目不能并列选择其中不同用途；`变量规则`、`变量数据`、`变量COT` 也不能在同一条目并列。范围组合不等于用途可以任意组合。

无标签时的默认范围、启用和激活条件见[世界书用途规则](#选择世界书条目的用途)；SQL 名称与读取方式见[SQL 接入](#为角色卡准备-sql)，内容版本见[版本检查](#主世界书版本检查)。旧标签对照集中在[旧卡转换](场景/旧卡转换.md#按完整标签组合核对)。

### 提示词内容宏

内容宏区分大小写：使用大写 `DVS_DATA`、`DVS_FILTER`、`DVS_PLOT`；格式写小写 `md` 或 `yaml`，配对词写小写 `start`、`end`。下表中的“表名、格式、key、条件、字段名”都是需要替换的参数，不要连这些占位文字一起照抄。

| 写法 | 用途与适用位置 | 最小例子 |
| --- | --- | --- |
| `[[DVS_DATA]]` | 在需要数据的提示词中输出全部准备表，默认 Markdown | `[[DVS_DATA]]` |
| `[[DVS_DATA:格式]]` | 指定全部准备表的输出格式 | `[[DVS_DATA:yaml]]` |
| `[[DVS_DATA_表名]]` | 输出指定准备表，默认 Markdown | `[[DVS_DATA_人物]]` |
| `[[DVS_DATA_表名:格式]]` | 指定单表输出格式 | `[[DVS_DATA_人物:yaml]]` |
| `[[DVS_DATA_表名:扩展key]]`、`[[DVS_DATA_表名:扩展key:格式]]` | 在宏位置输出指定扩展的内部工作表，默认 Markdown，可指定 `md` 或 `yaml`。两个格式名为保留字 | `[[DVS_DATA_日志条目:journal:yaml]]` |
| `[[DVS_DATA_表名:格式:key:条件]]` | 声明一个表行选择组，并在正文输出该组结果；启用筛选时须位于可参与预处理的条目中 | `[[DVS_DATA_物品:yaml:本轮物品:本轮需要使用的物品]]` |
| `[[DVS_FILTER:保留条件]]` | 写在可筛选世界书条目的内容开头，说明何时保留整个条目；开头允许空白 | `[[DVS_FILTER:本轮涉及雨天出行]]` |
| `[[DVS_PLOT:start:字段名]]` | 在剧情规划规则条目中开始一段字段要求；标记后写该字段的描述 | `[[DVS_PLOT:start:结束位置]]` |
| `[[DVS_PLOT:end]]` | 结束上面的字段要求，必须配对使用 | `[[DVS_PLOT:end]]` |

数据宏的来源与序列化规则见[正文数据注入](#正文数据注入)。正文使用 `narrativePrepare` 准备的数据，变量请求使用 `beforeGen` 准备的数据，不把正文裁剪结果当成完整业务状态。

四段数据宏的 key 是选择组标识，不是业务行的键；key 和条件不能为空，不能省略 key 写成三段。相同表名与 key 的声明须使用相同条件。全量宏不会自动变成筛选结果；关闭或跳过筛选时的行为、完整业务键要求见[世界书与表格筛选](#世界书与表格筛选)。

世界书条件宏作用于整个条目，不用 start/end 包裹；条件可换行，但不能包含结束符 `]]`。规划字段宏则必须在同一条目内成对出现，不能嵌套，字段名和描述不能为空。例如：

```text
[[DVS_PLOT:start:结束位置]]
说明本轮结束时的位置和正在进行的动作，不把下一步计划写成已发生。
[[DVS_PLOT:end]]
```

规划基础字段、覆盖规则与完整示例见[规划字段与完整示例](#规划字段与完整示例)。SQL 中的 `[[last_fid]]` 是另一类迁移标记，使用位置见[角色卡升级](#角色卡升级)，不要混入提示词宏。

## 独立调用模型

`DVS.llm(type, messages)` 在 0.6.2 发布后加入。使用提供此接口的构建时，作者脚本可在全局 `DVS` 就绪后直接调用，无须先注册变量功能。例如，使用玩家为变量更新选定的模型概括一段场景：

```js
await waitGlobalInitialized('DVS');
const summary = await DVS.llm('post', [
  { role: 'system', content: '用一句话概括场景，只返回摘要。' },
  { role: 'user', content: '掌柜收起门板时，发现门口放着一封没有署名的信。' },
]);
console.log(summary);
```

`pre` 使用「输入增强」选定的模型配置，`post` 使用「变量更新」选定的配置；两者都可以随时调用。传入非空消息数组，每条消息包含 `role`（`system`、`user` 或 `assistant`）和文本 `content`。DVS 只发送这些消息，不附加聊天、世界书或变量，也不保存楼层记录。

请求沿用所选配置的连接、生成参数及超时，输出格式固定为文本。即使配置为流式，`await` 也直接得到完整回复字符串。每次调用只请求一次，不检查「最小正文」，也不执行配置中的重试；配置不可用或请求失败时，脚本可用 `try/catch` 处理错误。

## 主世界书版本检查

可选方法签名：

```ts
lorebookVersionCheck(options: {
  onExpired: 'WARNING_MESSAGE' | 'AUTO_UPDATE';
}): Promise<void>;
```

独立酒馆助手脚本启动时调用一次：

```js
await waitGlobalInitialized('DVS');
await DVS.lorebookVersionCheck({ onExpired: 'AUTO_UPDATE' });
```

方法比较当前单人角色卡的 `data.character_version` 与当前主世界书中唯一版本条目的内容，不依赖变量开关或业务注册。新名称为 `[DVS:版本]`，旧 `[DVS_VERSION]` 继续兼容；按归一化后的版本条目总数检查唯一性，条目是否启用不影响读取。不扫描附加、全局或聊天世界书，也不从内嵌世界书补足版本。两侧版本均去首尾空白和可选的单个 `v`／`V` 前缀，按严格三段 SemVer 比较，支持预发布标识，构建元数据不影响优先级。例如 `0.2.0`、`v0.2.0` 有效，`0.2`、`vv0.2.0` 和前导零无效。卡片／世界书内容版本与 DDL 迁移版本各自维护。

主书版本相同或更高时正常完成，不提示、不更新。缺少当前单人角色、主书、唯一版本条目或有效版本时报告具体原因，不推定过期。主书较旧时，`WARNING_MESSAGE` 只提示过期；`AUTO_UPDATE` 先显示原生确认框，说明书名、双方版本及保留本地修改的方式。取消时正常返回，不读取内嵌来源、不写入数据。

点击“备份并更新”后，DVS 取得卡片内嵌的新版，把玩家现用的原书另存为备份。只有酒馆明确回复备份写入成功，才用新版覆盖原书；书名、主书关联和附加书列表保持不变。未收到备份成功回复时，提示“原世界书备份失败，请手动备份后重新导入卡内世界书”，停止更新。覆盖完成后核对主书内容、版本和关联；主书版本仍落后时报告更新未解决版本问题。

成功框显示新书、版本和旧书名，只有玩家点击“刷新页面”才重新加载整个酒馆页面；Esc 或关闭成功框不刷新。

调用完成返回 `void`，读取、版本格式或更新失败时拒绝 Promise，不刷新页面。如果酒馆已确认备份成功，后续更新失败时提示会给出备份名，便于玩家手动处理。独立脚本不与注册约定先后顺序，也不自动重试或跨刷新恢复。

## 注册与查询

新卡在角色卡绑定的酒馆助手脚本中设置预设定变量 `{ "dvs": { "enabled": true } }`。关闭或缺省不会注册、初始化；字符串 `"true"` 和数字不是有效开关。改动后按助手原生方式重载脚本。旧 `dvs_enable` 等开关在读取时自动转换为新结构并移除旧字段，保留其他作者变量；已有 `dvs` 时以它为准，格式错误会报告，不退回旧字段。完整映射见[旧卡配置升级](DVS作者使用手册.md#旧版-dvs-卡片升级)。

```js
const lifetime = new AbortController();
$(window).one('pagehide', () => lifetime.abort());
await waitGlobalInitialized('DVS');
const dispose = await DVS.register({
  scriptId: getScriptId(),
  uniqueKeys: { 角色: ['角色名'], 道具: ['持有人', '道具名'] },
  narrativePrepare: ({ tables }) => tables,
  beforeGen: (_state, tables) => tables,
}, { signal: lifetime.signal });

const state = await DVS.getState();
const person = await state.table('角色').get('阿呆');
const items = await state.table('道具')
  .query('持有人 = ? OR 数量 > ?', '阿呆', 2)
  .orderBy('数量', 'desc', '道具名', 'asc').rows();
```

注册规则：

- 同一角色只使用一个 DVS 注册脚本。
- 同脚本重新注册会替换声明。旧 dispose 不会清掉新注册。
- 作者传自身 `getScriptId()`。DVS 在父页面读取该脚本变量，不在共享方法内猜测发起调用的 iframe。

`waitGlobalInitialized('DVS')` 只表示公共接口已发布，不表示当前角色已启用或完成注册。玩家的浏览器尚未完成 SQLite Helper 的「自动设置」时，接口不发布，这一等待不会结束；玩家完成设置、保存并刷新页面后才继续。关闭 DVS 时变量功能的公共方法报未启用，不初始化或删除数据；Helper 基础接口仍可独立使用。注册脚本及其所在文件夹也须保持开启。

### 注册状态与脚本关闭

注册第二参数与订阅签名如下：

```ts
register(options: DvsRegistration, lifetime?: { signal?: AbortSignal }): Promise<() => void>;
onRegistrationChange(callback: (ready: boolean) => void | Promise<void>): () => void;
```

脚本生命周期 signal 应在等待 DVS 接口之前创建并绑定 `pagehide`，如上例所示。它只管理本次注册，仍可调用返回的 `dispose()` 主动注销；不传 signal 的旧调用保持可用。已终止的 signal 不开始注册，也不替换现有有效注册；准备等待期间终止立即使本次注册失效，原准备返回或失败后按实际取消或目标失效原因拒绝，不保证错误名为 `AbortError`，也不能因晚返回重新激活。注册成功后终止即注销。旧 signal 和旧 `dispose()` 不影响后来注册；不会因终止信号推断已开始的 SQL 已取消或已完成的初始化已回滚。

独立状态栏先等待公共接口、完成自身界面准备，再订阅注册状态，无须维护父页面就绪标记或自定义注册通知：

```js
await waitGlobalInitialized('DVS');
let stopData;
let stopProgress;
const stopRegistration = DVS.onRegistrationChange(ready => {
  stopData?.();
  stopProgress?.();
  stopData = stopProgress = undefined;
  if (!ready) {
    // 清空界面并禁用依赖 DVS 注册的操作。
    return;
  }
  // 读取当前数据和进度，并建立本次注册的更新订阅。
  stopData = DVS.onUpdate(() => { /* 重新读状态并刷新界面。 */ });
  stopProgress = DVS.onUpdateStatus(status => { /* 更新进度显示。 */ });
});
$(window).one('pagehide', () => {
  stopRegistration();
  stopData?.();
  stopProgress?.();
});
```

注册前即可订阅。`onRegistrationChange(callback)` 建立时直接调用一次 `callback`，传入本卡是否已完成注册。首次回调同步抛错会从订阅调用抛出，异步拒绝也须由回调自行处理。此后只通知就绪值变化，其他监听或注册不会因某个回调失败而中断。订阅跨重新注册有效，调用返回的取消函数或关闭运行时后停止。

注册准备中或失败为 `false`，完成为 `true`，替换开始或注销回到 `false`。同一角色切换聊天会沿用注册，页面不一定先收到 `false`；新聊天的数据能否读取，以该聊天的 `getState()` 结果为准。

`onUpdate` 和 `onUpdateStatus` 仍绑定建立时的注册，需要在新注册就绪后重新订阅；它们分别通知业务数据变化与变量处理进度，不能代替注册状态通知。

注册中的真实表名、业务键和数据库列名须一致，真实表必须有单列主键 `rid`。业务表名不能使用 `_dvs_`、`__stsh_` 保留前缀；业务键不能使用 `rid` 或 `_dvs_` 前缀，不能为空或重复。声明业务键不等于创建全表 SQL `UNIQUE`。

查询方法：

| 方法 | 行为 |
| --- | --- |
| `get(...keys)` | 按 uniqueKeys 的完整顺序传参。没有匹配返回 null，多匹配报错 |
| `row()` | 返回首行或 null |
| `rows()` | 返回数组。无排序时不承诺业务顺序 |
| `query` | 使用 SQL 条件与参数绑定 |
| `orderBy` | 接受实际列及小写 asc／desc |

`query(condition, ...values)` 的条件不带 `WHERE`，动态值使用 `?` 和后续参数传入。DVS 自动限制到该 fid 的有效集合。`table()`、`query()` 和 `orderBy()` 同步返回查询对象，`get()`、`row()`、`rows()` 异步取数据。不支持 `groupBy`。

读取哪个版本：

- 无参 `getState()` 取最近一条未隐藏 AI 回复的当前 swipe，跳过用户、系统和 narrator 消息。显式指定 `/hide` 隐藏的 AI 回复时，当前版本也会拒绝查询。
- 最新 AI 回复无 fid 时报未建立状态，不回退到更早回复。
- `DVS.getState({messageId:0,swipeId:0})` 可读当前聊天保留的历史版本，不切换界面。
- DVS 管理方法只允许最新 AI 回复的当前版本。

显式 `messageId` 须为非负整数，指向当前聊天实际存在的非系统 AI 回复；省略 `swipeId` 取该消息当前版本。用户、系统、narrator、越界版本或缺少 fid 都拒绝，不猜测替代目标。

每次 `getState()` 都进入当前聊天的数据准备路径；同目标、同注册等条件相同的在途准备可共用，完成或失败后释放。新的准备重新读取世界书，数据库内容按查询取得。取得的 state 固定到当时的角色、聊天及 fid；切聊天或切换 swipe 后重新 `getState()`，不要把旧对象当成新目标。

## 修改与逻辑事务

```js
const state = await DVS.getState();
await state.transaction(async tx => {
  const person = await tx.table('角色').get('阿呆');
  if (!person) throw new Error('角色不存在');
  person.金钱 -= 10;
  await person.update();
  await tx.table('道具').insert({ 持有人: '阿呆', 道具名: '短刀' });
});
```

事务边界：

| 操作 | 结果 |
| --- | --- |
| 单独的 `insert`、`update`、`remove` | 各提交一次事务 |
| `state.transaction` | 按回调登记顺序共同提交或回滚 |
| `update` | 插入 UUIDv7 新行版本，并替换当前 fid 索引 |
| `remove` | 只移除当前关联，历史业务行保留 |

字段约束、默认值、生成列和业务键比较交给真实 SQLite。提交后对象使用数据库实际值。

行对象规则：

- 同一 state 查到同一行时，行对象共享待保存修改。赋值后必须 `update` 才入库。
- `insert` 返回显式输入字段，重新查询可读取默认列。
- 生成列可读，不能直接赋值。
- 字段与 `$字段` 等价。与方法同名的列要加前缀：例如列名 `update` 用 `$update`，原列 `$HP` 用 `$$HP`。
- rid 隐藏，`JSON.stringify` 导出原业务字段。
- JSON 写为 TEXT，读取不会自动解析。
- BLOB 与 `state.fid` 读取均为副本。状态对象不提供各表的 `rid` 集合；需要原始记录标识时使用 `state.chat.query()` 编写 SQL。

逻辑事务内的限制：

- `get`／`rows`／`orderBy` 看到已加载和已登记的数据。不支持 `query` 或嵌套事务。
- 临时 `get` 在 JS 中比较显式或已加载的值，不模拟 SQLite 默认值、列亲和或 collation。最终键冲突由提交时的真实 SQL 检查。
- 回调不构成 SQLite 快照。网络、界面或直接 Helper SQL 的副作用不在这批事务中。
- 回调结束后临时对象关闭。需要长期对象时，请从原 state 再查询。

```js
const unsubscribe = DVS.onUpdate(async () => {
  const current = await DVS.getState();
  render(await current.table('角色').rows());
});
$(window).on('pagehide', unsubscribe);
```

以下情况会通知 `onUpdate` 监听：初始化关联成功、SDK 提交、目标切换和变量更新结束。

- 通知不能作为文件保存证据。
- 监听失败单独报告，不撤回成功写入。
- 不同 state、直接 SQL 与 Proxy 不自动同步。
- `state.char`／`state.chat` 是固定代理（创建时固定数据库目标的 Helper 代理）。通过它直接执行 SQL 时，业务和 DVS 索引由作者维护，接口不是 SQL 沙箱。

## 预处理表数据

`DVS.table(表名, 行列表?)` 同步处理内存数据。narrativePrepare、beforeGen 执行期间可省略行列表，直接使用本次回调的输入；也可显式传入指定数据。它自动保护注册的全部业务主键，仅转换副本，不修改输入或数据库；`state.table()` 仍用于数据库查询和管理。

| 方法 | 用途 |
| --- | --- |
| `excludeFields(names)` | 移除指定业务字段 |
| `excludeValues(values, scope?)` | 移除值严格匹配任一候选值的字段 |
| `replaceValues(from, to, scope?)` | 将严格匹配的字段值替换为副本 |
| `replaceText(from, to, scope?)` | 只替换字符串字段中的文字 |
| `rows()` | 返回当前处理结果的独立行列表副本 |

字段名可传字符串或字符串数组。`scope.fields` 指定只处理哪些字段，`scope.except` 排除字段，二者可组合；任何选择都不能改动注册业务键。

例如在注册的 narrativePrepare 中，隐藏角色的内部数值，并将物资未知信息显示为空白：

```js
narrativePrepare: ({ tables }) => ({
  ...tables,
  角色: DVS.table('角色')
    .excludeFields(['好感度', '相遇情境'])
    .excludeValues('未知')
    .rows(),
  道具: DVS.table('道具')
    .replaceValues('未知', '')
    .rows(),
})
```

上例要求对应角色字段存在于作者表中。姓名或持有人、道具名等注册业务主键即使值为“未知”，也会保留原值；其余字段是否隐藏由作者决定。

持久字段与正文显示字段可以分开。例如 `人物` 表只保存好感度，正文临时增加“关系描述”；这不是新增数据库列，不需要 DDL 迁移：

```js
narrativePrepare: ({ tables }) => ({
  ...tables,
  人物: tables.人物.map(({ 好感度, ...row }) => ({
    ...row,
    关系描述: 好感度 >= 60 ? '熟悉' : '初识',
  })),
}),
beforeGen: (_state, tables) => tables,
```

这里以 `姓名` 为业务键，阈值是示例作者的规则。变量模型仍收到数值起点，正文才收到派生描述。不要把派生列送回 `preUpdate` 的真实表，也不要在正文准备时写库。如果物品用 `['持有人', '物品名']` 定位，即使只显示部分字段，也必须保留两列原值；两个人持有同名物品是两行，查询、筛选和补丁都提供完整键。

默认数据可在回调内跨 await 使用，回调结束后释放。回调之外、更新订正／后处理或多个异步准备回调重叠时，请显式传入第二个参数；否则缺少或无法确定默认数据时会报错。其他脚本在准备回调执行期间调用辅助方法，也应显式指定数据来源。

```js
// 只处理说明、状态；也可用 except 排除指定字段，两者能组合使用。
DVS.table('道具', tables.道具)
  .replaceValues('未知', '', { fields: ['说明', '状态'] })
  .replaceText(/\r?\n/g, ' ', { except: '道具名' })
  .rows();
```

`excludeValues(['未知', '未填写'])` 可以移除多个候选值对应的字段。匹配按类型严格比较，不将 0、空字符串、NULL 或“未知原因”当作“未知”。`replaceText` 只处理字符串，字符串模式替换首处，正则模式按标记执行。辅助对象可用于不同准备回调；只调用它不产生保存或 onUpdate 通知。

## 正文数据注入

角色卡注册完成后，单人聊天的普通生成、重新生成最新回复和生成新 swipe 会先执行一次 `narrativePrepare`。普通追加取最近 AI 回复当前分支的数据；真正替换末尾 AI 回复时取它前一 AI 回复的数据。这里的“最近”“前一”都跳过 `/hide` 隐藏的回复，隐藏回复的变量不进入下一轮。末尾是用户消息时，重新生成仍按追加取值。只有开场白时使用当前已初始化的开场白，不重跑 INIT。

例如 A 的 hp 为80，用户输入下一句后生成 C，回调和只读模板查询都从 A 出发。回调可把提示词 hp 改成“受伤”，宏输出“受伤”，普通 EJS 仍读数据库中的80。准备回调返回值只影响本次提示词；回调通过 Helper SQL 明确执行的写入另按 Helper 契约处理，不因正文取消回滚。

在原生世界书中启用正文条目，例如：

```text
条目名称：[DVS:预处理,正文]角色状态
正文：请依据以下状态描写人物：
[[DVS_DATA_角色:yaml]]
```

条目的关键词、插入位置、角色和顺序继续由酒馆处理。`[DVS:预处理,正文]` 是用途标签；宏也可放在其他提示词文本中。总表用 `[[DVS_DATA]]`，分表用 `[[DVS_DATA_角色]]`，默认 Markdown，可加 `:md` 或 `:yaml`。重复标记分别替换，不递归执行替换结果中的新标记。未知表或格式报告错误并将该标记替换为空；准备失败则停止请求。

回调返回普通“表名 → 行列表 → 业务字段”数据。支持有限数值、字符串、布尔、NULL 和普通 JSON 数组／对象。SQL TEXT 原样保留；BLOB 须由作者在回调中转为合适的可表达值。函数、访问器、undefined、NaN／Infinity、类实例和循环引用会使准备失败。YAML 复用酒馆助手公开库；Markdown 转义特殊字符，空表仍输出空集合。

EJS 是可选用法，需要另装并启用 [ST-Prompt-Template](https://github.com/zonde306/ST-Prompt-Template) 的相应正文处理。只使用宏的卡片不需要该插件。开启后，普通生效世界书可另写异步 EJS：

```ejs
<% const person = await dvs_state.table('角色').get('阿呆'); %>
当前金钱：<%= person?.金钱 %>
<% const rows = await dvs_state.table('道具').query('数量 > ?', 0).orderBy('数量', 'desc').rows(); %>
```

若卡片引入了扩展的内部表，EJS 可通过 `await dvs_state.internal('journal').table('日志条目').get(12)` 读取指定组。普通 `dvs_state.table(name)` 和不带扩展 key 的宏只访问普通表。

`table()`、`query()`、`orderBy()` 同步返回查询对象，`get()`、`row()`、`rows()` 异步读数据。`dvs_state` 只查询本次固定起点，不提供 char、chat、rid、transaction 或写入方法。返回业务字段的独立只读副本；BLOB 是独立字节副本，修改它不改数据库。与 SDK 方法同名的业务列在这里仍按原列名读取。正式正文及变量请求中的查询失败，即使被模板 catch，也会使最终请求停止；打开聊天的额外世界书处理保留真正错误，不承诺停止整个第三方模板流程。

正式正文请求使用本次固定起点。打开、刷新或切换单人聊天触发的世界书条件和预处理也可查询 `dvs_state`：DVS 先等作者脚本注册和现有初始化完成，再提供最近 AI 回复当前版本的数据，不额外执行作者准备回调。作者无需逐条判断 `dvs_state` 是否存在。已启用脚本 10 秒内仍未开始注册时会报告错误；请检查脚本错误并原生重载。初始化完成后的空表正常返回空数组或 `null`，随后访问不存在记录的字段仍可能产生模板错误。

历史显示、提示词模板的独立预加载、`/ejs` 和助手独立请求不能自动取得该对象。DVS 停用时不等待、不初始化、不注入，依赖 DVS 的模板仍由作者负责停用。模板关闭时宏仍可使用；EJS 条目须由作者启用相应模板处理。宏在最终模板之后替换，业务字符串中的 EJS 不再执行。数据不参与本轮世界书递归扫描，完整替换数据不计入替换前预算。

最终 EJS 接入针对 Chat Completion 的 messages 和 TextGen 的 prompt。安装提示词模板的最终文本处理只读取 prompt；NovelAI 使用 input 字段，DVS 可替换其宏，但不承诺该插件会处理 input 中的普通 EJS。

提示词模板的 iframe“环境隔离”与 Worker“后台编译”应二选一。iframe 方式已有真实酒馆验证；Worker 方式的最小 EJS 编译对照未完成，DVS 在该模式下的最终正文注入仍未验证，不能据此判断不支持。需要 EJS 时可使用已验证的 iframe 方式。

续写、冒充用户、群聊、工具递归和助手独立生成不在支持范围内。准备或查询失败会停止正文发送；停止不自动撤回原生已加入的用户消息或已删除的待替换回复。正文成功完成后自动更新变量；主动变量更新见下文。

## 生成拦截

玩家邀请新访客进入书店时，作者可以先显示资料编辑界面，让玩家确认访客后再生成正文。把[最小原生 DOM 组件](../../../examples/dvs-pre-narrative-ui/README.md)加入已有注册脚本的 `preNarrativeUi` 数组，并设置 `dvs.exts.pre_narr_ui: true`。组件与作者脚本一起构建，不引用插件内部 Vue；样式由组件提供。剧情规划可以同时启用，也可以关闭。

```ts
await DVS.register({
  scriptId: getScriptId(),
  uniqueKeys,
  narrativePrepare,
  beforeGen,
  preNarrativeUi: [{
    key: 'visitor',
    buttonText: '重新编辑访客',
    insist: '正文采用已确认的访客资料，不另行随机生成访客。',
    condition: '本轮邀请新访客进入书店，需要玩家确认其资料。',
    narrativeEntriesSkip: ['自动访客生成'],
    component: visitorComponent,
  }],
}, { signal: lifetime.signal });
```

`key` 在同一注册中唯一，数组顺序就是优先级。输入增强在同一次请求中完成条件判断及已启用的规划等任务；多个条件命中时，只打开注册数组最靠前的一项。没有命中则继续正文。条件只由代码 `condition` 定义；它是输入增强模型需要判断的自然语言条件，不是浏览器执行的布尔函数。

可选的 `buttonText` 为非空字符串，设置胶囊中重开该交互的按钮文字。省略时，待完成显示“继续交互”，已确认显示“重新调整”；设置后两种状态均显示该项文案。点击仍打开交互界面，确认保存后才生成或重新生成正文。

| 组件方法 | 作者负责的工作 |
| --- | --- |
| `mount(container, context)` | 在 DOM 容器内挂载交互界面，返回卸载函数 |
| `mountResult(container, result)` | 独立挂载已保存结果的只读展示，返回卸载函数 |
| `toPrompt(result)` | 将最终结果转为正文补充文本，可返回 Promise；不重新生成候选 |

注册项可通过 `paramsSchema` 声明需要输入增强模型在命中时返回的参数，并用 `validateParams` 检查业务取值。例如房车交互声明正整数人数，模型返回 `{"keys":["npc_generate"],"params":{"npc_generate":{"count":2}}}`。DVS 将选中项的参数随交互记录保存，通过 `context.params` 传给组件。组件重试或继续已有交互时沿用这份参数。

每次交互有自己的实例。完成、取消、原生停止、切聊天或注册失效时，DVS 移除容器并调用卸载函数。作者在卸载函数中移除监听、定时器和框架实例。弹层透明，内容、标题和取消按钮由作者组件提供，DVS 保留焦点、Esc 和关闭管理；宽屏容器放宽，窄屏保留屏幕边距。胶囊展示另建实例，收起、重绘或目标失效时卸载。

`context` 提供本轮 `userInput`、`plotPlan`（未启用时为 `null`）、可选的 `params` 和 `result`、`prompt`、`worldbook`、`requestModel`、`complete(result)`、`cancel()` 和 `signal`。DVS 只在 `key` 和 `params` 都与已确认记录相同时，将旧 `result` 的独立副本传回弹窗。例如同一“生成访客”从 1 人变成 2 人，新弹窗收到 `params.count = 2`，从新的候选开始。作者只在玩家最终确认时以 JSON 值调用 `complete(result)`。DVS 保存并读回消息后才采用结果。交互、组件内的模型请求和 `toPrompt` 都在整组输入增强重试之外。

拦截记录有三种。`{ key: null }` 表示没有选中交互，`{ key }` 表示已命中、正在等待玩家确认，`{ key, result }` 保存最终确认的资料。命中项声明了参数时，待确认和已确认记录都附带 `params`。DVS 先保存已经完成的规划、筛选和拦截选择，再打开界面。取消时停止本次操作，首次命中的待确认交互可以继续。同一项已有确认结果时，取消调整会保留原结果。

| 玩家使用的入口 | 执行什么 | 完成后的正文 |
| --- | --- | --- |
| 用户消息「输入增强」顶部的「重新生成」，或 `DVS.reInject()` | 重做这条消息适用的整组任务。命中拦截时等待玩家确认，保存结果后再等待 `toPrompt` 返回 | 不生成或改写正文。即使 `toPrompt` 报错，已保存的确认结果仍在 |
| 拦截项的「继续交互」／「重新调整」 | 只打开已选组件，沿用保存的参数。有已确认结果时从它开始编辑 | 保存确认结果并成功取得 `toPrompt` 的资料后，已有正文时重新生成，没有正文时生成回复。输入框草稿保留 |
| 酒馆的重新生成正文或新 swipe | 已有成果完整时复用，已确认的交互直接交给 `toPrompt`。仍待确认时先打开组件；成果缺项时按已启用功能重新判断 | 使用本次已确认的结果生成正文 |

前两个入口只操作最新一条未隐藏的用户消息，历史消息仅供查看。

### 正文条目屏蔽

注册项的可选 `narrativeEntriesSkip: readonly string[]` 指定玩家确认后，本轮正文额外排除的条目。填写去掉 DVS 标签并去除首尾空白后的名称，例如 `['自动访客生成']`；本次正文中的所有同名条目都会屏蔽，未匹配时不处理。DVS 标签仍决定原用途范围，原生激活和普通筛选保持原规则，名单只追加排除。普通模型筛选关闭时，生成拦截的名单仍生效。

DVS 确认交互结果已保存后，按最终记录的 key 读取当前注册项的屏蔽名单，只处理本轮正文副本。重新生成正文时，DVS 复用确认结果，重新应用当前名单。取消、未命中或拦截关闭时，不应用本项名单。保存失败时停止正文生成。世界书原文和条目的永久启用状态均保留。

名单只用于本次正文，不撤销输入增强已读取的资料，不改写普通筛选记录，也不控制后续变量请求。消息不另存屏蔽名单。需要额外正文资料时，作者可在 `toPrompt` 中读取世界书后返回。

### 读取世界书条目

组件通过 `context.worldbook.getEntries(names)` 主动读取本轮角色绑定的主世界书和附加世界书。填写去掉 DVS 标签并去除首尾空白后的条目名称，与 `narrativeEntriesSkip` 使用同一匹配规则：

```ts
const entries = await context.worldbook.getEntries(['访客生成规则', '访客资料格式']);
// 每项包含 book、uid、原始 name、原始 content、enabled 和 order。
const materials = entries.map(entry => entry.content).join('\n\n');
```

`names` 为字符串数组，各名称去除首尾空白后不能为空。返回全部精确同名条目，重复传入名称不会重复返回同一条目；没有匹配项时返回空数组，空名称数组不发起读取。结果保持主世界书、附加世界书及各书原有条目顺序，不按传入名称或 order 重新排序。返回条目是独立副本，修改它不写回世界书。

每次调用读取当前文件内容，不缓存为本轮快照；不读取全局、聊天或 Persona 世界书。禁用、未激活、被普通筛选或本轮正文屏蔽的条目仍可读取，DVS 用途标签不限制此主动取材。读取失败直接拒绝 Promise；交互结束或本轮目标失效后不再交付读取结果。

方法不展开酒馆宏、DVS 宏或 EJS，不移除 `DVS_FILTER`，也不执行筛选条件。作者按请求用途处理控制声明和正文专属指令；例如复用可筛选条目时，先移除 `[[DVS_FILTER:...]]` 声明，再在完整请求返回后的统一发送处调用 `context.prompt.expand()`。普通酒馆宏可通过酒馆助手 `substitudeMacros()` 处理。需要原生世界书其他能力时，作者仍可直接调用酒馆助手 API。

### 组件请求与提示词

```ts
// prompts 是作者自己定义的请求函数对象，action 是作者选择的属性名。
const request = await prompts[action](context, input);
const response = await context.requestModel({
  ...request,
  messages: request.messages.map(message => ({
    ...message,
    content: context.prompt.expand(message.content),
  })),
});
// response.content 为完整文本；response.finishReason 为结束原因或 null。
```

作者可用普通对象组织任意多组同步或异步请求函数；initial、regenerate 只是业务示例名称，DVS 不注册或调度这些函数。控件主动调用函数，等其返回完整的 `DvsPreNarrativeModelRequest` 后，在统一发送处对消息内容展开一次宏，再调用 `requestModel`。函数内部不提前展开，函数组装时新增的宏也会得到处理。完整代码见[通用示例](../../../examples/dvs-pre-narrative-ui/interaction.js)。

请求复用本轮输入增强模型配置与密钥，但输出格式由本次参数决定，省略时为 `text`。`json_object` 请求 JSON；`json_schema` 必须同时传入 `schema`，其他格式不能传 schema。此覆盖不修改玩家设置，也不使用变量更新协议。业务消息由作者组织，DVS 自动在前后附加输入增强的 head/tail；模型名含 gemini（不区分大小写）时使用 Gemini 资源并将 system 消息按顺序合并到首条，其余模型含 DeepSeek 使用通用资源。头尾选择与消息清理复用输入增强逻辑，不额外加入组合任务、JSON 输出指令或随机前缀，也不自动再加入历史、规划或用户输入。请求失败保留界面，由作者显示错误并让玩家决定是否重试；交互结束会取消未完成请求，不交付迟到结果。

交互组件内用 `context.requestModel()`，它绑定正在进行的交互，能按本次请求选择输出格式。普通作者脚本如需独立发送自备的消息并取得完整文本，可使用 0.6.2 后新增的 [DVS.llm](#独立调用模型)。

| 辅助方法 | 对应宏与范围 |
| --- | --- |
| `prompt.userInput()` | `[[DVS_USER_INPUT]]`，本轮固定用户输入 |
| `prompt.prevNarrative()` | `[[DVS_PREV_NARRATIVE]]`，本轮起点 AI 正文 |
| `prompt.historyNarrative(N)` | `[[DVS_HISTORY_NARRATIVE:N]]`，起点之前最近 N 条 AI 正文，按时间排列，0 返回空文本 |
| `prompt.plotPlan()` | `[[DVS_PLOT_PLAN]]`，本轮规划的 JSON 文本；关闭时为空文本 |
| `prompt.expand(text)` | 展开上表宏及完整表数据宏，返回实际文本 |

用户及正文材料已剥离 DVS 胶囊，经过适用的发送正则。`[[DVS_DATA]]`、`[[DVS_DATA_人物:yaml]]` 等完整数据宏读取本轮 `narrativePrepare` 加工后的完整表，不采用筛选组结果，不再次运行准备回调。组件请求不支持四段筛选宏或 `DVS_FILTER`。

条件和请求由作者代码管理。作者可通过上述 `context.worldbook.getEntries()` 或酒馆助手接口取材；读取原文不代表已进行原生激活、筛选或模板处理，DVS 不隐式用世界书替换请求内容。

`toPrompt` 的文本进入当前用户消息发送副本的资料区，不改写用户原文。注册项可用非空字符串 `insist` 设置“执行要求”中的 `pre_narr_ui` 内容，填写时替换默认要求。未填写时沿用：已确认事项以交互结果为准，规划的对应内容随之调整，其余规划继续采用。首次确认和复用成果均读取当前注册项，不将 `insist` 保存到胶囊，也不改变 `toPrompt` 返回字符串的格式。

## 正文筛选与剧情规划

例如玩家说“检查武器并寻找向导”，作者可让输入增强模型先安排本轮检查、寻找和交谈，再按规划挑出需要的设定与道具行。正文模型负责展开正文，后置变量更新只依据实际生成的正文及其原定输入。可直接照着配置的例子见[作者手册](DVS作者使用手册.md#可选正文资料筛选与剧情规划)。

在“DVS 配置”的“功能配置”中，世界书优化、变量优化和剧情规划独立启用。脚本中的对应字段为 `dvs.config.lb_opt.llm_filter`、`dvs.exts.tables_opt` 和 `dvs.exts.plot_plan`，缺省均关闭。开启规划时，先依据完整准备数据规划至本轮行动结束并遵守条目适用条件，再按已定规划筛选。已有具体关联但细节未知的资料保留，不能凭未安排的未来情节保留，不为保留资料扩写剧情；固定条件仍按原条件判断。输入增强模型可独立选择命名配置，或跟随变量更新配置；表单草稿不会参与正式请求。旧总开关仅在兼容升级时解释，新配置的剧情规划不依赖两类优化开启。

### 输入增强接口

“变量功能”控制整个 `dvs.exts.tables` 扩展：关闭后不输出变量数据，也不执行正文后的变量请求和提交；变量筛选无候选数据，不提交任务，世界书筛选与剧情规划仍正常执行。没有有效输入增强任务或 AI 后处理任务时不发送模型请求，新消息保留空 records 胶囊。功能配置中的“世界书优化”只控制模型筛选，不关闭世界书基础处理。

新卡最低配置为 `{ "dvs": { "enabled": true } }`。`exts` 缺省时启用 `tables`（表数据）、`dvs_pre`（正文准备）、`dvs_post_update`（变量更新）和 `lb_opt`（世界书基础处理）；`tables_opt`（变量行筛选）、`plot_plan`（剧情规划）、`pre_narr_ui`（生成拦截）以及 `lb_opt.llm_filter`（世界书模型筛选）默认关闭。通常保留基础扩展，只按需要启用可选能力。


```ts
getExtension(key: string): Promise<boolean>;
setExtension(key: string, enabled: boolean): Promise<boolean>;
getConfig(key: string): Promise<Record<string, unknown>>;
setConfig(key: string, config: Record<string, unknown>): Promise<Record<string, unknown>>;
getInject(): Promise<{ filter: boolean; plot: boolean }>;
setInject(flags: { filter: boolean; plot: boolean }): Promise<{ filter: boolean; plot: boolean }>;
reInject(): Promise<void>;
```

通过以上 API 成功保存功能开关或筛选方式后，插件设置和开场白中已打开的功能配置面板会同步显示新值，无需关闭重开。

在有效注册后的作者脚本中使用：

```js
const previous = await DVS.getInject();
const saved = await DVS.setInject({ filter: true, plot: previous.plot });
console.log(saved); // 酒馆助手读回的两个布尔开关
await DVS.reInject(); // 覆盖最新已保存用户消息的记录，不生成正文或更新变量
```

新 API 分别管理扩展启用及配置，`setConfig` 合并指定扩展的字段并保留其他配置。`getInject`／`setInject` 保留为旧两开关视图：filter 同时代表世界书模型筛选与变量表筛选，plot 代表独立剧情规划；只开启一种筛选时 getInject 的 filter 返回 false。`setInject` 要求完整的两个布尔字段，filter 同时修改 `tables_opt` 与 `lb_opt.llm_filter`，开启时确保 lb_opt 启用，关闭时保留 lb_opt 的基础处理；plot 独立修改 `plot_plan`。所有写入保留无关配置，返回值确认酒馆助手变量读回，不表示服务器文件保存已确认。写回失败、读回不一致或目标已变时拒绝 Promise。改动在下次新流程或独立重做时生效，自动重试使用本轮已固定的配置。失败弹窗不修改功能开关。

`reInject()` 的目标是最新一条未隐藏、已保存的用户消息。它与面板顶部的「重新生成」一样，强制重做这条消息适用的整组任务。调用时须有有效注册、适用的输入增强扩展和可读取的前置 AI 状态，且酒馆当前没有在生成正文或更新变量。成功返回 `void`，前提不满足或执行失败时拒绝 Promise。

规划和筛选成功后先保存。命中拦截时，DVS 等待玩家确认，另存交互结果并读回，然后等待 `toPrompt(result)` 返回。如果回调报错，`reInject()` 会拒绝 Promise，已保存的交互结果仍在。这次操作不会生成正文。

模型或结果检查失败时保留原记录。玩家取消交互时，已完成的规划和筛选以及同项原有的确认结果都会保留。强制重做也可替换无法解析的旧记录。

### 世界书与表格筛选

| 世界书写法 | 作用 |
| --- | --- |
| 普通有效条目 | 作为参考，不参与删选 |
| 标题含 `[DVS:正文;可筛选]` | 原生最终激活后，参与本轮筛选；可在内容开头加 `[[DVS_FILTER:保留条件]]` |
| 标题含 `[DVS:正文]` | 不进入输入增强请求，仍沿原生路径输出；启用筛选时不能在该条目声明四段筛选宏 |
| 主书或附加书的已启用 `[DVS:筛选规则]` | 输入增强的作者筛选规则及筛选检查要求，直接读取，不进入正文或变量请求 |
| 主书或附加书的已启用 `[DVS:剧情规划]` | 规划开启时直接读取的作者剧情规则及规划检查要求；普通文字即可，没有该条目也可使用默认规划任务 |

专用用途不能在同一启用条目混写；SKIP 对专用规则同样有效。筛选只清空落选条目的本次输出，不修改世界书、不补回预算外内容、不删除激活成员或重算粘滞／冷却计时。

按位置筛选变量使用四段宏，`key` 在同表内标识一组选择，与行的业务主键不同：

```text
[[DVS_DATA_道具:yaml:equipped_weapons:已装备的武器]]
[[DVS_DATA_道具:md:used_items:已经使用掉的道具]]
```

表名、格式、key 用前三个冒号分隔，其后是完整条件，条件可含冒号。key 和条件必须非空，不支持省略 key 的三段简写。同表同 key 的多处声明必须使用相同条件，可使用不同输出格式。筛选表须保留注册的完整业务键，每行可唯一定位。模型只选择业务键，正文按原准备数据的行序和字段值输出，模型附带的业务值不会覆盖原数据。

已有全量宏保持原义。关闭变量优化、没有用户消息或本轮“清除并继续”跳过输入增强时，四段宏输出 narrativePrepare 的全量对应行；空记录本身不表示永久跳过，下次生成仍判断所需成果。变量请求始终输出 beforeGen 的全量对应行。条件宏仅供筛选，在正文和变量请求中移除。

条目名中的 `可筛选` 与正文开头的 `[[DVS_FILTER:保留条件]]` 配合使用。条件可包含换行和列表，模型按自然语言理解，不按 YAML 解析；前面允许空白，但条件内部不能包含结束符 `]]`。它作用于整个条目，不使用 `start/end` 包裹正文；配对的 `[[DVS_PLOT:start:字段名]]`／`[[DVS_PLOT:end]]` 用于规划字段描述。

普通 EJS 先在条目副本上以全量数据求值，`runType` 为 `dvs_input_inject`，随后按选择进入原生正文阶段。两个阶段的 `dvs_state` 都读取正文起点数据库；`dvs_narrative.rows(table, key)` 分别返回全量或已选原行的独立副本。先用完整四段宏声明分组，再自定义排版：

```ejs
<%# [[DVS_DATA_道具:yaml:equipped_weapons:已装备的武器]] %>
<%- dvs_narrative.rows('道具', 'equipped_weapons').map(row => row.道具名).join('\n') %>
```

声明在普通 EJS 执行前收集，包括注释。第一阶段通过提示词模板公开的 `prepareContext` 和 `evalTemplate` 取得完整环境；普通原生宏和显式预处理不会重复执行。两次求值不隔离作者模板副作用，需要只在正文执行的写变量或命令用 `runType === 'generate'` 判断。模板后台 Worker 模式未专项验证。

### 规划字段与完整示例

`plot` 始终包含以下四个字段，不需要作者手工声明。下表是未定制时的默认建议，不是强制类型：

| 字段 | 建议写法 | 默认任务 |
| --- | --- | --- |
| 本轮方向 | 字符串 | 回应当前行动，说明这一轮的推进方向 |
| 情节步骤 | 字符串数组 | 依次安排主要行动，以及必要动机、原因与预期结果 |
| 事实与边界 | 字符串数组，可为空 | 记录相关事实、人物认知、信息披露及行动限制 |
| 结束位置 | 字符串 | 指定本轮在哪里收束，哪些决定尚未作出 |

`[DVS:剧情规划]` 的普通文字作为总规则；配对字段宏可覆盖同名字段描述或增加作者字段。例如下面是一个完整的已启用规划条目：

```text
围绕玩家当前行动安排一轮，不替玩家决定是否接受向导的报价。
检查人物位置、装备来源、认知与行动所需时间。

[[DVS_PLOT:start:情节步骤]]
返回对象数组，每项包含“行动”和“原因”两个字符串。
先检查现有武器，再按现场可知信息寻找向导；遇到需要玩家决定的条件时停下。
[[DVS_PLOT:end]]

[[DVS_PLOT:start:气氛]]
用一个字符串描述本轮的叙事气氛，遵守已有文风设定。
[[DVS_PLOT:end]]
```

同名描述按条目处理顺序以后者覆盖前者，也可以覆盖值的结构。四个基础字段必须存在，但它们与可选新增字段的值都可以是对象、数组、字符串、数字、布尔值或 null；DVS 不按示例限制类型，也不按作者的自然语言描述检查字段类型或要求扩展字段出现。例如模型没有按上例返回对象数组，DVS 仍会保留实际合法 JSON 值。字段宏须在同一条目内配对，不能嵌套；字段名和描述不能为空，未闭合或格式错误直接停止，不请求模型。

符合上述结构的规划可能是：

```yaml
本轮方向: 检查现有武器，并找到可以进一步询价的向导
情节步骤:
  - 行动: 检查已拥有武器的外观与当前状态
    原因: 回应玩家的检查要求，不凭空增加装备
  - 行动: 根据现场已知信息寻找向导并询问服务
    原因: 先展示服务与报价，把接受与否留给玩家
事实与边界:
  - 玩家只是表达行动意图，检查和交谈尚未发生
  - 不替玩家接受报价，不提前扣款
结束位置: 向导说明服务与报价，等待玩家决定
气氛: 平静而务实
```

这只是展示字段用法，实际内容以卡片数据和模型返回为准。DVS 将规划交给正文模型展开；不据此直接更新数据库。

模型按本次任务的扩展 key 返回公共包装，例如 `plot_plan: { cot?, data }`、`lb_opt: { cot?, data }`、`tables_opt: { cot?, data }`。规划在 `plot_plan.data` 中，筛选列表按各自模式放在对应 data 的 `excludedEntries`／`excludedRows` 或 `includedEntries`／`includedRows`。可选 cot 仅保留非空字符串，保存为按扩展归属的 analyses，用于展示，不参与选择、规划或成功判定，也不通过 `DVS_PLOT` 字段宏声明。旧记录的 plot_cot、filter_cot 由兼容层读取，不再作为新输出字段。

输入增强的世界书数据宏替换为表引用，实际全量准备数据只在 `current_tables` 提供。第一阶段 EJS 仍可读取全量数据，自定义 EJS 输出和静态文字不推测删减；正文及变量请求的数据宏保持原义。

### 保存、显示与复用

输入增强需要请求时，用户消息末尾先写入 records 为空的 `<DVSData type="user">…</DVSData>`，成功后保存完整记录并通过原生保存和固定聊天文件读回确认；用户正文不变。标签正文为 `{ records, analyses? }`：lb_opt 保存被屏蔽条目的世界书名、ID 和名称，tables_opt.filters 只保存各组保留行的完整业务键，plot_plan 保存规划，analyses 保存可选分析；头部摘要另存为 summary 属性。新写入不保存完整有效数据快照。原生请求正则移除新旧胶囊。启用剧情规划且取得可用规划时，正文发送副本附加统一 `<附加指令>`，将规划 YAML 放入 `<任务资料>` 内的 `<plot_plan>`，执行指令放入 `<执行要求>`；历史分析不加入这些正文指令，图片等内容保留。

执行指令要求正文按四个规划字段确定回应重点、展开行动与对话、遵守事实限制并在指定情境收束，作者扩展字段按对应故事指令处理。规划与本轮用户明确要求、已发生剧情或原设定冲突时修正冲突部分；保留现有思考与输出格式，不额外展示规划或检查过程。

重新生成正文或生成新 swipe 时，按这条用户消息上标签的状态处理：

| 标签 | 处理 |
| --- | --- |
| 所需成果完整的合法记录 | 复用记录，不请求输入增强模型；不因正文仍在生成而把用户胶囊标为生成中 |
| 空记录或所需成果缺项，包括合法的表筛选记录缺少本次需要的筛选组 | 自动重做本次所需的整组任务 |
| 记录损坏，例如 JSON 无法解析、记录结构不符，或已保存的业务键缺字段、值类型错误 | 暂停正文生成，弹出三选一，见[停止与失败](#停止与失败) |
| 没有标签（老楼层、发送时未开启、标签被删掉） | 按本次已开启功能判断任务；确需请求时保存空胶囊，再完成所需整组 |

复用时沿用屏蔽名单，仍重新准备数据、扫描并组装正文；当前候选未命中屏蔽 ID 则保留，因此新候选默认保留。表格按保存的业务键取本次准备行，字段变化使用当前值。新增行不会自动进入旧选择，已选行不再存在时略过，多余旧组忽略。面板的“有效数据”另按该用户消息之前有效 AI 楼层的数据和保存的业务键读取，不是提示词快照。关闭剧情不删除旧规划，也不在正文中使用它；修改输入或规则后需要重新计算时主动 `reInject()`。

聊天中这条用户消息显示“输入增强”面板，折叠时只读取属性摘要，展开才解析完整记录并按需读取“有效数据”，不重新执行世界书扫描、作者正文准备或模型请求；屏蔽条目预览另外读取世界书当前内容。旧标签展示时统一转换并保存新结构；旧 tables 快照和已有 tables_opt.tables 在读取时舍弃，正常写回去掉冗余快照，不批量改写历史。旧共同筛选分析只显示一次，空分析不显示标题。面板的状态字样、分区和按钮见[作者手册](DVS作者使用手册.md#查看重用与重做)。条目 ID 只在悬停提示和预览中出现。

`reInject()` 从目标用户消息之前的 AI 状态出发，历史与扫描截止该用户输入，不生成 AI 回复或更新变量。没有有效注册、没有用户消息、没有启用适用输入增强扩展或已有任务时拒绝。自动正文请求中，最新用户输入已隐藏、不在原生发送副本里时停止，需先显示该消息。

面板「清除」清空最新用户消息的 records、analyses 和 summary，保留标签并保存读回；用户原文及其他内容不变，不关闭功能、不回滚业务变量。空记录不作为已完成成果，下次生成仍按所需成果判断是否请求。自动失败选择“清除并继续”仅跳过当前 Turn；没有公共 `clearInject` API。

### 停止与失败

模型请求和结果检查采用固定输入有限重试，不重复数据准备或第一阶段 EJS。自动流程中重试全部失败，或复用时记录无法读取，正文生成暂停并弹出三选一：“重新生成输入增强”再请求一次，成功后继续正文，失败时原记录不变并留在弹窗；“清除并继续”清空标签后不筛选、不规划直接生成；“取消正文生成”停止本次生成并保留记录，按 Esc 关闭弹窗也按取消处理。弹窗不修改功能开关。面板「重新生成」和 `reInject()` 的模型或检查失败保留原记录；交互取消保留已完成的规划和筛选及同项旧确认结果。模板、开关写回、记录保存及正文注入失败直接停止，不重发成功的模型请求。停止、切聊天或撤销注册后，旧结果不能写入新目标。停止不撤回原生消息、不回滚已完成写入，也不保证远端停止计费。独立扫描复用原生计时和作者模板行为，不承诺隔离它们的副作用。

正文使用酒馆原生请求，最终宏处理针对 Chat Completion 的 `messages`、文本后端的 `prompt` 或 `input`；第三方 EJS 对 NovelAI `input` 的处理和模板后台 Worker 模式仍受[正文注入的限制](#正文数据注入)。输入增强和变量更新则使用已保存配置的 OpenAI 兼容 Chat Completions 接口，不继承正文连接；服务支持的模型、参数和格式须由作者自行配置。

## 选择世界书条目的用途

新卡使用 `[DVS:词组]`，逗号与分号按[速查中的名称写法](#世界书名称标签)分别使用；不要在同一条目混用新旧标签。旧标签的完整组合对照见[旧卡升级](DVS作者使用手册.md#旧版-dvs-卡片升级)。

完整词组、用途及名称示例见[世界书名称标签速查](#世界书名称标签)。下面说明实际读取条目时的规则。

未加 DVS 标签的普通条目默认供预处理、正文和后处理使用。显式写范围后只使用选定范围；例如 `[DVS:正文]` 不送入输入增强，因此不能在其中声明需要预处理收集的四段筛选宏。`[DVS:预处理,正文]` 可供两阶段参考，`[DVS:正文;可筛选]` 还允许世界书优化删除它。规则条目按用途读取，建议单独组织，不与普通设定混写。

普通设定仍须启用并满足酒馆的激活条件、预算和递归规则；正文保留原生插入位置，变量上下文按 order 排序合并到 `<world_context>`。专用规则和变量数据直接读取已启用条目，不靠关键词或红绿灯。SQL 和版本条目即使禁用也会按各自用途读取。禁用提示词条目不会参与请求、模板或用途冲突检查。

DVS 标识和英文 DDL/COT 不区分大小写；中文词组使用速查表原文。普通用途标签可出现在条目名其他位置，元数据完整名称按上表书写。

### 变量提示词怎样取材

每次新更新重新读取当前角色主世界书和附加世界书。普通设定调用酒馆原生扫描，截止目标 AI 回复并包含该正文；扫描深度、关键词、递归、概率、预算和冷却遵守酒馆规则，`DVS.regen()` 的扫描触发类型仍为 normal。全局、聊天和 Persona 的其他书不作为本次变量请求候选；历史正文数只控制给模型补充多少较早 AI 正文，不改变扫描深度。

RULES、DATA、VAR_COT 和普通设定各自按 `position.order` 升序合并，同值保持读取顺序。`order` 缺失或不是有限数值会停止并报告条目。普通设定合并到 `<world_context>`，不沿用正文插入位置；背景设定不能独立证明事件已经发生，也不能覆盖实际起点。一次更新的自动重试复用同一批选定条目，下一次 `regen()` 才重新读取和扫描。

条目按普通酒馆宏、EJS、DVS 数据宏的顺序准备；原生预处理已经展开的普通宏和 EJS 不再次执行。变量数据宏读取 `beforeGen` 返回集，可选 EJS 的 `dvs_state` 则查询固定起点数据库，两者不能混为同一数据来源。EJS 或只读查询失败，即使模板捕获了查询错误，也会停止本次准备，不发送变量请求或自动重试作者准备。

### 编写 RULES 与 DATA

变量提示词中的表结构说明由 DVS 按注册信息自动生成，只列表名、业务键和字段名，不列类型和默认值。字段名尽量自描述；单位、枚举和缩写的含义写在 `[DVS:变量规则]` 中。

`[DVS:变量规则]` 集中写框架无法知道的业务内容，用“发生什么 → 改哪个字段 → 改多少或怎样替换”的短句表达。例如“正文明确休息恢复体力 5 时，hp 加 5”，比“合理更新体力”更容易执行。

| 需要说明的内容 | 例子 |
| --- | --- |
| 字段含义、单位或枚举 | hp 代表体力；状态只用正文明确给出的文本 |
| 事件触发与更新方式 | 药水用完则移除；明确恢复 5 才加 5，不按常识推算 |
| 同名对象是原行修改还是替换 | 换成另一把同名旧刀：先 remove 再 add |
| 缺失字段与默认值 | 新刀不指定品质时省略品质字段，由数据库默认值填写，不带回旧品质 |
| 开场白初始化 | 空起点从最新开场白 add 建行，不对不存在的行 delta 或 replace |

JSON 格式、API 角色说明和业务键对象写法由 DVS 模板提供，规则中不必重复。可以给业务例子，但要标明是例子，不要整段复制正文或当前表。

`[DVS:变量数据]` 提供本轮起点，也就是最新回复之前的实际状态。完整保留所提供行的业务键和值，不要让模型从历史重新推算起点，也不要混入本回合更新后的数据。小型整齐的表适合用 Markdown 表格，逐行对象较多的表可以单独用 YAML；同一份数据中字段名、业务键值和数值类型保持一致，文本按所用格式正确转义。表很大或结构复杂时，可以比较同一份数据的两种写法，选更清楚、token 更少的一版。

### 提供本轮检查项

启用一个单独条目，例如标题 `[DVS:变量COT]本轮核对`，正文写“1. 时间线：核对本轮结束时间和活动时长。2. 物品：核对转交双方的数量变化。”业务规则仍放在 RULES，停用 COT 后也应完整。多个条目按 order 稳定合并，只发送正文，建议在正文中使用清楚且不同的项目标题。普通宏、EJS 和 DVS 数据宏沿用变量提示词的展开规则。

模型被要求在 tables.cot 的可选字符串中逐项报告检查结果，在 tables.data 中输出 Analysis 与 UpdateCommands；无检查内容时省略 cot。只有非空字符串 cot 保存为 analyses，不进入业务回调或 SQL；真正更新仍取决于两个数组及作者回调。检查文字不证明模型没有遗漏，效果需另行比较。

## 数据准备和更新回调

注册必须提供 `narrativePrepare` 和 `beforeGen`。不需要改写提示词数据时直接返回收到的 `tables`；没有业务计算时省略 `preUpdate`、`postUpdate` 和 `virtualTables`。

| 回调 | 输入、返回及发生时间 |
| --- | --- |
| `narrativePrepare({ char, chat, tables })` | 正文发送前执行；返回正文宏使用的表数据，可异步 |
| `beforeGen(state, tables)` | 本轮变量请求准备时执行一次；返回变量数据宏使用的表数据，可异步，自动重试复用已准备请求 |
| `preUpdate(state, newTables, oldTables)` | 补丁计算后、写数据库前执行；返回全部订正后的真实表，可异步 |
| `postUpdate(state, newTables, oldTables)` | 默认更新及实际值读回成功后执行，仍属于必须成功的变量处理链；返回 `void`，可异步，通过管理方法另行写入，整条链成功后才关联目标回复 |

`beforeGen` 收到完整起点的独立副本，它的返回值只供提示词。补丁始终从完整起点的另一份副本计算，不会因作者隐藏了提示词字段而删除数据库字段。`oldTables` 也是本轮完整起点的副本，不是上次失败尝试、筛选后的提示词或稍后重查的当前值。

`beforeGen`、`preUpdate` 的 `state` 提供固定的 `char`、`chat`、`fid` 和只读 `table()` 查询。它们从本轮起点读取；修改待写入数据请改 `newTables`。只有开场白的变量重新生成从全部注册表为空的起点开始，此时 `fid` 为 `null`，不读取原 INIT 或已有变量。`postUpdate` 的 `state` 对应成功后的目标层，具有非空 `fid` 和管理方法；其 `newTables` 包含数据库实际默认值。传入的两个表数据快照不会随随后管理操作改变。

`preUpdate` 返回值必须恰好包含全部真实注册表；用 `[]` 明确清空一张表。遗漏表、未知表、未知列、缺少完整业务键或未移除虚拟表会拒绝写入。已有行不能靠省略原有列伪装成新增行；新行省略的列交给 SQLite 默认值处理。生成列只读，写入后由 SQLite 重算。DVS 比较最终数据和完整起点，只为实际变化建立行版本，并建立目标层的完整索引。

`preUpdate` 的返回数据和默认更新在同一事务提交。`postUpdate` 使用管理方法产生后续事务；失败时本次链失败，不采用失败版本，但已提交写入不会物理撤销。有本次模型请求时，响应链失败会在配置次数内重试，每次从同一起点生成新的目标版本；没有模型请求时直接报错。若 postUpdate 自身多项修改需要共同成功，请使用 `state.transaction()`。直接 Helper SQL、网络或界面副作用不受默认事务保护，自动重试也不承诺这些副作用只发生一次。

### 模型补丁格式

变量任务通过公共包装返回 `{ tables: { cot?, data: { Analysis, UpdateCommands } } }`，其中 data 的必需字段是 Analysis、UpdateCommands 两个数组，可选 cot 是展示分析。公共层将 data 交给变量扩展，业务回调不接收包装或 cot。模型不编写 SQL，也不提供内部 `rid`、`fid`、行序号或拼接路径。

| 操作 | 要提供的字段 | 前提与结果 |
| --- | --- | --- |
| `add` | `reason, op, table, keys, value` | 行不存在；`value` 是新行业务字段对象，缺省列交给数据库 |
| `remove` | `reason, op, table, keys` | 行存在；移除当前目标中的该行 |
| `delta` | `reason, op, table, keys, field, value` | 行和数值字段存在；把有限数值变化量加到原值，负数表示减少 |
| `replace` | `reason, op, table, keys, field, value` | 行存在，字段已声明；替换该字段 |

每条命令的 `keys` 都须准确包含注册的全部业务键。复合键按字段名定位，顺序任意，字符串和数字不自动转换。`add.value` 若再次写入键字段，类型和值须与 `keys` 一致；不能写生成列。命令按数组顺序执行并逐项检查存在条件，同键替换应先 `remove` 再 `add`。

`Analysis` 用于引导模型分析及记录展示，每项提供 `reason, table, keys`，可选 `field`。运行时只校验并执行 `UpdateCommands` 的业务定位和操作前提，合法命令可独立于分析条目生效。无法展示的分析条目略过。两个空数组表示没有业务变化，仍会为回复建立完整数据关联。命令检查不能证明模型没有漏掉剧情变化。

真实表的顶层字段和键只接受其存储规则允许的值；数值须有限，整数及 `delta` 的原值和结果须在 JavaScript 安全整数范围。普通对象、数组写成 SQL TEXT，读取不自动解析。真实表顶层布尔不符合 Helper 绑定规则，会明确拒绝；JSON 对象内部的布尔可以保留。虚拟表按声明检查顶层 JSON 类型，不额外解释嵌套业务数值。

三种输出格式都检查同一公共包装和补丁协议。响应须是一份 JSON 对象，也可使用单个完整 JSON 代码块；不接受前置 `<think>…</think>`、其他说明或第二份答案。DVS 不自动修复 JSON，不把推理字段或工具调用拼成补丁。cot 只接受非空字符串作为展示分析，不进入回调或 SQL，显示它不证明更新正确。


## 主动更新最新回复的变量

```js
await DVS.regen();
const current = await DVS.getState();
```

`regen()` 不重新生成正文，只处理最新一条未隐藏 AI 回复的当前 swipe，与面板「重新更新」的目标相同；它不检查自动流程的正文长度门槛，空胶囊或旧胶囊无法解析也不阻止重算。普通回复从它之前最新一条未隐藏 AI 回复的状态出发；只有开场白时从所有注册表为空的起点出发，忽略已有变量且不重跑 INIT。每次新更新读取固定正文及最近前置用户消息，再按配置追加较早 AI 正文。普通设定按酒馆扫描设置重新扫描，例如设置最近五条，就扫描截止目标 AI 回复的最近五条，其中包含目标正文。扫描只选择当前角色主世界书和附加世界书；历史正文数不决定扫描深度。作者在世界书中提供 `[DVS:变量规则]` 规则条目、可选 `[DVS:变量COT]` 检查条目、`[DVS:变量数据]` 数据条目和注册回调。

自动更新和手动 `regen()` 期间，酒馆输入框显示停止按钮，暂不能发送下一轮。停止按钮会取消变量请求；已提交的数据库修改不会撤销，错误会说明是否已提交及关联。请求和已开始的处理结束后恢复发送。

在模型请求或重试等待中停止，若本轮默认更新没有改变原数据，原先已确认的变量可立即通过 `getState()` 重新读取，无须刷新页面。没有旧变量的回复不会凭空获得变量；此前结果未确认，或本轮写入／关联结果无法确认时，读取保护仍保留。恢复读取不改变变量，不另发 `onUpdate` 通知。

处理期间 DVS 保持酒馆的发送按钮处于请求中，直到本轮落定。当前可通过“正文分析”胶囊查看运行状态，作者界面可读取或订阅下面的进度。诊断会记录错误；开始、每次重试和取消后的结果目前还没有完整接到同一条酒馆通知。

作者状态栏可用以下接口让按钮同时响应自动和手动更新；中途挂载也应先读取当前状态。`onUpdate` 仍用于读取更新后的业务数据，不能代替进度订阅。

```js
function showUpdateStatus(status) {
  updateButton.disabled = status.phase !== 'idle';
  updateButton.textContent = status.phase === 'idle' ? '重新更新变量' : '正在更新变量…';
}
showUpdateStatus(DVS.getUpdateStatus());
const unsubscribeStatus = DVS.onUpdateStatus(showUpdateStatus);
// 状态栏卸载时调用 unsubscribeStatus()。
```

使用这些接口的作者界面需要与提供该接口的插件构建配套。

### 更新进度

`getUpdateStatus()` 返回当前注册、当前聊天的独立进度副本；`onUpdateStatus(callback)` 返回取消订阅函数，注册注销时清理。切聊天按新目标通知，不把旧聊天的进行中状态用于新聊天。监听失败不改变变量处理结果。

| 字段 | 含义 |
| --- | --- |
| `phase` | `idle` 空闲、`preparing` 准备、`requesting` 请求、`retrying` 等待重试、`processing` 处理补丁及后续步骤 |
| `attempt` | 当前尝试从 1 开始，首次请求前为 0；等待重试时是刚失败的编号 |
| `maxAttempts` | 本轮最多尝试次数，尚未读取配置时为 0 |
| `retryDelayMs` | 等待重试的配置间隔，其他状态为 0；不是实时倒计时 |

`idle` 时数字均为 0。界面在非 `idle` 时禁用更新按钮，等待重试可显示 `attempt + 1`。中途挂载要先读取状态，不能只依靠自己的点击 Promise 判断自动更新是否忙碌。

同一条回复在变量处理期间被插件或用户改写，DVS 仍按本轮读取的正文计算变量，不因改字取消或重新请求；写回胶囊时重新读取最新正文，保留改写内容。如果改写改变了剧情，本轮变量仍对应改写前已捕获的剧情。删除回复、再次重新生成将旧回复替换为新消息，或切换聊天、swipe 时，旧操作仍停止。保存与错误边界见[作者面板的显示与操作](#状态栏标签与刷新)。

同一次更新的失败自动重试复用这次选中的条目；再次调用 `regen()` 会重新读取、扫描，刷新页面后也一样，不依赖上次内存结果。普通设定只补充背景，不证明当前已发生事件、不覆盖起点值。

发送给变量模型的最新正文、历史 AI 正文和最近用户输入，会分别应用酒馆“发送给 AI”的正则，并遵守各条消息在完整原聊天中的深度设置；仅格式显示的规则不参与。过滤后的文本只用于本次请求，聊天原文不改写，详见[数据来源与排列](#主动更新最新回复的变量)。

`beforeGen` 返回原生“表名 → 行列表 → 业务字段”，只供提示词，不作更新底稿。模型通过 `table` 和完整 `keys` 对象定位；复合键按字段名和值分别提供，具体契约见[输出协议](#模型补丁格式)。正文 narrative 宏和 EJS 查询保持原格式。

### 状态栏标签与刷新

楼层内嵌状态栏在变量处理链（含 `postUpdate`）成功并确认消息关联后，由 DVS 随 AI 胶囊保存自动补齐 `<DVSPanelPlaceHolderImpl/>`，去重并放在当前叙事正文之后、胶囊数据块之前，再由作者的仅格式显示正则替换成状态栏。独立悬浮状态栏可按[场景指南](场景/悬浮状态栏.md#制作悬浮状态栏)查询和订阅数据，不依赖正文占位。

自动流程为有效 AI 回复保留 `<DVSData type="ai">…</DVSData>` 胶囊，records 为空时显示“无数据”；已有胶囊在处理成功前保持原记录，开场白 INIT 不写生成记录。整条变量处理链成功后保存目标关联，并把业务记录、可选分析与摘要一起写入胶囊，使用酒馆助手的单楼层刷新。不刷新页面，不重新生成正文，不改其他 swipe 或无关消息变量。模型失败后已确认沿用起点时，胶囊保持原内容；更新失败继续报错。变量与关联已成功而胶囊保存失败时单独报告，不重复执行变量更新。

已有标准标签会从模型上下文副本中移除，聊天文件保留原始标签；不删除其他 HTML。正文完成自动触发与主动 `DVS.regen()` 共用同一流程。作者已有楼层内嵌界面时，通过 `DVS.getState({messageId, swipeId})` 读取指定回复的数据，并自行管理界面和卸载。

### 虚拟表输入与写库前计算

模型适合识别“谁收到了什么、数量多少”；固定加减由代码计算。例如真实表 `库存` 使用业务键 `['持有人', '物品']`，字段为持有人、物品和数量，保留数量为 0 的行。规则要求模型只向虚拟表记录本轮已经发生的收支，数量变化用正数表示收入、负数表示支出，不直接修改库存数量。

在现有注册中加入以下片段；`库存` 必须已在 DDL 和 `uniqueKeys` 中登记：

```js
virtualTables: {
  收支事件: { keys: ['编号'], fields: {
    编号: 'string', 持有人: 'string', 物品: 'string', 变化: 'number',
  } },
},
preUpdate: (_state, newTables, oldTables) => {
  const inventory = oldTables.库存.map(row => ({ ...row }));
  for (const event of newTables.收支事件) {
    if (!Number.isInteger(event.变化)) throw new Error('收支数量必须是整数');
    let row = inventory.find(row => row.持有人 === event.持有人 && row.物品 === event.物品);
    if (!row) {
      row = { 持有人: event.持有人, 物品: event.物品, 数量: 0 };
      inventory.push(row);
    }
    row.数量 += event.变化;
    if (row.数量 < 0) throw new Error('库存不足，请核对事件');
  }
  // 库存完全从本轮起点和事件计算；其他真实表保留模型的合法修改。
  newTables.库存 = inventory;
  delete newTables.收支事件;
  return newTables;
},
```

例如交付两本书，要记录交付方 `变化: -2` 和接收方 `变化: 2` 两行，并给每个事件不同编号。业务规则负责说明哪些事实需要成对记录；代码只按这张卡的确定规则计算，不把计划中的交付提前记账。无事件时库存保持本轮起点。重试也从同一 `oldTables` 计算，不从上次失败结果继续累加。

`fields` 声明顶层 JSON 类型，支持 string、number、boolean、array、object、null。嵌套字段含义及计算规则由作者写入 RULES 并在回调中处理。`keys: []` 表示至多一行，以 `keys: {}` 定位；模型使用 `add` 建立行，之后可按已有操作替换字段。需要多行时，keys 使用已声明的 string／number 字段并提供完整键，不需要内部编号。

DVS 把声明与真实表结构一起交给模型，输出仍只有 Analysis／UpdateCommands。例如收支事件可输出 `table: "收支事件", keys: { 编号: "交付1" }, op: "add", value: { 持有人: "林溪", 物品: "书签", 变化: -1 }`，并配套同表同键的 Analysis。虚拟表每次请求从 [] 开始，不继承历史，不来自 beforeGen 的提示词副本，不建立数据库表或索引。

回调返回前必须删除全部虚拟表，包括空表。没有清除、返回未知真实字段或漏掉真实表都会明确报错。虚拟表不进入 SQL；真实表的完整键、已有列、生成列及事务检查继续有效。

虚拟表名不得与真实表名冲突，也不能使用 `rid`、`fid`、`_dvs_` 或 `__stsh_` 保留名／前缀。字段名遵守相同保留规则，至少声明一个字段；键字段须已声明为 string 或 number，不能重复。

### 更新结果与错误


调用等待提示词准备、模型请求、补丁计算、订正、默认事务、实际值读回、后处理、消息关联、周期清理和通知完成。后处理失败使本次链失败，不采用失败版本，已提交部分不物理撤销。每次模型尝试是独立请求，重试不携带前次报错或输出，界面继续报告错误；重试复用准备好的请求，每次为同一起点分配新的目标版本。补丁用 `table`、完整 `keys` 对象及适用的 `field` 定位注册业务数据，规则见[输出协议](#模型补丁格式)。有限重试耗尽时，按目标回复是否已有数据关联区分：

| 目标回复 | 全部尝试失败后 |
| --- | --- |
| 新生成的正文、新 swipe，或独立重做尚无关联的回复 | 报告变量更新失败，回复沿用本轮起点的 fid。若起点没有 fid，回复也没有变量版本。关联保存成功后检查周期清理，并通过 `onUpdate` 通知面板重读 |
| 独立重做已有关联的回复 | 保留原 fid 和 AI 胶囊。失败尝试中已经提交的数据按孤儿清理规则处理 |

模型返回可解析的 JSON 但响应处理链失败时，不把失败尝试的建议写入 AI 胶囊。版本关联与胶囊保存失败不重试模型；它们发生在业务链成功之后，按实际已确认结果报告。支持范围见[本篇限制](#支持范围)。

| 失败 | 是否自动再请求模型 |
| --- | --- |
| 模型发送、接收、公共 JSON 解析失败 | 在配置次数内重试完整请求 |
| 有本次模型请求时，必须成功的响应处理入口失败，包括补丁、preUpdate、SQL、实际值读回或 postUpdate | 在配置次数内重试完整请求；新目标版本、同一起点，不采用失败版本 |
| `beforeGen`、扫描或请求模板准备失败 | 停止，不重复请求准备 |
| 没有本次模型请求的处理失败，或主动停止、目标失效 | 停止，按实际结果收尾 |
| 版本关联、胶囊保存或后续周期清理失败 | 不重试模型，交付已确认的业务与保存结果 |

单次超时只覆盖模型请求到完整响应体，不包含回调、SQL、聊天保存和后处理；取消不保证远端停止计费。自动重试不重跑 beforeGen 或请求准备，补丁通过才执行 preUpdate，重试共用固定起点和本轮选择的世界书条目。失败沿用不调用 postUpdate，不能把它当成空补丁成功。

## 查看变量模型原始建议

正文尾部的“正文分析”面板读取 `<DVSData type="ai">` 的 records.tables 和分配给它的 analyses，默认收起为胶囊。展开后直接显示内部“思维链”“实体分析”“更新命令”，不额外套扩展折叠，只有“更新命令”默认展开。思维链仅在有非空分析时显示。命令类型显示为修改、新增、删除、增减（replace、add、remove、delta），增减命令按正负标为“增加”或“减少”；头部计数如“改 2 · 增 1 · 删 1 · 增减 2”，展开后可点选筛选。历史分析中的数组逐项换行，字符串项原样显示，其他项显示为缩进 JSON。对象或数组的紧凑 JSON 超过 50 个 UTF-8 字节时另起一块显示 YAML。面板的状态字样和操作见[作者手册](DVS作者使用手册.md#查看变量更新面板)。

标签有三种保存状态：合法记录按结构显示；records 为空显示“无数据”；内容无法解析时显示“数据异常”和错误详情。“更新中”“出错”和“已取消”只是本次会话的运行状态，不写入标签，刷新页面后不再显示。生成拦截中主动取消显示“已取消”及普通说明，真正失败仍显示“出错”。更新中暂时隐藏旧结果和解析错误，失败或取消后恢复保存记录。自动流程跳过变量请求也保留空胶囊；没有标签的历史回复不批量补写。楼层数据按钮按查看开关与注册状态提供，忙碌时禁用；合法空 records 也可查看。解析或展示准备失败时，当前错误视图只保留适用的重做／清除入口，不挂扩展的数据按钮。

成功时 records.tables 保存通过处理的 Analysis、UpdateCommands 原始建议，非空 cot 另存为 analyses；作者回调可能订正实际数据，记录不代表全部按建议写入。失败尝试的局部记录不保存。只有最新一条未隐藏的 AI 回复提供「重新更新」，效果与 DVS.regen() 相同。旧 DVSUpdateData 由公共兼容层转换，旧命令只展示，不重放。插件分别安装原文隐藏及请求移除正则，同时覆盖用户和 AI 消息的新旧胶囊；配置标签另有一对规则。其他原生规则及其完整字段保留，规则一致时不重复保存或重载聊天。

## 为角色卡准备 SQL

在角色卡绑定的 primary 或 additional 世界书中放置下列条目。DVS 读取禁用条目，推荐关闭 SQL 条目，避免它们进入模型提示词。每条内容可以有多条 SQL，通过 Helper `runSql` 执行；不要自行写 BEGIN／COMMIT／ROLLBACK。

扩展所需表名、业务键和业务列由扩展说明提供。要为卡片引入该组，使用 `[DVS:DDL:扩展key]v1.0.0`，开场白初值写在 `[DVS:初始化:扩展key]welcome_0`。每组分别记录迁移版本，同一开场白所有命中的初值条目按世界书 `order` 执行。内部表的业务键由扩展声明。默认变量补丁只更新普通业务表，内部表的数据由所属扩展按楼层读写。

条目 `[DVS:DDL]v1.0.0`：

```sql
CREATE TABLE "角色" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  角色名 TEXT NOT NULL,
  金钱 INTEGER NOT NULL DEFAULT 50 CHECK(金钱>=0)
);
CREATE TABLE "道具" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  持有人 TEXT NOT NULL,
  道具名 TEXT NOT NULL,
  数量 INTEGER NOT NULL DEFAULT 1
);
```

条目 `[DVS:初始化]welcome_0`：

```sql
INSERT INTO "角色"(rid,角色名,金钱) VALUES(randomblob(16),'阿呆',50);
```

初值需要使用玩家名字时，在 INIT 的 SQL 字符串中写 `'{{user}}'`，例如：

```sql
INSERT INTO "道具"(rid,持有人,道具名,数量) VALUES(randomblob(16),'{{user}}','手机',1);
```

DVS 在初始化时通过酒馆宏接口取得当前用户／Persona 名称，转义名字中的单引号后写入数据库。只处理 INIT 中精确的 `{{user}}`，不展开整段 SQL 的其他宏；源条目保持原样。已有初始化状态不重跑。

`rid` 与 `fid`：

- `rid` 为 16 字节 BLOB，标识一条历史记录。
- 正常生成的 `rid` 和楼层 `fid` 使用 UUIDv7。
- INIT 可以手工写 UUIDv7 的 BLOB，也可以为便利使用 `randomblob(16)`。
- 业务唯一键只在某个 fid 的有效集合中唯一。不要在整个历史业务表上为角色名等业务键建 UNIQUE。

开场白与 INIT 的对应：

| 开场白 | INIT 条目 |
| --- | --- |
| 默认开场白 | `welcome_0` |
| 额外开场白 | 依序 `welcome_1`、`welcome_2` |

- 当前只在聊天恰有一条消息、目标是消息 0 时识别开场，直接用当前 `swipeId` 匹配 INIT。若默认文本为空且酒馆移除了默认项，第一个额外开场可能取到 `welcome_0`。几种开场需要同一套初值时可用 `welcome_*`。
- INIT 名称支持单编号 `welcome_0`、英文逗号分隔的编号列表 `welcome_0,1,2`，以及单独使用的 `welcome_*`；旧标签 `[DVS_INIT]` 也支持这些写法。
- 每个命中的世界书条目执行一次，允许同名条目。按世界书 `order` 升序执行，相同值保持读取顺序。SQL 有依赖时，给需要先执行的条目填较小的 `order`。
- 通配和列表条目会为每个首次初始化的开场白各执行一次。作者负责让全部命中条目共同插入该开场白的完整初值，可用 `randomblob(16)` 为每次执行创建独立业务行。
- 允许没有对应 INIT，此时各注册表的初层为空，不自动收入 DDL 已写入的业务行；开场白 regen 从空数据生成初值，忽略已有变量。没有 INIT 时，开场白重新生成仍从空起点开始。
- 相同业务值应插入新的 rid。写死重复 rid 或改写其他开场白旧记录的后果由作者处理。

初始化时机：

- 打开新聊天立即初始化当前原生开场白。
- 切换到未初始化的开场白，会执行对应 INIT 并建立新的 fid 索引。
- 切回已有 fid，直接读原数据。
- 已初始化的单开场白所有 swipe 均丢失 fid 时，复用注册业务索引中唯一的 fid，不重跑 INIT；完整空索引且业务全空时只建立空状态关联，多状态或数据／结构不完整时停止并提示核对。
- 手工重排或导入的开场白不能保证自动识别来源，不应依靠文本猜编号。
- 自动处理新聊天开场白选择；完整正文成功后自动更新变量，也可主动重新更新最新回复当前 swipe。

全部命中 INIT、必要索引结构和初始索引在同一次数据库事务中提交，任一条失败整组回滚。成功后关联一个 fid，聊天中的 fid 另行保存并读回。DDL 仍按版本分别提交。迁移或初始化 SQL 失败会停止并报告，不自动重试。本页已知关联保存失败也停止；刷新页面后按文件中的实际关联继续，无关联且仍为可识别的单开场白时按唯一现存索引补回关联，不重跑 INIT。聊天文件与当前显示关联不一致时先停止，不能绕过读回检查。

## 角色卡升级

本节处理业务表结构变化。只整理旧标签或脚本默认配置时，按[旧版 DVS 卡片升级](DVS作者使用手册.md#旧版-dvs-卡片升级)执行，不增加 DDL 迁移或重跑 INIT。

升级规则：

- 每个聊天自己的 `_dvs_version` 单行保存最近成功的 DDL 版本。
- 添加 `[DVS:DDL]v1.1.0` 后，DVS 使用 npm semver 选择比该聊天记录更高的条目，按升序执行。
- 每个版本的 SQL 与版本号在同一次 `runSql` 中提交。
- 某版本失败时停止后续版本，保留之前已成功的版本。
- 不自动降级。

版本格式：

- 必须是三段 SemVer `major.minor.patch`，支持预发布和构建元数据，例如 `1.10.0`、`2.0.0-alpha.2`。
- 不支持 `1.2`、前导零或版本范围。
- 构建元数据不影响优先级，两个同优先级条目会报歧义。

迁移中的新增或改名业务表、数据与索引关联，由作者 SQL 明确维护。DVS 保留 `_dvs_version`、`_dvs_gc_counter`、`_dvs_index_<业务表名>`，不要把这些名称作为业务表。

```sql
CREATE TABLE "新表" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  名称 TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS "_dvs_index_新表" (
  fid BLOB NOT NULL CHECK(typeof(fid)='blob' AND length(fid)=16),
  rid BLOB NOT NULL CHECK(typeof(rid)='blob' AND length(rid)=16),
  PRIMARY KEY(fid,rid)
) WITHOUT ROWID;
INSERT INTO "新表"(rid,名称)
SELECT randomblob(16),'升级初值' WHERE [[last_fid]] IS NOT NULL;
INSERT INTO "_dvs_index_新表"(fid,rid)
SELECT [[last_fid]],rid FROM "新表" WHERE [[last_fid]] IS NOT NULL;
```

这是新增业务表的完整迁移示例，需要同时在注册声明中增加 `新表: ['名称']`。

| 聊天情况 | `[[last_fid]]` | 结果 |
| --- | --- | --- |
| 已有聊天 | 固定 fid | 将新行关联到当前 fid |
| 全新聊天 | NULL | 只建表，不创建关联；由随后对应的 INIT 插入完整初值 |

作者应同步修改各开场白 INIT，包含新表的初始行。旧历史 fid 是否补齐，由作者迁移 SQL 决定。

`[[last_fid]]` 的规则：

- 它是保留文本标记。所有精确匹配的文本直接替换为固定 fid 的 `X'32位十六进制'`，无有效关联时替换为 NULL。
- 只放在 SQL 值位置，外面不加引号。
- 字符串、标识符和注释中的相同文本也会被替换。需原样保留的文字，避免写出完整标记。
- 迁移 SQL 不展开酒馆宏，源世界书不被修改。INIT 单独支持 SQL 字符串内的 `{{user}}`，见[准备 SQL](#为角色卡准备-sql)。

## 配置变量模型

配置有独立名称和稳定标识。“DVS 配置”中的“功能使用”“模型配置”“功能配置”和“显示”怎样操作见[作者手册](DVS作者使用手册.md#配置变量模型)。新增、修改和复制先编辑草稿，点「保存」后才可供请求使用，「取消」保留已保存值。复制包含当前空间密钥，保存后可独立修改；使用中的配置须先在“功能使用”换成其他配置才能删除。这两个功能的模型选择属于酒馆账户，切卡后沿用。角色卡各自决定是否启用输入增强。“变量更新”和“输入增强”的下拉框选中即保存，保存失败时回到原值；“变量更新”未选择时正文生成后不更新变量，“输入增强”可选择固定配置或“跟随变量更新”，作者启用适用功能后在正文生成前使用。每次更新固定开始时的保存值，改动从下次新流程生效。

高级参数中的“额外历史正文”允许 0，默认 2。当前待更新 AI 正文及最近前置用户消息不计入这个数。

插件设置中的“DVS 配置”不依赖当前角色卡是否已注册 DVS；其中角色功能配置仅在注册有效时提供。API 地址填写 `http` 或 `https` 基础地址，即 OpenAI 兼容接口的 `/v1` 这一级，不要填写完整的 `/chat/completions` 路径；模型名可以直接输入，也可以点「获取」读取模型列表后选择。无认证服务可以不填 API Key。保存前校验输入，普通参数交给酒馆原生设置保存，同一页面立即使用新配置。其他酒馆页面刷新后取得修改。

普通参数保存在当前酒馆账户的扩展设置中。API 密钥保存在当前 SQLite 存储空间的 root 数据库，记录为本机明文；其他可信脚本、数据库查看器和备份可能读取。API Key 输入框始终以空值开始：已有密钥时留空表示保持，输入新值才替换；要删除时点「清除密钥」，保存后才执行，点「撤销」或取消编辑则保留原值。存储空间切换后需重新读取当前空间的密钥状态。读取失败会显示“状态未确认”，不能据此假定没有密钥。密钥写入与普通参数保存是两个存储操作，界面分别报告已知结果；数据库后台保存仍可能尚未落盘。

“附加请求参数”接收 JSON 对象，留空等同 `{}`，格式错误即时提示。「DeepSeek 关闭思考」只在当前表单写入 `{"thinking":{"type":"disabled"}}` 并保留其他参数，不会自动保存或发送请求。地址、数值或 JSON 不符合输入规则时会提示并阻止保存或请求。测试最多发送三次固定内容的模型请求，可能产生费用；它不读取聊天或修改变量。模型列表为空时仍可手动填写模型名；模型接口或配置读取失败会显示错误，不能据此认定服务不支持所选格式。保存后的摘要只显示密钥是否存在，不显示明文。

角色卡作者可在开场白原文中加入精确标签 `<DVSConfig/>`。DVS 注册并启用后，会在合格角色卡开场白的标签位置显示同一套配置面板；已有配置时默认收起，只列出两项功能各自使用的配置名和 API 地址，点头部展开，没有任何配置时始终展开。两处面板共用已保存配置，一处保存后另一处立即同步，各自保留未保存的修改。没有标签时仍可从插件设置进入。标签应置于独立段落或普通正文中，不要放在代码块中。插件自动安装仅 AI 输出的显示和提示词正则：显示时将标签替换为空容器并在原位置挂载面板，发送给 AI 时删除标签，无深度限制。作者无需另配这两条规则；已有的仅提示词删除规则可以保留，不要另加仅格式显示的删除规则。代码块中的标签作为示例显示，不生成面板。

### 参数与输出格式

| 参数 | 默认值 | 有效范围或含义 |
| --- | ---: | --- |
| 流式调用 | 关闭（stream=false） | 布尔值，随命名配置保存；旧配置缺字段按关闭读取。两种方式均收齐结果后执行，模型列表仍读 JSON |
| 世界书优化筛选方式 | 排除无关（exclude） | 仅输入增强；保存在角色的 lb_opt.filter_mode，include 列出保留项，exclude 列出排除项 |
| 变量优化筛选方式 | 排除无关（exclude） | 仅输入增强；保存在角色的 tables_opt.filter_mode，与世界书独立设置 |
| 最大回复 | 65535 tokens | 正整数，所选功能模型请求的输出上限 |
| 额外历史正文 | 2 条 | 非负整数，不决定世界书扫描深度 |
| 温度 | 1 | 0–2 |
| 频率惩罚／存在惩罚 | 0 | 各为 -2–2 |
| Top P | 1 | 0–1 |
| Top K | 0 | 非负整数，0 不发送 |
| 最小正文 | 0 字符 | 非负整数。按变量更新所选模型配置，去掉 DVS 胶囊、HTML 注释和标签后，正文长度严格大于此值才自动请求。手动「重新更新」或 `DVS.regen()` 不检查此值 |
| 最多请求 | 3 次 | 正整数，含首次请求，1 不重试 |
| 重试间隔 | 1000 毫秒 | 非负有限毫秒数 |
| 超时 | 300 秒 | 单次请求的上限，大于 0 的有限秒数，只约束模型请求 |

两种筛选方式都要求保留本轮相关资料，以及已有具体关联而细节未知的资料；不凭未安排的未来情节保留，固定条件仍按原条件判断。exclude 的空列表表示全部保留，include 的空列表表示不保留；模式不改变变量更新的补丁生成。操作方式见[正文筛选与剧情规划](#正文筛选与剧情规划)。

温度 1、惩罚 0、top p 1、top k 0 省略发送，由服务采用默认值；这不强制服务使用这些值。DVS 不继承正文模型当前的采样设置。非法输入会阻止保存和请求，合法值是否被服务接受以实际请求为准。

API 地址不能包含凭据、查询参数或片段，不自动补 `/v1`。额外请求体只能使用 JSON 对象和有限 JSON 值，不能覆盖 `model`、`messages`、`prompt`、`stream`、token 上限、采样、工具调用、`json_schema`、`chat_completion_source`、`custom_*` 或鉴权字段；密钥只填密钥框。`response_format` 由 DVS 按所选格式整体管理，`text` 时移除，不能用额外请求体绕过格式选择。

为兼容 OpenCode，DVS 变量更新的 JSON Schema 省略了 `propertyNames`。DVS 收到更新命令后仍在本地检查 `keys` 的键名非空，并按表声明核对完整业务键。

初始输出格式为 `text`，不发送 `response_format`，仍要求 DVS JSON 补丁；`json_object` 发送对象约束；`json_schema` 发送完整 DVS schema，使用 `strict: false` 以允许新增行省略默认列。三种格式最终都做本地协议和数据库检查，不根据模型名称自动推断支持，也不在失败后静默降级。

「测试」先用小 JSON 示例检查连接。连接成功后依次试 JSON_Schema、JSON_Object，并按结果标出推荐格式。若“排除参数”含 `response_format`，只测连接，两种格式均显示未测试。网络、认证、限流、超时或取消会使测试未完成。可点「改用推荐格式」后自行保存，修改连接参数会清除旧结果。测试只验证本次示例；取消或超时停止本地等待，远端仍可能继续生成或计费。

## 错误与保存

管理方法成功说明当前数据库内核中的事务已在内存提交，SQLite 文件由 Helper 之后后台保存。此规则适用于共享、独立 Worker 和页面内执行模式。聊天 fid 通过原生保存及固定文件读回确认。SQLite 与聊天文件不是同一事务。

| 情况 | 结果与处理 |
| --- | --- |
| 明确回滚 | 不保留失败写入 |
| 结果 unknown | 不重发 |
| 已提交但对象读回失败 | 报“数据库已提交、对象刷新失败”。相关对象禁止继续管理，请重新 `getState` 核对 |
| 初值已提交但聊天关联失败 | 本页停止初始化；刷新页面后按文件实际关联继续，单开场白仅有一份现存状态时补回关联，不重跑 INIT |
| 另一 Tab 已保存关联、本 Tab 仍缺 fid | 重新打开或刷新聊天后读取 |

完整入门卡见[青禾书店示例](../../../examples/dvs-minimal-card/README.md)；该卡只含世界书、开场白和注册脚本，不提供作者面板。

## 支持范围

DVS 用于单人聊天的普通生成、重新生成最新回复和新 swipe；完整 AI 正文成功、变量功能已启用且正文长度超过所选模型门槛时，才会自动请求变量更新。续写、冒充用户、群聊、工具递归和酒馆助手独立生成不在支持范围内。

历史状态只在当前聊天仍保留相应消息和 swipe 关联时可读，不能管理旧层。删除楼层或 swipe、替换版本等可能留下无引用数据的操作累计满 10 次后，DVS 在能确认聊天引用时清理失效关联与无引用业务行。普通追加回复不增加计数。

插件启用时，单人聊天新建的原生分支和检查点使用独立聊天库。DVS 在副本中保留目标聊天全部楼层及 swipe 仍引用的变量数据，之后的变量更新只写入各自的库。已有分支沿用原编号。其他方式复制聊天、导入带编号的角色或聊天，以及插件停用期间创建的副本，均无自动隔离保证。完整备份恢复尚未提供。数据保存、存储模式及插件更新见[使用与维护指南](../../sqlite-helper/指南/使用与维护指南.md)。

提示词模板 Worker 后台编译方式的 DVS 最终正文注入未完成专项验证；约 10 MB、每秒一次写入与长期内存占用也没有专项性能结论。浏览器、模型或模板的其他版本不能由一份示例成功推定全部可用。
