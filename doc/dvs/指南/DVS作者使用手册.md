# DVS 作者使用手册

先运行[青禾书店最小角色卡](../../../examples/dvs-minimal-card/README.md)，再沿本手册把它改成自己的卡。示例只有成年店员林溪的基本设定、开场白、世界书和 DVS 脚本，记录好感度、时间地点和随身物品，不需要状态栏或 EJS 插件。

SQLite Helper 负责数据库读写和文件保存；DVS 为每条 AI 回复管理一份状态，把起点交给正文模型，并在正文完成后请求变量模型更新。作者决定表结构、初值、字段含义和变化规则。安装、自动设置（工作模式与存储模式）与更新先按[使用与维护指南](../../sqlite-helper/指南/使用与维护指南.md)完成，未完成自动设置时 DVS 接口不发布；接口细节在[DVS 接口与进阶用法](DVS接口与进阶用法.md)中按需查阅。

## 从完整示例开始

需要随卡提供插件安装提示时，可另行附带[安装引导脚本](../../使用/安装引导脚本.md)，与 DVS 注册脚本分开保留；这项内容可选。

按示例的[README](../../../examples/dvs-minimal-card/README.md)导入 [card.json](../../../examples/dvs-minimal-card/card.json)。它的可编辑来源是 [index.yaml](../../../examples/dvs-minimal-card/index.yaml)、[开场白](../../../examples/dvs-minimal-card/welcome.txt)、[DVS 脚本](../../../examples/dvs-minimal-card/dvs.js)及世界书文件；导入包由这些来源生成。修改源文件后重新生成，避免同时手改来源和导入包。

先打开示例的专用新聊天，确认脚本启用、初始化查询和一次变量更新都能完成，再修改内容。已有聊天不会因改了 INIT 就重新初始化。

| 作者操作 | 应得到的结果 |
| --- | --- |
| 确定设定及需要变化的内容 | 静态人物设定与动态字段各有用途 |
| 写 DDL 和 INIT | 表结构、初值和开场白一致 |
| 组织世界书 | 正文看到当前状态，变量模型看到规则和起点 |
| 注册业务键与两个准备回调 | DVS 能定位每行，并准备两次请求的数据 |
| 生成正文、查询结果 | 表名、键、字段及实际变化可核对 |
| 修改字段并升级 | 新聊天和已有聊天都按明确版本取得新结构 |

## 从设定确定表和业务键

林溪是青禾书店的 24 岁店员，用户是来访者。人物身份放在[人物设定](../../../examples/dvs-minimal-card/worldbook/person.txt)；会随剧情变化的值才进入数据库。

| 表 | 业务字段 | 在一份状态中怎样定位一行 | 初值 |
| --- | --- | --- | --- |
| 人物 | 姓名、好感度 | 姓名 | 林溪，好感度 10 |
| 场景 | 编号、时间、地点 | 编号，固定为“当前” | 2026-10-19 15:00，青禾书店 |
| 物品 | 名称、数量 | 名称 | 林溪随身的帆布包 1、书签 2 |

这里的定位字段叫业务键，注册时写入 `uniqueKeys`。姓名定位“林溪”，不是它的数据库行编号。物品表统一表示林溪随身的物品；同名物品合并数量，不能在同一份状态中有两个同名行。需要区分不同持有人或不同实例时，应先决定自己的业务含义，再相应修改表和业务键。

每张真实表另有 `rid`：它是 16 字节 BLOB 主键，区分同一对象不同时间的记录。DVS 正常写入时生成 `rid`，模型不用提供它。业务表保留历史行，因此不要给姓名、物品名称等业务键加全表 SQL `UNIQUE`；它们只要求在目标 AI 回复的有效集合中唯一。

## 为角色卡准备 SQL

**DVS 业务表和楼层索引表不支持触发器。**

打开示例的 [ddl.sql](../../../examples/dvs-minimal-card/worldbook/ddl.sql) 和 [init.sql](../../../examples/dvs-minimal-card/worldbook/init.sql)：

1. DDL 创建业务表及字段约束。示例好感度为 0–100，物品数量是大于 0 的整数；这些是该卡的规则，由 SQLite 约束实际写入。
2. INIT 插入开场白起点，使用 `randomblob(16)` 产生初始 `rid`。初始化数据必须与[开场白](../../../examples/dvs-minimal-card/welcome.txt)相符。
3. 在角色卡绑定的主世界书或附加世界书中，将它们分别登记为精确名称 `[DVS:DDL]v1.0.0` 和 `[DVS:初始化]welcome_0`。SQL 条目保持禁用，DVS 仍会读取；内容可有多条 SQL，不自行写 `BEGIN`、`COMMIT` 或 `ROLLBACK`。

条目名中的 `1.0.0` 只是示例，作者也可以从 `[DVS:DDL]v0.1.0` 开始。已有聊天不会自动降级；修改起始版本不代表会重新执行其初值。

第一次打开新聊天，DVS 先执行 DDL，再执行对应开场白的全部 INIT，并为它建立一个数据关联。INIT 可以拆成多条同名条目，也可用 `welcome_0,1,2` 供指定开场白共用，或用 `welcome_*` 供全部开场白共用。命中条目按世界书 `order` 升序执行，相同值保持读取顺序；全部 INIT 和初始索引共同提交或回滚。共用条目每次首次初始化都会执行，新增独立业务行时可用 `randomblob(16)`。

已有有效关联时重新打开不会重复插入；切回已有初始化状态的开场白会读取原值。已初始化的聊天只有开场白且所有版本关联丢失时，会补回数据库中的唯一状态关联，不重跑 INIT；有多份状态而无法确定时会提示核对。保留默认开场白时，它对应 `welcome_0`，额外开场白依次用 `welcome_1`、`welcome_2`。若去掉空默认项，当前按实际 swipe 编号匹配。所有开场共用的初值可放在 `welcome_*`。多个开场白、INIT 省略和用户名字占位符 `{{user}}` 的完整规则见[初始化参考](DVS接口与进阶用法.md#为角色卡准备-sql)。

## 选择世界书条目的用途

示例在 [index.yaml](../../../examples/dvs-minimal-card/index.yaml) 中登记以下条目，正文来源仍在各自文件中维护：

新卡和本示例统一使用 `[DVS:…]` 标签。旧卡继续兼容；需要整理旧源文件时，按[旧版 DVS 卡片升级](#旧版-dvs-卡片升级)操作，不要逐词替换标签。

| 条目 | 内容来源 | 开关与用途 |
| --- | --- | --- |
| `[DVS:DDL]v1.0.0` | [ddl.sql](../../../examples/dvs-minimal-card/worldbook/ddl.sql) | 禁用；创建或迁移表结构 |
| `[DVS:初始化]welcome_0` | [init.sql](../../../examples/dvs-minimal-card/worldbook/init.sql) | 禁用；插入开场白初值 |
| 人物设定 | [person.txt](../../../examples/dvs-minimal-card/worldbook/person.txt) | 启用常驻；正文和变量请求共用静态背景 |
| `[DVS:预处理,正文]当前状态` | [narrative.txt](../../../examples/dvs-minimal-card/worldbook/narrative.txt) | 启用常驻；给正文提供当前状态 |
| `[DVS:变量规则]更新规则` | [rules.txt](../../../examples/dvs-minimal-card/worldbook/rules.txt) | 启用；说明字段含义和变化条件 |
| `[DVS:变量数据]变量数据` | [data.txt](../../../examples/dvs-minimal-card/worldbook/data.txt) | 启用；给变量模型提供本轮起点 |

正文条目用 `[[DVS_DATA]]` 或分表宏取得本次准备好的数据。规则写“发生什么，改哪张表、哪个字段，怎样改变”，并交代数值边界、时间格式、物品耗尽时移除等业务含义；数据条目用宏提供实际起点，不手写一份会过时的当前值。DVS 自动提供表名、业务键、字段名和补丁协议，不必再复制一套输出格式。

`[DVS:预处理,正文]` 可给输入预处理与正文使用；`[DVS:后处理]` 只给正文完成后的变量请求使用。无 DVS 标签的普通设定可供三阶段使用，仍遵守酒馆激活规则。`[DVS:变量规则]`、`[DVS:变量数据]` 直接读取已启用条目，不靠关键词激活；SQL 不进入提示词。标签范围与用途的组合见[世界书参考](DVS接口与进阶用法.md#选择世界书条目的用途)。


## 注册与查询

角色卡只绑定一个 DVS 注册脚本。查看示例 [dvs.js](../../../examples/dvs-minimal-card/dvs.js)，它依次等待 `waitGlobalInitialized('DVS')`、传入自身 `getScriptId()` 注册，并在页面卸载时调用返回的释放函数。

需要同时处理等待注册期间脚本关闭时，可在等待接口之前创建 `AbortController`，用 `pagehide` 调用 `abort()`，注册时传入第二参数 `{ signal }`，由 DVS 统一注销本次注册。独立状态栏使用 `DVS.onRegistrationChange()` 等待有效注册并在重新注册后重建数据订阅；接口已发布不代表卡片已就绪。完整写法见[注册状态与脚本关闭](DVS接口与进阶用法.md#注册状态与脚本关闭)。

新卡在这个脚本的酒馆助手预设定变量中设置 `{ "dvs": { "enabled": true } }`，并启用角色卡脚本及其文件夹。这里只接受布尔值 `true`，字符串 `"true"` 和数字无效；改动后按助手原生方式重载脚本。旧卡的配置处理见[旧版 DVS 卡片升级](#旧版-dvs-卡片升级)。等待公共接口可用不等于已启用卡片功能，关闭时不会注册或初始化。

注册的 `uniqueKeys` 与上表逐项一致：`人物: ['姓名']`、`场景: ['编号']`、`物品: ['名称']`。两个准备回调都不能省略：

| 回调 | 用途 | 最小卡的处理 |
| --- | --- | --- |
| `narrativePrepare({ tables })` | 正文生成前准备宏数据 | 返回 `tables` |
| `beforeGen(_state, tables)` | 变量模型请求前准备宏数据 | 返回 `tables` |

这两个返回值只影响相应提示词，不会直接修改数据库。没有确定的业务计算时，无需增加其他回调或虚拟表。需要隐藏提示词字段或在写入前计算时，查[回调参考](DVS接口与进阶用法.md#数据准备和更新回调)。

注册完成后，可在当前角色的酒馆助手脚本中查询：

```js
const state = await DVS.getState();
const person = await state.table('人物').get('林溪');
const scene = await state.table('场景').get('当前');
const items = await state.table('物品').orderBy('名称', 'asc').rows();
console.log(JSON.stringify({ person, scene, items }));
```

`get()` 按注册业务键的完整顺序传值，没有匹配返回 `null`。无参 `getState()` 取最近 AI 回复当前 swipe 的状态；该回复尚无关联时会报错，不偷偷退回旧回复。历史查询和多字段业务键见[查询参考](DVS接口与进阶用法.md#注册与查询)。

## 正文数据注入

正文模型按照人物设定和当前状态续写；`narrativePrepare` 返回的数据通过正文世界书中的 DVS 宏送入提示词。最小示例不使用 EJS，只需酒馆助手及本插件。

| 操作 | 正文和随后变量更新使用的起点 |
| --- | --- |
| 发送下一句，正常追加回复 | 最近 AI 回复当前 swipe 的状态 |
| 重新生成末尾普通 AI 回复、生成它的新 swipe | 被替换回复之前的 AI 回复状态 |
| 末尾是用户消息时重新生成 | 仍按追加取值 |
| 只有已初始化的开场白时生成后续正文 | 当前开场白状态，不重跑 INIT |

例如林溪的好感度在 A 回复后是 10，B 回复后变为 12。正常接着 B 写从 12 出发；重新生成 B 从 A 的 10 出发。作者不需要自己计算上一层，也不要在准备回调中无条件再读一次 `DVS.getState()` 来替代收到的起点。

总表宏默认 Markdown；`[[DVS_DATA_人物:yaml]]` 可只输出人物表的 YAML。只修改返回的数据副本，就只影响本次提示词。宏格式、序列化错误和可选 EJS 查询的边界见[正文注入参考](DVS接口与进阶用法.md#正文数据注入)。

## 配置变量模型

第一次配置时，打开“扩展设置 → DVS → 模型配置”，填写名称、接口地址、模型和服务所需的密钥，点「保存」。第一份配置自动用于变量更新。之后可在“功能使用”中分别选择变量更新和输入增强的模型，或让输入增强跟随变量更新。这两项选择保存在酒馆账户中，切卡后沿用；是否启用输入增强由各角色卡决定。

| 区块 | 在这里看到什么、怎样操作 |
| --- | --- |
| 功能使用 | “变量更新”“输入增强”各一行下拉框，选中即保存，旁边显示保存中或已保存的勾；保存失败时下拉框回到原值并提示错误。变量更新没有选择时显示“变量更新还没有选择配置，正文生成后不会更新变量。”。输入增强可选“跟随变量更新”，说明里注明当前跟随的配置。第一份保存的配置会自动用于变量更新 |
| 模型配置 | 每份配置是一张卡片，显示名称、用途标签、模型、API 主机和密钥状态图标；点开卡片查看详情，并可「修改」「复制」「删除」。点「新增」创建配置，还没有配置时直接显示“创建第一个模型配置” |
| 功能配置 | 默认折叠，修改当前角色卡的变量功能、剧情规划、生成拦截、世界书优化和变量优化；两项优化各自选择“排除无关”或“只留所需”，关闭优化仍保留选择 |
| 显示 | “聊天面板配色”可选跟随酒馆主题、深色、浅色，点选后聊天中的 DVS 面板立即换色。“楼层数据查看”设为“显示”后，“正文分析”胶囊展开时卡片头提供「楼层数据」，空记录也可查看实际关联的业务数据；账户级显示设置不放入角色功能配置 |

「楼层数据」窗口的“更新后”显示本楼层当前回复版本关联的数据，“更新前”显示上一条未隐藏 AI 回复当前版本关联的数据；开场白没有更早的状态。选择业务表后，可以搜索、筛选、排序、翻页或切换行列，也可查看建表语句。数据页不显示内部 `rid` 列；建表语句始终来自当前数据库，不代表历史楼层当时的表结构。窗口只读，不会修改变量或触发模型请求。

新增、修改和复制都在卡片内展开编辑区，点「保存」后才用于请求，点「取消」保留已保存值。编辑区依次是：

1. 连接：填写配置名称、API 地址和按需填写的 API Key。地址是 OpenAI 兼容接口，填到 `/v1` 这一级，不包含末尾 `/chat/completions`；新增时预填 DeepSeek 官方地址。模型可以手填，也可以点「获取」后从列表选择。
2. 输出与筛选：选择输出格式和“调用方式”（非流式／流式，默认非流式）；角色卡的筛选方式在“功能配置”中调整。
3. 高级参数：默认收起，标题显示“已改 N 项”或“全部为默认值”；改过的数值可一键恢复默认。“附加请求参数”可用「DeepSeek 关闭思考」填入预设。
   - “最小正文”按变量更新所选的模型配置生效，默认 0。去掉 DVS 胶囊、HTML 注释和标签后，正文长度超过这个数才自动请求变量更新。
   - “排除参数”填写模型接口不接受的顶层字段名，如 `top_p, reasoning_effort`，也可每行填一个。酒馆发送请求前会去掉这些字段。
   - “附加请求头”每行填一个 `Header: Value`。点击「opencode会话头」后，直接输入自己的会话键即可替换选中的 `your-session-key`。再次点击会选中已有的值。请求头随这份模型配置保存在酒馆扩展设置中。
4. 测试：点「测试」检查连接和两种 JSON 格式；若“排除参数”含 `response_format`，只检查连接，两种格式显示未测试，结果逐项显示通过、未通过或未完成，并在输出格式上标出“推荐”，可点「改用推荐格式」，不会自动改动或保存。每次测试最多三次请求，会产生少量费用，但不读取聊天、不更新变量。
5. 保存：有改动时显示“未保存”；正在使用的配置注明“保存后立即用于：…”，保存后下一次流程即按新值请求，正在进行的更新仍用开始时的配置。

复制会沿用原配置的密钥，界面不显示明文，保存后成为独立配置。正在被任一功能使用的配置不能删除，需先在“功能使用”换成其他配置；删除时卡片内会再要求点「确认删除」。

“功能配置”中的世界书优化和变量优化分别设置筛选方式。开启对应优化后才能切换。关闭时保留原选择，下次开启时继续使用。

默认的“排除无关”（`exclude`）让模型列出要去掉的资料，其余保留。“只留所需”（`include`）让模型列出要保留的资料，其余去掉。选择保存在当前角色卡的扩展配置中，不影响变量更新。角色尚未设置时，继续使用旧模型配置中的筛选方式。初次使用可沿用默认值，按[输入增强示例](#可选正文资料筛选与剧情规划)编写条件与规划规则。

角色卡也可以在开场白中放 `<DVSConfig/>`，让玩家在聊天中直接配置；已有配置时这个面板默认收起，只显示两项功能各自使用的配置名和 API 地址，点头部展开。两个入口共用同一份已保存配置，一处保存，另一处立即同步。

旧配置没有调用方式字段时使用非流式，复制配置会保留该值。切换调用方式会清除上次测试结果并取消进行中的测试，不影响模型列表；保存后只影响新请求。输入增强选择“跟随变量更新”时也跟随调用方式。DVS 在两种方式下都收齐回复后处理变量，不改变酒馆正文的流式显示。

普通参数保存在酒馆账户设置中；密钥以明文保存在当前 SQLite 存储空间。API Key 输入框留空表示保持已有密钥；要删除时点「清除密钥」，保存后才执行。切换存储空间后重新核对密钥状态，显示“状态未确认”不等于没有密钥。参数范围、输出格式、密钥保存结果及开场白配置面板的写法见[配置参考](DVS接口与进阶用法.md#配置变量模型)。

## 检查一次完整更新

1. 在专用新聊天运行上面的查询。初值应与 INIT 一致：人物林溪／10，当前场景的时间地点，以及两行随身物品。
2. 发送“林溪，请送我一张书签。”等待正文完整生成，用酒馆的提示词查看入口核对本轮起点。正文应收到准备好的状态，SQL 和变量专用规则只供 DVS 使用。
3. 等待变量处理结束。回复尾部的“正文分析”胶囊会从“更新中”变为命令计数，例如“改 1 · 增 1 · 增减 1”。点开后展开“更新命令”（“思维链”“实体分析”默认收起），检查每条命令的表名、完整业务键和字段；命令类型显示为修改、新增、删除、增加或减少。这里是模型原始建议，不是全部写入成功的证明，面板的读法见[查看变量更新面板](#查看变量更新面板)。
4. 再用 `DVS.getState()` 查书签数量。林溪已交付一张时应从 2 变为 1；只答应稍后送时应仍为 2。好感度则按卡片规则和生成的正文判断。
5. 重新生成最新普通回复或生成新 swipe，核对起点来自前一个 AI 回复；切回原 swipe，仍应读到它自己保存的状态。
6. 单独核对保存：管理方法或查询成功只证明当前数据库内核中的数据，不证明 SQLite 文件已落盘。先处理插件报告的后台保存失败，再按[保存与检查说明](../../sqlite-helper/指南/业务侧使用指南.md)检查文件或关闭全部相关页面后重新打开读取；聊天关联与数据库文件也不是同一事务。

启用变量更新并选好模型后，只有成功完成的正文长度超过所选模型的「最小正文」，才会自动请求变量模型。只支持单人聊天的普通生成、重新生成最新回复和新 swipe；续写、冒充用户、群聊、工具递归和助手独立请求不在支持范围内。

### 查看变量更新面板

DVS 处理过的 AI 回复，正文末尾带有 `<DVSData type="ai">…</DVSData>` 标签，聊天中显示为一个默认收起的“正文分析”胶囊。标签正文保存按扩展划分的 records 及可选 analyses，summary 属性保存头部摘要；在酒馆消息编辑框中可以看到。自动流程即使因正文失败或过短跳过变量请求，也为有效 AI 回复保留无数据胶囊。旧 `<DVSUpdateData>` 继续兼容，展示读取时转换并保存新格式；没有任何标签的历史楼层不批量补写。

| 胶囊上显示 | 含义 |
| --- | --- |
| 命令计数，如“改 2 · 增 1 · 删 1 · 增减 2” | 正常记录，四类分别是修改、新增、删除、增减；没有命令时显示“无更新” |
| 更新中 | 这条回复正在更新变量。展开只显示进度和头部操作区，暂时隐藏旧结果；成功后显示新记录，失败或取消后恢复原记录 |
| 无数据（灰色） | records 为空，例如本次跳过变量请求、更新失败并沿用起点变量。下一轮仍从这条回复已关联的变量继续 |
| 出错（红色） | 标签为空且本次会话中更新失败，展开可看失败原因；刷新页面后不再显示原因，回到“无数据” |
| 数据异常（琥珀色） | 标签内容无法解析，展开后显示失败信息与错误详情；可在最新回复上重新更新，不要求旧记录能解析 |

展开后直接显示扩展内部的可折叠内容，不额外套一层扩展标题或折叠。“思维链”和“实体分析”默认收起，“更新命令”默认展开。思维链仅在有非空内容时显示，它是模型可选的检查摘要，超过五行先折叠，点“展开全文”查看全部。实体分析和更新命令的位置写成“表 › 业务键 › 字段”，多字段业务键显示为 `列=值`，原因在下一行。每条命令左侧标出类型：修改显示 `字段 → 新值`，新增直接展开新值，删除在路径上加删除线并注明“移除整行”，增减按正负显示为“增加”或“减少”，后面是带符号的数字。清空单个字段使用修改命令。较长的对象或数组另起一块按 YAML 显示。

面板展开后，头部的计数可当作筛选：点“改 2”只看修改命令，“更新命令”显示为“2 / 6”，再点一次或点“显示全部”取消；收起面板时筛选清空。面板底部提示“这是模型给出的原始建议，作者规则可能订正，实际写入以数据库为准。”。

只有最新一条 AI 回复（跳过 `/hide` 隐藏的消息）在展开后显示「重新更新」；更早的回复展开后标为“历史记录 · 只读”。生成或更新进行中按钮不可用。重绘时如果沿用已有面板，展开状态会保留；面板卸载重建或刷新页面后默认收起。

### 主动更新最新回复的变量

点击最新 AI 回复“正文分析”面板中的「重新更新」，或在角色卡作者脚本中调用 `await DVS.regen()`，可重算这条回复当前 swipe 的变量，不重新生成正文；手工请求不检查自动流程的正文长度门槛，空胶囊也能使用。普通回复仍从前一 AI 回复开始；只有开场白时从全部注册表为空开始，忽略已有值且不重跑 INIT。因此它不能用来“恢复原 INIT”。

重新更新只在成功后替换面板内容。这条回复已经关联了变量时（包括此前失败后沿用得到的变量），全部尝试失败不采用失败目标版本、不改变原关联，原记录保持不变，面板显示失败原因；已经发生的部分写入不会物理撤销。只有还没有任何变量关联的回复（通常是刚生成完的正文）失败后，才沿用上一 AI 回复的变量。

处理期间暂不能发送下一轮，可以点击酒馆停止按钮；取消不撤销已提交修改。自动重试、停止后的结果和进度接口见[变量更新参考](DVS接口与进阶用法.md#主动更新最新回复的变量)。

## 角色卡升级

如果给人物增加“备注”，新聊天和已有聊天都要取得这个字段。不要只编辑已执行过的 `v1.0.0` 或修改 INIT 来期待旧聊天重跑。

1. 保留旧 DDL，新增禁用的 `[DVS:DDL]v1.1.0`，内容例如 `ALTER TABLE "人物" ADD COLUMN "备注" TEXT NOT NULL DEFAULT '';`。新聊天依次执行两个版本，旧聊天只执行高于已成功版本的迁移。
2. 检查 INIT 是否需要显式设置备注；这里可以省略并使用默认空字符串。若改变初值，同步开场白；旧聊天已有业务值按迁移 SQL 处理。
3. 在世界书中说明备注含义和何时更新，检查正文数据是否需要包含它。表和业务键不变时无需改 `uniqueKeys`；改名、拆表或换键则同步修改 DDL、数据、索引和脚本声明。
4. 原生重载脚本后分别检查一个新聊天和一个已有聊天。新的数据准备重新读取世界书，重叠的同目标准备可能共用尚未完成的任务。

迁移版本必须是完整三段 SemVer，按升序逐版本提交；当前版本失败会停止后续版本，保留先前成功版本，不自动降级。新增表及 `[[last_fid]]` 索引关联的完整写法见[迁移参考](DVS接口与进阶用法.md#角色卡升级)。

## 错误与保存

输入增强或变量更新报错时，打开“扩展设置 → DVS → 错误记录”。点开一条可查看 DVS 给出的原因、当次请求及原始响应，并可复制或下载 YAML。网络失败、响应解析或输出校验失败都会记录。部分响应后处理也在同一个捕获范围内，包括作者回调、数据库异常和这期间捕获的取消或目标失效。请按具体错误判断是要调整模型输出、修改脚本，还是核对数据库。

重试成功后，之前的失败仍保留。两个功能合计只保存本页最近 30 条，切聊天仍可查看，刷新前可下载。密钥会隐藏，提示词和模型输出会保留。

| 看到的情况 | 应怎样处理 |
| --- | --- |
| 未启用或未注册 | 检查布尔开关、脚本启用和当前角色绑定，再原生重载 |
| 表不存在、字段或业务键不符 | 对照 DDL、`uniqueKeys`、世界书字段和迁移版本 |
| 正文准备失败 | 修正回调或宏；请求会停止，原生已加入的用户消息不会自动撤回 |
| 变量模型失败，已沿用上一 AI 回复 | 这轮业务变化没有完成，“正文分析”显示“无数据”或“出错”；先检查规则／请求错误，再点「重新更新」或调用 `regen()` |
| 重新更新失败，这条回复保留原有变量 | 原变量和面板内容都没变，检查错误后可再试 |
| 结果无法确认、`unknown` | 不直接重发 SQL，按已知提交结果和实际读回核对 |
| 数据库已提交，对象刷新或后处理失败 | 已提交部分保留，重新 `getState()` 查询，不能当作全部回滚 |
| 初值已提交，聊天关联失败 | 本页停止重试；刷新页面后按聊天文件与索引核对，单开场白只有一份现存状态时补回关联 |

完整 DVS 结果边界见[错误与保存参考](DVS接口与进阶用法.md#错误与保存)，公共错误字段和后续处理见[错误说明](../../sqlite-helper/指南/错误说明.md)。启用插件后，在单人聊天中新建原生分支或检查点，DVS 会保留该分支楼层及 swipe 引用的变量。直接复制或导入聊天文件没有这项保证，完整备份恢复尚未提供。其余限制见[支持范围](DVS接口与进阶用法.md#支持范围)。


## 可选：正文资料筛选与剧情规划

当卡片有很多设定和物品时，可以在正文生成前增加一次“输入增强”请求。例如玩家说“请林溪挑一本雨天读的书，再拿张书签”，先让输入增强模型安排这轮对话，并挑出需要的书店设定与物品；正文模型据此展开描写。它不会提前改变好感度或扣除书签，变量仍在正文完成后按实际发生的事情更新。

最小卡默认关闭此功能，不需要修改也能正常游玩。下面是在自己的卡上增加的可选配置，不是要求向最小示例追加文件。仅使用宏不需要 EJS 插件。

### 开启并选择模型

在现有 DVS 注册脚本的酒馆助手预设定变量中保留原参数，再加上：

```json
{
  "dvs": {
    "enabled": true,
    "exts": { "tables_opt": true, "plot_plan": true },
    "config": { "lb_opt": { "llm_filter": true } }
  }
}
```

按酒馆助手原生方式重载脚本。在“DVS 配置”的“功能使用”中，为“输入增强”选择一份已保存配置，或保留“跟随变量更新”，选中即保存。它与酒馆自己的正文连接分别设置，可能额外产生一次模型请求费用。

世界书优化、变量优化与剧情规划独立启用；只需筛选时将 `dvs.exts.plot_plan` 设为 `false`，只需规划时也可单独开启它。玩家可直接在“功能配置”中调整，无需编辑脚本。“变量功能”关闭后不输出变量数据，也不请求或提交变量更新；变量优化没有候选数据，不产生筛选任务，世界书优化与剧情规划仍可使用。输入增强或正文后处理没有有效模型任务时不发送请求，新消息只保留空胶囊。旧 `dvs_input_inject`、`dvs_plot` 仍兼容，首次升级只保留旧配置当时实际启用的功能，升级后使用独立开关。

### 挑选世界书设定

在角色绑定的世界书中增加以下条目。为了先跑通例子，普通设定条目先设为启用、常驻；以后可按剧情改用关键词或其他原生激活条件。DVS 只在酒馆最终激活的条目中筛选，不能找回未激活或被预算挤出的内容。

| 条目名 | 内容 | 本轮用途 |
| --- | --- | --- |
| `[DVS:正文;可筛选]推荐雨天读物` | 见下方正文 | 满足条件时供正文参考，允许筛掉 |
| `[DVS:正文]文风` | `描写简洁温和，用具体动作表现人物情绪。` | 沿原生路径进入正文，不送入输入增强模型 |
| `[DVS:筛选规则]资料选择规则` | `保留本轮交谈、拿取与交付物品需要的资料。已有具体关联但细节尚未确定的内容保留；不要为了使用资料而增加支线。` | 启用即可；专供输入增强，不进正文或变量请求 |

“推荐雨天读物”的完整正文可以这样写：

```text
[[DVS_FILTER:本轮涉及挑选、推荐或讨论适合雨天阅读的书籍]]
书店的雨天推荐以节奏舒缓、适合短时阅读的散文为主。
推荐前应询问来客偏好，不凭空确定来客已经接受推荐。
```

标题中的 `可筛选` 表示允许筛选；正文开头的条件说明什么时候保留。没有条件时，模型按本轮相关性选择。普通有效条目会作为参考，正文仍正常使用；`[DVS:正文]` 适合只给正文使用的纯文风等内容，不能在其中放下面的四段数据筛选宏。

筛选规则可以分开写：`[DVS:世界书筛选规则]` 只用于世界书条目筛选，`[DVS:变量筛选规则]` 只用于表行筛选。`[DVS:筛选规则]` 同时用于两处，不必把同一段规则复制成两份。共用和专用条目同时存在时，按世界书顺序合并原文；启用即可，不要求关键词激活。条件仍表示“何时保留”，不随 include／exclude 反转。

### 只给正文需要的物品行

在现有 `[DVS:预处理,正文]当前状态` 中保留人物和场景，物品改用四段宏：

```text
请依据这些状态续写：
[[DVS_DATA_人物:yaml]]
[[DVS_DATA_场景:yaml]]

本轮可能查看、拿取或交付的物品：
[[DVS_DATA_物品:yaml:本轮物品:本轮行动需要查看、拿取、使用或交付的物品]]
```

四段分别是表名、输出格式、这一组选择的名字、自然语言保留条件。“本轮物品”只是你给这处筛选起的名字，不是数据库字段；同一表可以有不同组，也可在多处用同一组，但同组条件必须一致。筛选表的准备数据须保留完整业务键，例如最小卡的物品“名称”。

模型只能选择原有物品，正文收到的数量和其他字段来自 `narrativePrepare` 返回值，不采用模型重写的数值。原来的 `[[DVS_DATA]]`、`[[DVS_DATA_物品:yaml]]` 仍输出全量数据；不要又在正文别处输出全量物品宏，却期待它也被筛选。关闭变量优化或本轮“清除并继续”跳过输入增强时，四段宏输出该表的完整准备数据。变量更新使用 `beforeGen` 数据，不受这次正文筛选限制。

### 写剧情规则

在主世界书或附加世界书新增并启用 `[DVS:剧情规划]本轮安排`，内容例如：

```text
围绕来客当前要求安排这一轮，最多推进到本次交谈和取物结束。
林溪可以询问阅读偏好、提出推荐并回应取书签的请求。
不得替来客决定接受推荐、购买或离开。
检查人物所在地、已知信息与物品来源，未发生的交付不能写成既成事实。

[[DVS_PLOT:start:结束位置]]
在林溪提出选择或准备交付物品时结束，把购买和下一步行动留给来客。
[[DVS_PLOT:end]]
```

没有 `[DVS:剧情规划]` 条目也能规划。结果始终有“本轮方向”“情节步骤”“事实与边界”“结束位置”四个字段；上例只改写“结束位置”的要求，其他部分沿用默认任务。四项的值也可按作者要求改用对象、数组等 JSON 结构，新增字段可选，DVS 只检查四个基础字段存在，不检查各值的具体类型。一般规则直接写普通文字，需要细化某一部分或增加作者字段时才用成对字段宏，完整规则见[接口参考](DVS接口与进阶用法.md#规划字段与完整示例)。

开启规划后，同一次请求先用完整资料安排本轮，再依据已定规划和筛选条件选择资料。正文收到规划 YAML 和执行指令，按四部分展开行动与对话、遵守事实限制，在指定位置收束；若规划与玩家明确要求、已发生剧情或原设定冲突，应修正冲突部分。输入增强不写正文，也不把计划当成已经发生的事实。

如果使用 EJS 自定义排版，普通模板可能执行两次：第一次给输入增强看完整数据，第二次给正文看筛选后的数据。`dvs_state` 始终查询正文起点的数据库，按组读取筛选行则用 `dvs_narrative.rows()`。原生宏和显式预处理不会因这两个阶段重复执行；普通 EJS 中写变量、发命令等副作用仍由作者控制。需要只在正文执行时用 `runType === 'generate'` 判断，完整写法见[筛选与 EJS 参考](DVS接口与进阶用法.md#世界书与表格筛选)。只使用上面的宏例子无需处理这些模板接口。

### 查看、重用与重做

输入增强需要请求且用户消息原本没有胶囊时，先在末尾保存 records 为空的 `<DVSData type="user">…</DVSData>`。已有记录或损坏标签保留到新成果成功保存，成功后才替换为各扩展记录和可选分析；在酒馆的消息编辑框里能看到它。聊天中显示默认收起的“输入增强”胶囊，正常摘要类似“屏蔽 2 · 1 张表 · 已规划”，分别表示屏蔽条目数、筛选涉及的表数、是否带剧情规划。表筛选只保存各组保留行的业务键，不保存完整表快照。旧 `<DVSInputInject>` 继续兼容；没有标签的历史消息不批量补写。

| 胶囊上显示 | 含义 |
| --- | --- |
| 生成中 | 正在准备、请求或保存输入增强，暂时隐藏结果区；成功后显示新结果，失败或取消后恢复原记录。重新生成正文复用合法记录时不显示生成中 |
| 未使用（灰色） | records 为空，没有已保存成果；下一次主动生成仍按已开启功能判断是否需要请求，失败弹窗中的“清除并继续”只跳过当前这轮 |
| 出错（红色） | 标签为空且本次会话中请求失败，展开可看失败原因；刷新页面后回到“未使用” |
| 数据异常（琥珀色） | 记录无法读取，展开后显示失败信息和错误详情 |

展开后直接排列各已启用扩展的内容，各自保留内部折叠，不额外添加扩展外层标题：

| 分区 | 默认 | 内容 |
| --- | --- | --- |
| 剧情思维链、世界书优化、变量优化的分析 | 收起 | 模型可选的简短检查摘要，仅非空时显示；不进入正文，也不是判断成功的依据。旧版共同筛选分析只显示一次 |
| 屏蔽条目 | 展开 | 被筛掉的世界书条目名。点条目旁的小眼睛打开只读预览，显示该条目的启用状态、关键词、插入位置和内容。预览读取世界书现在的内容，不是屏蔽时的快照；条目改过名、已被删除或世界书不存在时会提示。按 Esc、点 × 或点弹窗外部关闭 |
| 有效数据 | 展开 | 从这条用户消息之前的有效 AI 楼层读取数据，按保存的筛选名单取行。每张表默认折叠，只显示“表名 · N 条记录 · M 列”，点开才显示明细；「行列翻转」把每个字段排成一行，只有一条记录的表默认已翻转。同一表有多组筛选时显示各组保留行的并集 |
| 剧情规划 | 展开 | 默认按“本轮方向”“情节步骤”“事实与边界”“结束位置”及作者自定义字段分块显示，右上角可切换为 YAML |

只有最新一条用户输入（跳过 `/hide` 隐藏的消息）在展开后显示「重新生成」和「清除」，更早的消息标为“历史记录 · 只读”；生成或变量更新进行中按钮不可用。重新生成需要开启适用输入增强扩展。消息重绘时可能保留原面板；面板重建或刷新页面后默认收起。

| 操作 | 结果 |
| --- | --- |
| 重新生成正文或生成新 swipe | 所需成果完整时，复用记录并重新读取本轮准备数据。没有标签、记录为空或缺少成果（包括本次需要的筛选组）时，自动重做适用的整组任务 |
| 修改世界书，出现新候选 | 复用时新候选默认保留；要按新规则重新判断，点「重新生成」 |
| 修改物品数量 | 复用业务键选择，正文使用重新准备的数量；面板展开时按该用户楼层之前的数据读取，不重复保存完整表数据 |
| 点击输入增强顶部「重新生成」 | 重做适用的整组任务，先保存已完成的规划和筛选。若命中拦截，玩家确认后保存交互结果，再调用卡片的正文资料回调。即使回调报错，确认结果仍在。此次操作不生成正文 |
| 点击拦截项「继续交互」或「重新调整」 | 只重开该组件。确认保存后才生成或重新生成正文，取消保留同项原先确认的结果。详见[生成拦截操作对照](DVS接口与进阶用法.md#生成拦截) |
| 点击「清除」 | 头部变为“确认清除这条记录？”，点「确认清除」后清空 records、analyses 和摘要，保留标签，用户原文不变；8 秒内不确认自动撤回。功能开关不变，下次生成仍按所需成果决定是否请求 |
| 开关由仅筛选改为筛选加规划 | 旧记录没有规划时，重新生成正文会自动重新请求；关闭剧情则保留旧规划但不再使用 |

修改用户原文、条件或规划规则后，应点「重新生成」，普通重新生成正文不会刷新选择。新增物品不会自动加入旧选择，已选物品不在当前准备数据中会略过。脚本也可调用 `await DVS.reInject()`，效果与「重新生成」相同；准确前提见[接口参考](DVS接口与进阶用法.md#输入增强接口)。

输入增强处理中可以使用酒馆停止按钮。自动生成正文时，如果模型请求重试全部失败，或旧记录损坏（例如格式不符、已保存的业务键无效），DVS 会暂停正文生成，让玩家选择下一步。

| 选项 | 结果 |
| --- | --- |
| 重新生成输入增强 | 再请求一次，成功后继续生成正文；失败时原记录不变，仍停在弹窗中可再选 |
| 清除并继续 | 清空标签，正文不筛选资料、不带剧情规划直接生成 |
| 取消正文生成 | 停止本次生成，记录保持原样，可稍后在面板中处理；按 Esc 关闭弹窗也按取消处理 |

弹窗不提供关闭功能的选项；要停用输入增强，在“功能配置”关闭相应优化和剧情规划。模板、记录保存等失败直接停止。停止不撤回已加入的用户消息，也不保证远端已停止计费。正文后端与 EJS 的支持范围见[正文注入参考](DVS接口与进阶用法.md#正文数据注入)。


## 可选：检查主世界书版本

玩家更新角色卡后，当前关联的主世界书可能仍是旧版。作者可在卡片元信息中填写版本，并在主世界书中放置唯一、名称精确为 `[DVS:版本]` 的条目，内容只写版本，例如 `0.2.0`；该条目可以禁用。这里的卡片／世界书内容版本与 DDL 迁移版本各自维护。

需要此功能时，在卡内另放一个独立酒馆助手脚本，启动时调用一次：

```js
await waitGlobalInitialized('DVS');
await DVS.lorebookVersionCheck({ onExpired: 'WARNING_MESSAGE' });
```

`WARNING_MESSAGE` 在主书版本落后时，提示玩家先保留修改，再从角色卡重新导入并关联。要自动更新，显式改成 `'AUTO_UPDATE'`。发现旧版时，玩家可在确认框查看书名、主书版本和卡片版本。取消则结束；点击“备份并更新”，DVS 会把玩家现用的书另存为备份，收到酒馆的成功回复后，用卡内新版覆盖原书。角色继续使用同一个书名。成功框会显示新版和备份名，玩家可从备份取回修改。

该脚本不需要 DVS 功能开关或业务注册，也不保证先于变量注册脚本运行；版本检查不会暂停注册。更新成功后点击“刷新页面”，新版和卡片脚本才重新加载。按 Esc 或关闭成功框不会刷新。备份失败时，DVS 停在覆盖之前，请手动备份后重新导入卡内世界书。版本格式、读取范围和更新失败的处理见[接口参考](DVS接口与进阶用法.md#主世界书版本检查)。

## 旧版 DVS 卡片升级

旧配置与旧标签仍兼容。只整理旧卡的 `index.yaml` 时，用随包工具转换，核对条目和默认配置的差异后即可交付。准备分发新版卡时，再按原工程方式生成并核对导入包。步骤见[旧卡转换指南](场景/旧卡转换.md)。

## 按需继续

日常卡片接入完成后，仅在自己的规则确实需要时再读进阶内容：

- [查询、修改与逻辑事务](DVS接口与进阶用法.md#修改与逻辑事务)：用脚本修改当前层，保留历史版本。

- [可选模板查询](DVS接口与进阶用法.md#正文数据注入)：使用 ST-Prompt-Template 的只读 `dvs_state`，不用它也可以继续使用 DVS 宏。

### 预处理表数据

需要隐藏或替换提示词字段时，用只处理副本并保护业务键的 `DVS.table()`，见[完整用法](DVS接口与进阶用法.md#预处理表数据)。

### 虚拟表输入与写库前计算

虚拟表每次请求从空集合开始，计算后必须从 `preUpdate` 返回值中删除；最小卡无需声明。见[完整用法](DVS接口与进阶用法.md#虚拟表输入与写库前计算)。
