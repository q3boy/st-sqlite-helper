# 安装引导脚本

角色卡依赖酒馆sqlite助手时，作者可以随卡附带一个独立的酒馆助手脚本。玩家加载脚本后，它检查插件是否安装；缺少插件时先征求玩家同意，再优先从 [GitHub 正式仓库](https://github.com/q3boy/st-sqlite-helper)安装，失败后自动尝试 [Gitee 备用仓库](https://gitee.com/q3boy/st-sqlite-helper.git)。已经安装并启用正式 Git 版时，脚本自动检查更新，有更新则征求玩家同意后更新。玩家必须先安装并启用[酒馆助手 JS-Slash-Runner](https://github.com/N0VI028/JS-Slash-Runner)。

引导不依赖预先安装 SQLite Helper 或 DVS。JSON 和 import JS 都通过 CDN 加载完整引导脚本，因此运行时需要联网；它是可选附带内容，不负责业务注册或数据库初始化。

## 下载与选择

从正式仓库取得以下一种文件：

| 接入方式 | 下载文件 |
| --- | --- |
| 在酒馆助手界面导入 | [sqlite-helper-install.json](https://raw.githubusercontent.com/q3boy/st-sqlite-helper/master/installer/sqlite-helper-install.json) |
| 使用 tavern_sync 打包角色卡 | [sqlite-helper-install-import.js](https://testingcf.jsdelivr.net/gh/q3boy/st-sqlite-helper@master/installer/sqlite-helper-install-import.js) |
| 查看完整实现或自行保留本地副本 | [install-rt-v3.js](https://raw.githubusercontent.com/q3boy/st-sqlite-helper/master/installer/install-rt-v3.js) |

JSON 与 JS 是两种替代方式，同一张卡只保留一个安装引导脚本。安装引导与原有 Helper／DVS 业务脚本分别保留；业务脚本继续按原有方式等待接口并注册，不要把引导代码放进等待插件的业务脚本中。

JSON 的 `content` 和 import JS 都只有下面这一行，也可以直接填进酒馆助手脚本编辑器：

```js
import 'https://testingcf.jsdelivr.net/gh/q3boy/st-sqlite-helper@master/installer/install-rt-v3.js';
```

该地址跟随正式仓库 `master`。引导脚本发布新内容后，后续重新加载脚本会在 CDN 缓存更新后取得它，不需要重新导入 JSON 或重新打包角色卡；已经运行的脚本不会自行替换或重复执行。CDN 不可用时引导无法加载，可稍后重试或通过扩展管理手动安装、更新。自行嵌入完整实现的副本不会随远端自动更新。

已经导入旧 `install-rt.js` 或 `install-rt-v2.js` 地址的脚本仍可使用，这两个地址保留相同实现，但仍需等待旧地址的 CDN 缓存更新。需要立即避开旧运行脚本缓存时，将脚本内容替换为上面的 `install-rt-v3.js` 导入语句，再重新加载脚本。JSON 和 import JS 下载地址本身也可能缓存旧内容，直接复制上面的新导入语句可避免这一层影响。

## 在酒馆助手中导入 JSON

1. 下载 `sqlite-helper-install.json`。
2. 在酒馆助手中将它导入到该角色的脚本范围。
3. 打开角色脚本范围的总开关，并手动启用导入后的“酒馆sqlite助手安装引导”，确认角色中只保留一个副本，再按酒馆助手原生方式随角色卡导出。

已核对的酒馆助手原生单脚本导入会重新分配脚本 ID，并将脚本设为停用，因此导入后需要手动启用。发行文件使用固定 ID `01a15a6c-8e86-70c4-9fce-c9729b904c2b`；原生导入后以实际生成的 ID 为准。

## 使用 tavern_sync 打包 JS

下载 `sqlite-helper-install-import.js` 到角色卡的脚本目录，在现有角色卡 YAML 的 `扩展字段.酒馆助手.脚本库` 中加入以下条目：

```yaml
扩展字段:
  酒馆助手:
    脚本库:
      - 名称: 酒馆sqlite助手安装引导
        id: 01a15a6c-8e86-70c4-9fce-c9729b904c2b
        启用: true
        类型: 脚本
        文件: 脚本/sqlite-helper-install-import.js
        数据: {}
        按钮:
          启用: false
          按钮列表: []
```

`文件` 指向实际下载的本地 JS，路径按你的角色卡目录调整。已有 `扩展字段`、`酒馆助手` 或 `脚本库` 时合入现有结构，不重复创建同名 YAML 键。显式保留上述 `id`，它由 YAML 提供，JS 不会自行生成脚本 ID。安装引导不需要设置 `dvs_enable`。

使用你已有的 tavern_sync `bundle <配置名>` 流程，将这一行 import 嵌入角色卡后再分发。

## 玩家会看到什么

| 当前情况 | 脚本的行为 |
| --- | --- |
| 正式 Git 版已安装且启用 | 自动检查当前分支是否有新提交；已是最新时安静结束，有更新时点击“更新插件”才执行 |
| 本地挂载版已安装且启用 | 结束本次检查，不进行 Git 更新 |
| 全局安装有更新，但当前账号不是管理员 | 提示联系酒馆管理员更新，不发起更新请求 |
| 已安装但停用 | 提示在扩展管理中启用指定扩展，再刷新页面；不代为启用 |
| 已安装，当前页面尚未识别 | 提示刷新页面，不重复安装 |
| 确认缺少插件 | 显示两个仓库、回退顺序、安装范围及刷新说明；点击“安装插件”后先尝试 GitHub，失败再尝试 Gitee |
| 取消、关闭提示或按 Esc | 结束本次执行；下次脚本加载时重新检查 |
| 安装或更新成功 | 再次询问是否刷新；选择“稍后刷新”会保留已安装或更新的文件，稍后手动刷新即可 |
| 两个安装地址都失败 | 一次显示 GitHub 和 Gitee 各自的错误及手动安装地址，结束本次执行 |
| 检查或更新失败 | 显示实际错误及手动处理说明，结束本次执行，不自动重试 |

脚本入口先检查全部必需接口，缺失时一次列出所有缺失项，提示更新酒馆或酒馆助手并检查是否加载成功，然后结束；不会继续查询安装状态或执行安装、更新、刷新。原生弹框不可用时使用浏览器提示框。

脚本每次加载只检查一次，不定时检查；检查失败时不会将插件当作未安装或已经最新。更新检查使用酒馆原生 Git 能力，不比较版本号，也不要求额外的版本文件。识别到安装不表示数据库服务或 DVS 已就绪，业务脚本仍需等待相应接口。

管理员确认安装时供酒馆全部账号使用，其他账号仅为当前账号安装，实际范围会在确认框中说明。两个安装地址使用相同范围，各自最多尝试一次，切换到 Gitee 无须再次确认。通过 Gitee 安装后，原生更新沿用 Gitee 仓库。安装成功只表示原生安装请求成功，插件需刷新页面后生效；刷新失败时按提示手动刷新，无需重复安装。

安装后按[使用与维护指南](../sqlite-helper/指南/使用与维护指南.md#安装后的首次使用)完成存储与服务设置。更新期间不要加载或刷新页面，更新成功后再刷新所有相关页面；也可以随时使用[原生扩展更新流程](../sqlite-helper/指南/使用与维护指南.md#更新步骤)。
