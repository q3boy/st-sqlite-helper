# 使用与维护指南

本文说明怎样安装和更新插件、选择存储模式、查看与清理数据，以及遇到故障时怎样处理。玩家、脚本作者和卡片作者的阅读路径见[使用导航](../../使用/README.md)，脚本调用见[业务侧使用指南](业务侧使用指南.md)。

## 安装与更新

酒馆sqlite助手（SQLite Helper）是酒馆前端扩展，必须安装并启用[酒馆助手 JS-Slash-Runner](https://github.com/N0VI028/JS-Slash-Runner)。

正式安装地址为 [q3boy/st-sqlite-helper](https://github.com/q3boy/st-sqlite-helper)。安装前确认该仓库根目录包含 `manifest.json` 的完整扩展包；只有项目介绍时不能安装。在酒馆扩展管理的安装入口填写此仓库地址；无需克隆开发仓库或运行构建命令。

卡片作者可随卡附带[安装引导脚本](../../使用/安装引导脚本.md)，让缺少插件的玩家确认安装；支持 JSON 导入和 JS 打包两种方式。

仅使用 SQLite Helper 或普通 DVS 宏不要求安装提示词模板。使用 EJS／`dvs_state` 模板查询时才需要安装并启用 ST-Prompt-Template，具体写法见[DVS 作者手册](../../dvs/指南/DVS作者使用手册.md)。

- 扩展在酒馆主页面建立服务，通过助手发布 `SqliteHelper`，同时挂载管理栏和查看器。
- 业务脚本继续使用 `waitGlobalInitialized('SqliteHelper')`。
- 无需另装 SQLite 助手服务脚本。

当前源码配套公共 API 29、通信协议 23、管理结构 6。页面与执行 SQL、读写文件的 SharedWorker 版本不配套时，业务收到 `SYS_VERSION`。此时须更新同一次完整构建，再刷新页面。

### 浏览器要求

| 能力 | 用途 |
| --- | --- |
| 安全上下文、SharedWorker | 必需 |
| OPFS 异步文件读写 | 游玩模式需要 |
| `showDirectoryPicker` | 开发模式选择目录时需要 |

缺少能力时界面明确提示，业务收到 `SYS_UNSUPPORTED`，插件不会静默换模式。

不同浏览器、浏览器配置或来源不能并发使用同一开发目录。多 Tab 协调只覆盖同一配置、同一来源。

### 安装后的首次使用

1. 安装完整扩展后刷新酒馆页面，同一酒馆只启用一个 SQLite Helper 版本。
2. 在扩展设置展开“SQLite Helper”，确认“启用 SQLite 服务”已开启。新配置默认开启，若先前关闭过，重新开启后需刷新。
3. 选择游玩模式或开发模式，按下文完成存储准备。换扩展目录不会隔离数据库。
4. 需要 DVS 自动更新变量时，按[DVS 模型配置](../../dvs/指南/DVS作者使用手册.md#配置变量模型)填写参数。独立 Helper 脚本不需要配置变量模型。

### 更新步骤

1. 阅读更新说明，保留重要数据的现有备份；插件尚不提供完整备份恢复，导出角色卡或聊天不等于备份 SQLite 数据。
2. 等待本轮修改完成并核对保存提示，再关闭服务，确认 Worker 已退出。设置保存成功不等于 Worker 已退出。关闭受阻时先处理界面显示的原因。
3. 完整包发布后，通过酒馆扩展管理更新正式扩展。不要混用不同构建的页面、Worker、资源或类型声明；更新期间不要加载或刷新，全部更新完成后再刷新所有相关页面。
4. 在“高级选项”核对页面和 Worker 构建一致，按需要重新开启服务并刷新。

旧 Worker 若因旧退出规则受阻，更新资源不会改变它。处理顺序：

1. 停止在线升级。
2. 结束旧连接会话，确认实例结束。
3. 加载新版。

不要另开 Worker 并行写同一目录。

## 启用服务与授权目录

### 存储模式

| 模式 | 数据位置 | 授权 |
| --- | --- | --- |
| 游玩模式（默认） | 当前浏览器、当前酒馆站点的 OPFS | 无需选择或授权目录 |
| 开发模式 | 本地授权目录，面向角色卡和脚本开发 | 显示本地目录和默认勾选的“自动重新加载” |

- 模式和这两个选择保存到酒馆原生设置。
- 切换模式不自动迁移数据，两种模式的数据各自保留。
- 浏览器或站点变更也不会自动搬运数据。

### 启用或关闭服务

在酒馆扩展设置中展开“SQLite Helper”。“启用 SQLite 服务”保存到酒馆扩展设置。

| 操作 | 结果 |
| --- | --- |
| 开启 | 刷新本页面才启动服务，旧页面和旧代理不会自动恢复 |
| 关闭 | 停止接收新调用；已接收 SQL 和已开始的文件写入结束后退出 Worker；尚未开始的后台保存取消，未落盘修改可能丢失 |
| 关闭时工作仍在执行或保存 | 界面说明原因并保留 Worker；关闭受阻不能解释为写入已取消 |

其他 Tab 每 10 秒读取设置，已接受这段生效时间差。

### 授权开发目录

- 点击“管理目录…”查看目录及可用状态。
- 首次选择建议使用专用空目录。
- 原目录失去权限时，点击“重新授权”并允许访问原目录。
- 浏览器限制的目录选择和权限确认须由用户亲自完成，代理不能代点或绕过。
- 插件还会核对权限和实际读写，浏览器允许访问不等于数据可用。

### 缺少授权时业务调用怎样处理

| 场景 | 行为 |
| --- | --- |
| 仅开发模式缺少目录或权限 | 业务调用等待用户授权，默认每次 120 秒。等待期间不执行 SQL，也不开始计算写入发送前的等待时间 |
| 授权取消、拒绝、失败或超时 | 结束这次调用。后来授权成功不会恢复已结束的调用 |
| 打开聊天时的后台编号检查 | 缺权限时不自动弹窗 |
| 游玩模式存储不可用 | 直接报告原因，不引导目录授权 |

### 切换目录

- 切换目录会改用新目录的数据，原文件保留，不自动复制。
- 插件等待本页面已接收 SQL 及已开始的文件保存结束，并取消旧实例未开始的后台保存。
- 切换错误未处理时，不报告切换成功。
- 旧代理不能转投新目录，业务须重新取得代理。

授权等待的业务行为见[公共接口契约](../契约/公共接口契约.md#未授权时的调用)。

## 查看数据与调试

### 外部修改后重新加载

开发模式下，用外部 SQLite 工具保存修改后，可选择全局、当前角色或当前聊天点击“重新加载”。

| 方式 | 触发条件 |
| --- | --- |
| 自动加载 | 每 2 秒检查已打开的库，mtime 变新或大小改变时加载 |
| 手动加载 | mtime 未变新且大小相同的修改，只能手动加载 |

- 普通查询不改变文件基准，插件自身保存会更新基准。
- 手动加载，或实际检测到外部变化后的重载，会丢弃尚未保存的内存修改。
- 未加载的库不因自动检测而打开。
- 开发者自行控制外部修改时机，先确认实际文件已经取得所需修改。业务 Promise 只确认当前内存事务提交，不确认文件保存，见[保存契约](../契约/数据库与保存契约.md#事务和保存)。

### SQLite 数据库查看器

从酒馆菜单打开“SQLite 数据库查看”，查看已有全局、当前角色、当前聊天数据库和文件信息。

- 查看器只读：不补编号、不建库、不升级管理结构。
- 从未初始化时显示“尚未初始化”。
- 同一 Worker 首次内存提交后可以查看表数据，此时文件尚未创建，文件信息会明确说明“未创建”，不伪造保存时间或大小。新的 Worker 只按文件和登记事实判断。
- 表过大或整数不能准确表示时拒绝预览，不返回截断或舍入的数据。

切换角色或聊天会关闭查看器，重新打开才读取新对象。旧响应不会更新已关闭窗口。

表列表默认只显示业务表。查看系统表：

1. 在“全局”页表列表末尾勾选“显示系统表”。
2. 页面显示插件内部普通表及 SQLite 内部表，名称前带 ⚙️ 前缀，实际表名和 SQL 不变。

补充说明：

- 收起表列表时复选框也隐藏，重新展开可操作。
- 重新打开查看器恢复默认。
- 角色和聊天页始终隐藏系统表。
- 勾选不修改数据，也不保存设置。

### 业务调试记录

“启用业务调试记录”控制 SQL、通信记录及右下角“调试”面板。

- 关闭会清空记录，重新开启不补历史。
- 记录容量有限，不能作为完整业务账本。
- 开关不改变 SQL 结果。
- 正式版默认关闭业务调试，仍可手动开启；内部诊断面板不显示。
- 调试入口和已打开的调试面板与原生输入区横向重叠时，会移到输入区上方，避免遮挡发送／停止按钮；输入区高度变化时跟随调整，宽屏互不重叠时仍在右下角。

业务调试只用于观察，不代替写入结果或文件保存确认。

## 扫描与修复

删除角色或聊天后，存储目录里可能留下用不到的数据库、空目录或管理记录。“扫描与修复”先只读检查并列出一张表，你核对后点“执行”查看逐步清单，再点“确认执行”才会处理。

### 扫描

1. 先停止生成，关闭其他酒馆标签页。处理期间不要在酒馆中删除、改名或导入角色和聊天。
2. 在独立“数据清理”区点击“扫描与修复…”，再点击“开始扫描”。服务须启用且当前存储可用，开发模式还需目录授权。

扫描只读取当前模式的存储目录、管理记录和必要的酒馆列表，不修改任何数据。

### 读懂结果表

每一行是一个必须一起处理的最小单元，例如一个无用文件、一个空目录（含其中的空子目录），或已删除角色和它下面的聊天库。表按“自动、默认选中、默认不选中、仅报告”的顺序排列：

| 列 | 内容 |
| --- | --- |
| 执行 | “自动”表示执行时一定处理，不能单独取消；复选框是可选项，初始勾选与否由系统建议；“—”表示仅报告 |
| 操作 | 清理或报告 |
| 类型 | 系统库、角色库、聊天库、文件或其它（如空目录） |
| 对象 | 角色名或聊天名、角色卡和聊天文件名，以及将处理的文件、目录和管理表记录（如 `__stsh_roles.role_id=3`）。编号缩写显示，鼠标停留可看完整内容 |
| 说明 | 为什么出现；有需要注意的影响时另起一行写出，例如“保留聊天的数据会和角色一起删除” |

执行时会处理的行（自动和已勾选的）带有醒目底色和左侧色条。误改勾选后可点“恢复默认”回到系统建议的选择。正常的角色、聊天和数据库文件只显示数量。

| 常见行 | 默认 |
| --- | --- |
| 没有登记的文件、空目录；酒馆中已删除聊天留下的数据库；只剩管理记录的对象 | 自动 |
| 角色卡已删除，且其下没有聊天数据库 | 勾选 |
| 角色卡已删除但仍有保留的聊天数据库（整组处理）；没有对应记录的初始化登记 | 不勾选 |
| 数据库内的系统结构问题、登记已建库但文件缺失、无法核对的项目 | 仅报告 |

没有管理登记的数据库也算没有依据的文件，会被自动清理；需要保留时先下载备份，或手工复制整个目录。浏览器写文件时的临时文件（`.crswap`）不列出、不删除。

管理库（`global.sqlite`）本身结构异常或无法读取时，表中只列出管理库的问题，没有可执行的项目：其他文件属于哪个角色或聊天要靠管理库判断。结构问题目前只报告、不自动修复；管理库恢复正常后重新扫描，才会列出清理项目。

### 下载备份

“下载备份”把自动和当前勾选的行将删除的原 SQLite 文件打成一个 zip，保留相对路径；会修改管理记录时包含原 `global.sqlite`。`global.sqlite` 中可能有 DVS 模型配置的 API 密钥，请妥善保管备份文件。下载不是执行的前提，也不改变选择。

### 执行

1. 点击“执行”：先在表下方列出将按顺序进行的每一步，这时还没有修改任何数据，可以“复制清单”。
2. 核对后点击“确认执行”才开始处理；点击“返回修改”或改变勾选会收起清单，需要重新点击“执行”。

项目逐项处理，清单中每一步、表中每一行都显示实际结果。处理前会再核对原记录、目录配置和共享引用，扫描后发生变化的项目会跳过。清理只涉及清单内的管理记录、存储目录中的数据库文件和其他没有登记的文件、空目录，不修改角色卡或酒馆聊天文件。

| 操作或情况 | 结果 |
| --- | --- |
| “停止扫描”或关闭窗口 | 已经开始的读取会结束，然后停止；结果标注为不完整 |
| “停止执行” | 已提交的一项照常结束，不再提交下一项。停止不能撤销已完成的删除 |
| 某项失败或被跳过 | 只影响该项，失败项仍可再次执行，或重新扫描核对 |
| 整组中角色库删除失败 | 角色已在管理记录中标为删除、其下聊天改为保留，这一修改不撤销；聊天库和记录保留，重新扫描后可再处理 |

扫描不保证所有结果来自同一瞬间，也不在后台定时扫描。

## 文件、升级与备份

数据库保存在 OPFS 专用 `st-sqlite-helper` 子目录或开发模式授权目录中，内部布局相同。路径由角色编号 `char_dbid` 和聊天编号 `chat_dbid` 决定；它们不是楼层或分支编号：

| 数据范围 | 文件 |
| --- | --- |
| 全局 | `global.sqlite` |
| 角色 | `characters/<char_dbid>/char.sqlite` |
| 聊天 | `characters/<char_dbid>/chats/<chat_dbid>.sqlite` |

不要这样做：

- 手动改编号，或移动文件来让旧代理匹配新对象。
- 让外部程序与 Worker 同时修改文件。

相关行为：

- 角色编号只认当前存储 `global.sqlite` 中“角色卡文件名 → 编号”的登记。插件不读取、不写入、不清除角色卡上的编号字段，卡片上已有的旧字段被忽略。
- 使用酒馆“替换／更新”导入新版卡后，只要文件名不变，就继续使用该存储中原有的登记和数据，卡片带什么编号都不影响。
- 酒馆复制角色得到新文件名，就是新角色，首次使用时独立登记，不复制原角色的数据库。
- 首次写入或打开聊天时的后台准备才会为没有登记的角色建立编号，建立前先确认角色文件仍在酒馆角色列表中；普通 `getHandles`、查询和查看器遇到没有登记的角色，只读查找不到编号，按数据库尚未初始化处理（`getHandles` 中的角色句柄为 null），不分配编号。
- OPFS 与本地目录各自登记，同一张卡可能使用不同的角色编号，切回原存储继续使用该存储中的原登记。
- 插件未运行时在酒馆内改名的角色，无法与原登记关联：新名字按新角色处理，原名字下的数据保留，交给扫描。
- 聊天编号保存在聊天文件中；聊天分支可以共享编号，分支隔离由业务处理。
- 聊天复制后的独立身份、导入聊天所带编号的处理，以及停用期间或酒馆外产生的聊天副本识别尚未提供。不能把复制、导入当作数据库迁移或隔离办法。
- 开发模式中需要外部修改文件时，由开发者控制时机：先确认文件已经取得所需修改，再修改并保存，最后重新加载。
- 正常关闭不会强制保存所有内存修改。

### 管理结构

- 当前全局管理结构为版本 6，使用 `__stsh_` 前缀，维护 meta、roles、chats、targets 四张表。
- 版本只表示插件管理结构。
- 它不保存完整名字历史、每次 SQL 指纹，也不保存改名、删除、清理的完整过程任务。

当前不提供旧版管理结构或目标库内部信息转换。只支持使用当前结构创建的数据。已有结构不完整或版本不支持时明确报错，不补造记录。

### 回退与备份

- 回退需要匹配的旧文件和旧构建，旧代码不能写新结构。
- 完整备份恢复尚未实现。临时文件备份不等于产品恢复能力，复制角色卡或导入聊天也不自动恢复对应数据库。

## 遇到故障时

1. 先看主提示，再展开“查看详细原因”。
2. “高级选项”提供版本、重新连接和安全重启。
3. 先检查目录、权限和配套版本。
4. 不要直接重做未确认写入，也不要删除数据库消除错误。

| 情况 | 处理及影响 |
| --- | --- |
| 业务接口发布失败 | 确认酒馆助手启用且支持 `initializeGlobal`，核对版本后刷新；控制台和诊断保留原因。接口发布失败不能作为数据库可用依据 |
| 服务停用 | 开启并刷新相关页面；旧代理不恢复，已接收写入不因此取消 |
| 原目录需要授权 | 重新授权原目录，继续使用原文件；不要静默换目录 |
| 目录可访问但数据不可用 | 检查读取、保存错误和空间；不能推断文件完整或自动建新库 |
| 页面与 Worker 版本不一致 | 更新完整配套构建并刷新；安全重启受阻先处理具体原因，不开第二个 Worker |
| 数据库尚未初始化 | 由业务执行必要首次写入；查询和查看器不会建库 |
| 原文件缺失 | 核对原目录和备份，保留错误信息；插件拒绝自动重建 |
| 后台保存失败 | 查看文件结果和内存是否仍可用，检查权限、磁盘空间及诊断；不要重发已经提交的 SQL，关闭或重载可能丢失未保存修改 |
| 提示 SQL 内存已提交但调用未完成 | 不重复提交，保留详细信息，停止依赖正常返回结果的后续流程 |
| 提示 SQL 已保存但调用未完成 | 保留详细信息，停止依赖正常返回结果的后续流程，不再次提交已保存 SQL；普通调用没有操作 ID |
| 改名或删除尚未确认 | 保留原对象和错误信息，按具体原因核对；不按当前选择猜目标，相关新调用受阻不表示原 SQL 已取消 |

重新连接只为后续调用准备，不重发已经发送的 SQL。写入执行结果未知时，保留输入并核对当前业务数据，不直接重做或补偿。

公共错误含义见[错误说明](错误说明.md)。删除角色后，酒馆可能仍保留聊天文件；插件的数据清理不负责删除这些酒馆文件。
