# 业务侧使用指南

酒馆助手业务脚本通过全局 `SqliteHelper` 操作全局、角色和单人聊天数据库。先运行[完整笔记示例](../assets/helper-notes/README.md)，再按本文将它改为自己的业务。安装、存储模式和授权见[使用与维护指南](helper-usage.md)。DVS 卡片作者另从[最小角色卡](../assets/dvs-minimal-card/README.md)开始。

## 运行笔记示例

1. 安装并启用酒馆助手和 SQLite 前端扩展，启用 SQLite 服务后刷新页面。当前正式仓库的安装状态见[安装与更新](helper-usage.md#安装与更新)。
2. 打开专用单人聊天，确认当前存储可用；开发模式先完成目录授权。
3. 按[示例说明](../assets/helper-notes/README.md)在酒馆助手脚本中运行 `notes.js`。从该源文件依次阅读等待入口、获取聊天代理、建表、参数绑定写入、查询和错误处理。
4. 重复运行，确认固定 `noteId` 的记录被更新，未新增重复记录。再按示例说明核对错误路径和保存结果。

示例实现只在 `notes.js` 维护。它使用业务表，插件不会预先替业务建立表结构。`waitGlobalInitialized` 属于酒馆助手：等待完成后读取全局 `SqliteHelper`，不要把等待函数的返回值当作数据库对象。不需要另装 SQLite 服务脚本，也不需要 import 运行时 SDK。

## 选择数据库并固定目标

| 属性 | 操作范围 | 没有有效对象时 |
| --- | --- | --- |
| `SqliteHelper.root` | 当前存储空间的全局数据 | 返回代理，调用仍可能因未初始化失败 |
| `SqliteHelper.char` | 取得属性时角色的共享数据 | 无有效角色或处于群聊时返回 `null` |
| `SqliteHelper.chat` | 取得属性时的单人聊天数据 | 无有效聊天或处于群聊时返回 `null` |

例如在聊天 A 取得 `const db = SqliteHelper.chat`，用户后来切到 B，`db` 仍操作 A。业务需要处理 B 时重新读取属性。解构同样固定目标，不会自动跟随界面。异步结果返回时，业务还需确认是否可以更新当前界面，不能把 A 的结果显示到 B。

取得代理不会建库。未初始化目标的查询返回 `DB_UNINITIALIZED`，业务可显示空状态，或在确实需要时首次写入。首次写入提交后即可查询当前内存，文件稍后创建。已有文件丢失时插件拒绝重建，不用空库替代原数据。

角色改名后，改名前已执行过调用的代理继续操作原库；改名前取得但从未调用的代理只记住了旧文件名，查询报 `DB_UNINITIALIZED`，写入报 `DB_UNAVAILABLE`，不会在旧名字下建库，重新取得代理即可。

切换存储模式或开发目录后，旧代理不能转写新目录，调用返回 `DB_UNAVAILABLE`。取得新代理也不会迁移数据。尚未保存且已离开当前上下文的聊天，可能无法确认原目标而拒绝调用。完整目标规则见[公共接口契约](helper-api.md)。

## 选择方法和绑定参数

| 方法 | 用途 |
| --- | --- |
| `query(sql, binds?)` | 一条 `SELECT`，返回列名和二维行数组 |
| `update(sql, binds?)` | 一条 `INSERT`、`UPDATE`、`DELETE` 或 `REPLACE` |
| `exec(sql)` | 一条或多条 `CREATE`、`ALTER`、`DROP` |
| `transaction(commands)` | 命令数组共同提交或回滚，每项可附参数 |
| `runSql(sqlOrArray)` | 可信作者的直接 SQL 入口，无 binds 参数 |
| `debounce(millisecondsOrFalse)` | 调整此代理后续写入的发送等待，同步返回代理 |

笔记示例使用固定业务键和 UPSERT，使重复执行有明确含义。Helper 本身不保存每次 SQL 的去重记录，同样的 SQL 再次提交会再次执行。

用户文本使用绑定参数，不能直接拼接进 SQL。位置参数传数组，命名参数传保留 `:`、`@` 或 `$` 前缀的对象。JSON 数组和对象可作为单个绑定值，读取时得到 JSON 文本；BLOB 使用 `Uint8Array`。顶层布尔值须转为 `0/1`。完整类型、输入限制和返回结构见[数据库与保存契约](helper-sql.md)。编辑器使用扩展包的 `types/sqlite-helper.d.ts`，不要另写一份接口声明。

普通方法按 SQL 首关键字检查，不接受追加语句、`WITH`、`PRAGMA` 或显式事务控制；`exec` 可以包含多条 DDL。`runSql` 不做这类前缀和单语句限制，但仍通过固定目标、服务事务和后台保存执行。不要在其中手写 `BEGIN/COMMIT`，也不能破坏 `__stsh_` 内部对象。具体边界见[SQL 方法](helper-sql.md#sql-方法)。

## 决定哪些修改必须共同成功

例如“扣除金币”和“增加物品”必须同时成功时，使用一次 `transaction`，把两条带参数的命令放入同一数组。后面的命令失败且回滚成功时，整次调用不生效。两次独立 `update` 是两个事务，第二次失败不会撤销第一次；`Promise.all` 也不能代替事务。

两次调用存在先后依赖时，先 `await` 前一次，再提交或查询下一次。调用 `debounce(false)` 仅关闭这个代理后续写入的发送等待，不会提交其他代理正在等待的修改。默认写入等待及消息合并规则见[公共接口契约](helper-api.md#公开操作与防抖)。

### UI 增量修改与 AI 结果的先后顺序

例如用户连续点击两次“加一”，AI 随后给出新结果。要让 AI 写入基于这两次修改，业务先等待两个 `update` 的 Promise 都成功，再提交 AI 命令。查询不会强制发送仍在等待的写入；关闭另一个代理的防抖也不能代替这次等待。

AI 请求、结果解析和业务校验应在事务外完成。等待 AI 时是否暂停新输入、是否允许使用旧数据计算，由业务决定；Helper 不推断业务冲突。

## 分清提交和文件保存

写入成功返回 `{ committed: true, persisted: false }`，表示本次事务已经提交到当前内存，之后可以查询或继续修改。它不交付文件保存确认，`persisted: false` 也不能证明文件一定尚未写入。文件由 Worker 在后台合并保存，规则以[数据库与保存契约](helper-sql.md#事务和保存)为准。

不要在成功返回后立即关闭、切换或重新加载，再把结果当作已经落盘。同一 Worker 内查询到笔记只证明内存结果；示例中的保存读回必须单独核对。公共业务对象没有 `flush`、`refresh`、`runtime` 或 `dispose`。

后台保存失败通过酒馆提示和插件管理区域通知，不会再次拒绝已经完成的业务 Promise。此时按提示核对文件结果、内存是否可用、权限或空间；不要重发已经提交的 SQL。关闭服务只等待已接收 SQL 和已开始的文件保存，尚未开始的后台保存取消，未落盘修改可能丢失。

## 错误处理

把属性读取、`debounce` 配置和异步调用都放在 `try/catch` 中。示例展示如何读取顶层 `code`、`message`、`level` 和可选 `suggestion`，按提示保留输入并停止依赖该结果的后续动作。跨 iframe 不依赖 `instanceof Error`；不要通过 message 文本或内部 `error.data` 判断业务结果。

| 情况 | 业务动作 |
| --- | --- |
| `DB_UNINITIALIZED` | 显示空状态，或由业务决定首次写入；查询本身不建库 |
| `SQL_COMMITTED`、`SQL_SAVED` | 修改已提交或保存，但调用另有错误；不要重复提交或继续依赖正常返回的流程 |
| `SQL_UNKNOWN` | 执行结果无法确认；保留输入，先核对当前业务数据，不直接重试或补偿 |
| 授权取消、拒绝、失败或超时 | 本次调用结束；后来授权成功不会恢复它，不自动再次弹窗 |
| `DB_UNAVAILABLE` | 原对象或存储不能继续使用，终止原流程，不自动更换目标 |
| `SYS_VERSION` | 按使用指南更新同一次完整构建，由用户刷新页面 |

`level` 只决定提示方式，不能证明修改是否执行或保存；用户取消授权即使显示为 info，调用仍失败。`SQL_FAILED` 等错误还须结合 `failureKind` 和 `executionState` 判断。字段、完整错误码和后续处理统一见[错误说明](helper-errors.md)。

重新连接只为后续调用恢复通信，不重发已发送 SQL，等待过久也不代表写入已取消。恢复规则见[调用等待与恢复契约](helper-recovery.md)。

## 支持范围

当前只处理单人聊天和一次调用一个库，不提供群聊、跨库事务、聊天分支自动隔离、业务冲突补偿或多设备同步。表结构、楼层、分支语义及跨事务依赖由业务设计。完整备份恢复和旧版结构迁移尚未提供，文件维护见[使用与维护指南](helper-usage.md#文件升级与备份)。
