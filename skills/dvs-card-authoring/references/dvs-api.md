# DVS 接口与进阶用法

本篇供已有 DVS 卡片的作者按需查询。第一次制卡先按[DVS 作者使用手册](dvs-author-guide.md)完成[青禾书店最小卡](../assets/dvs-minimal-card/README.md)，需要管理数据、调整提示词、增加业务计算或升级旧聊天时再读对应部分。

SQLite Helper 提供数据库和文件保存，DVS 管理每条 AI 回复对应的状态；业务字段、初值、规则及计算由作者决定。下面的代码片段各自说明一种接口用法，不是一张需要全部拼在一起的角色卡。

编辑器使用扩展包的 `types/dvs.d.ts` 及配套 `types/sqlite-helper.d.ts`，不要另外手写一份接口声明。声明与运行插件需配套更新。

## 主世界书版本检查

可选方法签名：

```ts
lorebookVersionCheck(options: {
  onExpired: 'WARNING_MESSAGE' | 'AUTO_UPDATE';
}): Promise<void>;
```

独立酒馆助手脚本启动时调用一次：

```js
await waitGlobalInitialized('DVS');
await DVS.lorebookVersionCheck({ onExpired: 'AUTO_UPDATE' });
```

方法比较当前单人角色卡的 `data.character_version` 与当前主世界书中唯一、名称精确为 `[DVS_VERSION]` 的条目内容，不依赖变量开关或业务注册。条目名区分大小写，条目是否启用不影响读取；不扫描附加、全局或聊天世界书，也不从内嵌世界书补足版本。两侧版本均去首尾空白和可选的单个 `v`／`V` 前缀，按严格三段 SemVer 比较，支持预发布标识，构建元数据不影响优先级。例如 `0.2.0`、`v0.2.0` 有效，`0.2`、`vv0.2.0` 和前导零无效。卡片／世界书内容版本与 DDL 迁移版本各自维护。

主书版本相同或更高时正常完成，不提示、不更新。缺少当前单人角色、主书、唯一版本条目或有效版本时报告具体原因，不推定过期。主书较旧时，`WARNING_MESSAGE` 只提示过期；`AUTO_UPDATE` 先显示原生确认框，说明书名、双方版本及保留本地修改的方式；取消时正常返回，不读取内嵌来源、不写入数据。点击“备份并更新”后才读取卡片内嵌来源，另名保存完整旧书并从后端读回确认，再删除原名文件、导入新版并关联当前卡，保持附加世界书列表。新书内容、关联及版本从后端确认后才显示成功；新书版本仍落后时报告更新未解决版本问题。

成功框显示新书、版本和旧书名，只有玩家点击“刷新页面”才重新加载整个酒馆页面；Esc 或关闭成功框不刷新。

调用完成返回 `void`，读取、版本格式或更新失败时拒绝 Promise 并显示原有错误提示，不刷新。更新的保存、删除、导入和关联不是一个原子事务；失败后保留已完成结果，按提示核对旧书、新书和主世界书关联，必要时手工重新关联保留的旧书。它不协调独立脚本与注册的先后顺序，也不自动重试或跨刷新恢复。

## 注册与查询

在角色卡绑定的酒馆助手脚本中设置预设定变量 `{ "dvs_enable": true }`。关闭或缺省不会注册、初始化；字符串 `"true"` 和数字不是有效开关。改动后按助手原生方式重载脚本。

```js
await waitGlobalInitialized('DVS');
const dispose = await DVS.register({
  scriptId: getScriptId(),
  uniqueKeys: { 角色: ['角色名'], 道具: ['持有人', '道具名'] },
  narrativePrepare: ({ tables }) => tables,
  beforeGen: (_state, tables) => tables,
});
$(window).on('pagehide', dispose);

const state = await DVS.getState();
const person = await state.table('角色').get('阿呆');
const items = await state.table('道具')
  .query('持有人 = ? OR 数量 > ?', '阿呆', 2)
  .orderBy('数量', 'desc', '道具名', 'asc').rows();
```

注册规则：

- 同一角色只使用一个 DVS 注册脚本。
- 同脚本重新注册会替换声明。旧 dispose 不会清掉新注册。
- 作者传自身 `getScriptId()`。DVS 在父页面读取该脚本变量，不在共享方法内猜测发起调用的 iframe。

`waitGlobalInitialized('DVS')` 只表示公共接口已发布，不表示当前角色已启用或完成注册。关闭 DVS 时变量功能的公共方法报未启用，不初始化或删除数据；Helper 基础接口仍可独立使用。注册脚本及其所在文件夹也须保持开启。

注册中的真实表名、业务键和数据库列名须一致，真实表必须有单列主键 `rid`。业务表名不能使用 `_dvs_`、`__stsh_` 保留前缀；业务键不能使用 `rid` 或 `_dvs_` 前缀，不能为空或重复。声明业务键不等于创建全表 SQL `UNIQUE`。

查询方法：

| 方法 | 行为 |
| --- | --- |
| `get(...keys)` | 按 uniqueKeys 的完整顺序传参。没有匹配返回 null，多匹配报错 |
| `row()` | 返回首行或 null |
| `rows()` | 返回数组。无排序时不承诺业务顺序 |
| `query` | 使用 SQL 条件与参数绑定 |
| `orderBy` | 接受实际列及小写 asc／desc |

`query(condition, ...values)` 的条件不带 `WHERE`，动态值使用 `?` 和后续参数传入。DVS 自动限制到该 fid 的有效集合。`table()`、`query()` 和 `orderBy()` 同步返回查询对象，`get()`、`row()`、`rows()` 异步取数据。不支持 `groupBy`。

读取哪个版本：

- 无参 `getState` 取最近 AI 回复的当前 swipe。用户消息和 narrator 不算 AI 回复，隐藏 AI 仍可读。
- 最新 AI 回复无 fid 时报未建立状态，不回退到更早回复。
- `DVS.getState({messageId:0,swipeId:0})` 可读当前聊天保留的历史版本，不切换界面。
- DVS 管理方法只允许最新 AI 回复的当前版本。

显式 `messageId` 须为非负整数，指向当前聊天实际存在的非系统 AI 回复；省略 `swipeId` 取该消息当前版本。用户、系统、narrator、越界版本或缺少 fid 都拒绝，不猜测替代目标。

连续 `getState()` 在 3 秒内可复用已读世界书条目，数据库内容仍每次查询。修改世界书定义后，`getState()` 最多延迟 3 秒看到变化；每次新 `regen()` 和重新注册会重新读取。取得的 state 固定到当时的角色、聊天及 fid；切聊天或切换 swipe 后重新 `getState()`，不要把旧对象当成新目标。

## 修改与逻辑事务

```js
const state = await DVS.getState();
await state.transaction(async tx => {
  const person = await tx.table('角色').get('阿呆');
  if (!person) throw new Error('角色不存在');
  person.金钱 -= 10;
  await person.update();
  await tx.table('道具').insert({ 持有人: '阿呆', 道具名: '短刀' });
});
```

事务边界：

| 操作 | 结果 |
| --- | --- |
| 单独的 `insert`、`update`、`remove` | 各提交一次事务 |
| `state.transaction` | 按回调登记顺序共同提交或回滚 |
| `update` | 插入 UUIDv7 新行版本，并替换当前 fid 索引 |
| `remove` | 只移除当前关联，历史业务行保留 |

字段约束、默认值、生成列和业务键比较交给真实 SQLite。提交后对象使用数据库实际值。

行对象规则：

- 同一 state 查到同一行时，行对象共享待保存修改。赋值后必须 `update` 才入库。
- `insert` 返回显式输入字段，重新查询可读取默认列。
- 生成列可读，不能直接赋值。
- 字段与 `$字段` 等价。与方法同名的列要加前缀：例如列名 `update` 用 `$update`，原列 `$HP` 用 `$$HP`。
- rid 隐藏，`JSON.stringify` 导出原业务字段。
- JSON 写为 TEXT，读取不会自动解析。
- BLOB 与 `state.fid` 读取均为副本。状态对象不提供各表的 `rid` 集合；需要原始记录标识时使用 `state.chat.query()` 编写 SQL。

逻辑事务内的限制：

- `get`／`rows`／`orderBy` 看到已加载和已登记的数据。不支持 `query` 或嵌套事务。
- 临时 `get` 在 JS 中比较显式或已加载的值，不模拟 SQLite 默认值、列亲和或 collation。最终键冲突由提交时的真实 SQL 检查。
- 回调不构成 SQLite 快照。网络、界面或直接 Helper SQL 的副作用不在这批事务中。
- 回调结束后临时对象关闭。需要长期对象时，请从原 state 再查询。

```js
const unsubscribe = DVS.onUpdate(async () => {
  const current = await DVS.getState();
  render(await current.table('角色').rows());
});
$(window).on('pagehide', unsubscribe);
```

以下情况会通知 `onUpdate` 监听：初始化关联成功、SDK 提交、目标切换和变量更新结束。

- 通知不能作为文件保存证据。
- 监听失败单独报告，不撤回成功写入。
- 不同 state、直接 SQL 与 Proxy 不自动同步。
- `state.char`／`state.chat` 是固定代理（创建时固定数据库目标的 Helper 代理）。通过它直接执行 SQL 时，业务和 DVS 索引由作者维护，接口不是 SQL 沙箱。

## 预处理表数据

`DVS.table(表名, 行列表?)` 同步处理内存数据。narrativePrepare、beforeGen 执行期间可省略行列表，直接使用本次回调的输入；也可显式传入指定数据。它自动保护注册的全部业务主键，仅转换副本，不修改输入或数据库；`state.table()` 仍用于数据库查询和管理。

| 方法 | 用途 |
| --- | --- |
| `excludeFields(names)` | 移除指定业务字段 |
| `excludeValues(values, scope?)` | 移除值严格匹配任一候选值的字段 |
| `replaceValues(from, to, scope?)` | 将严格匹配的字段值替换为副本 |
| `replaceText(from, to, scope?)` | 只替换字符串字段中的文字 |
| `rows()` | 返回当前处理结果的独立行列表副本 |

字段名可传字符串或字符串数组。`scope.fields` 指定只处理哪些字段，`scope.except` 排除字段，二者可组合；任何选择都不能改动注册业务键。

例如在注册的 narrativePrepare 中，隐藏角色的内部数值，并将物资未知信息显示为空白：

```js
narrativePrepare: ({ tables }) => ({
  ...tables,
  角色: DVS.table('角色')
    .excludeFields(['好感度', '相遇情境'])
    .excludeValues('未知')
    .rows(),
  道具: DVS.table('道具')
    .replaceValues('未知', '')
    .rows(),
})
```

上例要求对应角色字段存在于作者表中。姓名或持有人、道具名等注册业务主键即使值为“未知”，也会保留原值；其余字段是否隐藏由作者决定。

默认数据可在回调内跨 await 使用，回调结束后释放。回调之外、更新订正／后处理或多个异步准备回调重叠时，请显式传入第二个参数；否则缺少或无法确定默认数据时会报错。其他脚本在准备回调执行期间调用辅助方法，也应显式指定数据来源。

```js
// 只处理说明、状态；也可用 except 排除指定字段，两者能组合使用。
DVS.table('道具', tables.道具)
  .replaceValues('未知', '', { fields: ['说明', '状态'] })
  .replaceText(/\r?\n/g, ' ', { except: '道具名' })
  .rows();
```

`excludeValues(['未知', '未填写'])` 可以移除多个候选值对应的字段。匹配按类型严格比较，不将 0、空字符串、NULL 或“未知原因”当作“未知”。`replaceText` 只处理字符串，字符串模式替换首处，正则模式按标记执行。辅助对象可用于不同准备回调；只调用它不产生保存或 onUpdate 通知。

## 正文数据注入

角色卡注册完成后，单人聊天的普通生成、重新生成最新回复和生成新 swipe 会先执行一次 `narrativePrepare`。普通追加取最近 AI 回复当前分支的数据；真正替换末尾 AI 回复时取它前一 AI 回复的数据。末尾是用户消息时，重新生成仍按追加取值。只有开场白时使用当前已初始化的开场白，不重跑 INIT。

例如 A 的 hp 为80，用户输入下一句后生成 C，回调和只读模板查询都从 A 出发。回调可把提示词 hp 改成“受伤”，宏输出“受伤”，普通 EJS 仍读数据库中的80。准备回调返回值只影响本次提示词；回调通过 Helper SQL 明确执行的写入另按 Helper 契约处理，不因正文取消回滚。

在原生世界书中启用正文条目，例如：

```text
条目名称：[DVS_NAR]角色状态
正文：请依据以下状态描写人物：
[[DVS_DATA_角色:yaml]]
```

条目的关键词、插入位置、角色和顺序继续由酒馆处理。`[DVS_NAR]` 是用途标签；宏也可放在其他提示词文本中。总表用 `[[DVS_DATA]]`，分表用 `[[DVS_DATA_角色]]`，默认 Markdown，可加 `:md` 或 `:yaml`。重复标记分别替换，不递归执行替换结果中的新标记。未知表或格式报告错误并将该标记替换为空；准备失败则停止请求。

回调返回普通“表名 → 行列表 → 业务字段”数据。支持有限数值、字符串、布尔、NULL 和普通 JSON 数组／对象。SQL TEXT 原样保留；BLOB 须由作者在回调中转为合适的可表达值。函数、访问器、undefined、NaN／Infinity、类实例和循环引用会使准备失败。YAML 复用酒馆助手公开库；Markdown 转义特殊字符，空表仍输出空集合。

EJS 是可选用法，需要另装并启用 [ST-Prompt-Template](https://github.com/zonde306/ST-Prompt-Template) 的相应正文处理。只使用宏的卡片不需要该插件。开启后，普通生效世界书可另写异步 EJS：

```ejs
<% const person = await dvs_state.table('角色').get('阿呆'); %>
当前金钱：<%= person?.金钱 %>
<% const rows = await dvs_state.table('道具').query('数量 > ?', 0).orderBy('数量', 'desc').rows(); %>
```

`table()`、`query()`、`orderBy()` 同步返回查询对象，`get()`、`row()`、`rows()` 异步读数据。`dvs_state` 只查询本次固定起点，不提供 char、chat、rid、transaction 或写入方法。返回业务字段的独立只读副本；BLOB 是独立字节副本，修改它不改数据库。与 SDK 方法同名的业务列在这里仍按原列名读取。正式正文及变量请求中的查询失败，即使被模板 catch，也会使最终请求停止；打开聊天的额外世界书处理保留真正错误，不承诺停止整个第三方模板流程。

正式正文请求使用本次固定起点。打开、刷新或切换单人聊天触发的世界书条件和预处理也可查询 `dvs_state`：DVS 先等作者脚本注册和现有初始化完成，再提供最近 AI 回复当前版本的数据，不额外执行作者准备回调。作者无需逐条判断 `dvs_state` 是否存在。已启用脚本 10 秒内仍未开始注册时会报告错误；请检查脚本错误并原生重载。初始化完成后的空表正常返回空数组或 `null`，随后访问不存在记录的字段仍可能产生模板错误。

历史显示、提示词模板的独立预加载、`/ejs` 和助手独立请求不能自动取得该对象。DVS 停用时不等待、不初始化、不注入，依赖 DVS 的模板仍由作者负责停用。模板关闭时宏仍可使用；EJS 条目须由作者启用相应模板处理。宏在最终模板之后替换，业务字符串中的 EJS 不再执行。数据不参与本轮世界书递归扫描，完整替换数据不计入替换前预算。

最终 EJS 接入针对 Chat Completion 的 messages 和 TextGen 的 prompt。安装提示词模板的最终文本处理只读取 prompt；NovelAI 使用 input 字段，DVS 可替换其宏，但不承诺该插件会处理 input 中的普通 EJS。

提示词模板的 iframe“环境隔离”与 Worker“后台编译”应二选一。iframe 方式已有真实酒馆验证；Worker 方式的最小 EJS 编译对照未完成，DVS 在该模式下的最终正文注入仍未验证，不能据此判断不支持。需要 EJS 时可使用已验证的 iframe 方式。

续写、冒充用户、群聊、工具递归和助手独立生成不在支持范围内。准备或查询失败会停止正文发送；停止不自动撤回原生已加入的用户消息或已删除的待替换回复。正文成功完成后自动更新变量；主动变量更新见下文。

## 选择世界书条目的用途

DVS 开启且注册有效时，只含 `[DVS_NAR]` 的条目用于正文，只含 `[DVS_VAR]` 的条目用于变量更新；同时有两个标签或没有用途标签的普通设定，两边都可使用。它们仍须启用，并满足酒馆激活规则。正文保留原生插入位置；变量把激活内容合并到 `<world_context>`，按 order 排序。

`[DVS_RULES]`、`[DVS_DATA]`、`[DVS_VAR_COT]` 分别提供变量规则、起点输入数据和本轮检查项，直接读取已启用条目，不走关键词或红绿灯，不进入正文或普通变量扫描。与 NAR／VAR 混写时仍按特殊用途处理；启用条目不能同时有三种特殊用途中的多种。停用则跳过，包括冲突检查、宏和模板。

DDL／INIT 只用于 SQL，不进入两种提示词；可保持停用，SQL 读取仍忽略该开关。DVS 不修改世界书保存的开关。关闭 DVS 或没有有效注册时不执行分流。

这些 DVS 用途标记不区分大小写，但 SQL 条目的完整名称仍须符合 `[DVS_DDL]v版本` 或 `[DVS_INIT]welcome_编号` 的格式，不在名称前加其他文字。NAR、VAR 及三个特殊提示词标签可出现在条目名其他位置。

### 变量提示词怎样取材

每次新更新重新读取当前角色主世界书和附加世界书。普通设定调用酒馆原生扫描，截止目标 AI 回复并包含该正文；扫描深度、关键词、递归、概率、预算和冷却遵守酒馆规则，`DVS.regen()` 的扫描触发类型仍为 normal。全局、聊天和 Persona 的其他书不作为本次变量请求候选；历史正文数只控制给模型补充多少较早 AI 正文，不改变扫描深度。

RULES、DATA、VAR_COT 和普通设定各自按 `position.order` 升序合并，同值保持读取顺序。`order` 缺失或不是有限数值会停止并报告条目。普通设定合并到 `<world_context>`，不沿用正文插入位置；背景设定不能独立证明事件已经发生，也不能覆盖实际起点。一次更新的自动重试复用同一批选定条目，下一次 `regen()` 才重新读取和扫描。

条目按普通酒馆宏、EJS、DVS 数据宏的顺序准备；原生预处理已经展开的普通宏和 EJS 不再次执行。变量数据宏读取 `beforeGen` 返回集，可选 EJS 的 `dvs_state` 则查询固定起点数据库，两者不能混为同一数据来源。EJS 或只读查询失败，即使模板捕获了查询错误，也会停止本次准备，不发送变量请求或自动重试作者准备。

### 编写 RULES 与 DATA

变量提示词中的表结构说明由 DVS 按注册信息自动生成，只列表名、业务键和字段名，不列类型和默认值。字段名尽量自描述；单位、枚举和缩写的含义写在 `[DVS_RULES]` 中。

`[DVS_RULES]` 集中写框架无法知道的业务内容，用“发生什么 → 改哪个字段 → 改多少或怎样替换”的短句表达。例如“正文明确休息恢复体力 5 时，hp 加 5”，比“合理更新体力”更容易执行。

| 需要说明的内容 | 例子 |
| --- | --- |
| 字段含义、单位或枚举 | hp 代表体力；状态只用正文明确给出的文本 |
| 事件触发与更新方式 | 药水用完则移除；明确恢复 5 才加 5，不按常识推算 |
| 同名对象是原行修改还是替换 | 换成另一把同名旧刀：先 remove 再 add |
| 缺失字段与默认值 | 新刀不指定品质时省略品质字段，由数据库默认值填写，不带回旧品质 |
| 开场白初始化 | 空起点从最新开场白 add 建行，不对不存在的行 delta 或 replace |

JSON 格式、API 角色说明和业务键对象写法由 DVS 模板提供，规则中不必重复。可以给业务例子，但要标明是例子，不要整段复制正文或当前表。

`[DVS_DATA]` 提供本轮起点，也就是最新回复之前的实际状态。完整保留所提供行的业务键和值，不要让模型从历史重新推算起点，也不要混入本回合更新后的数据。小型整齐的表适合用 Markdown 表格，逐行对象较多的表可以单独用 YAML；同一份数据中字段名、业务键值和数值类型保持一致，文本按所用格式正确转义。表很大或结构复杂时，可以比较同一份数据的两种写法，选更清楚、token 更少的一版。

### 提供本轮检查项

启用一个单独条目，例如标题 `[DVS_VAR_COT]本轮核对`，正文写“1. 时间线：核对本轮结束时间和活动时长。2. 物品：核对转交双方的数量变化。”业务规则仍放在 RULES，停用 COT 后也应完整。多个条目按 order 稳定合并，只发送正文，建议在正文中使用清楚且不同的项目标题。普通宏、EJS 和 DVS 数据宏沿用变量提示词的展开规则。

模型被要求在同一 JSON 的可选 cot 字符串中逐项报告检查结果，再输出 Analysis 与 UpdateCommands；无检查内容时省略 cot。cot 的值由本地完全忽略，不校验、不执行；完整返回 JSON 包括 cot 会保存在正文尾部供查看，真正更新仍取决于两个数组及作者回调。检查文字不证明模型没有遗漏，效果需另行比较。

## 数据准备和更新回调

注册必须提供 `narrativePrepare` 和 `beforeGen`。不需要改写提示词数据时直接返回收到的 `tables`；没有业务计算时省略 `preUpdate`、`postUpdate` 和 `virtualTables`。

| 回调 | 输入、返回及发生时间 |
| --- | --- |
| `narrativePrepare({ char, chat, tables })` | 正文发送前执行；返回正文宏使用的表数据，可异步 |
| `beforeGen(state, tables)` | 每次变量模型请求前执行；返回变量数据宏使用的表数据，可异步 |
| `preUpdate(state, newTables, oldTables)` | 补丁计算后、写数据库前执行；返回全部订正后的真实表，可异步 |
| `postUpdate(state, newTables, oldTables)` | 默认更新、关联及实际值读回成功后执行；返回 `void`，可异步，通过管理方法另行写入 |

`beforeGen` 收到完整起点的独立副本，它的返回值只供提示词。补丁始终从完整起点的另一份副本计算，不会因作者隐藏了提示词字段而删除数据库字段。`oldTables` 也是本轮完整起点的副本，不是上次失败尝试、筛选后的提示词或稍后重查的当前值。

`beforeGen`、`preUpdate` 的 `state` 提供固定的 `char`、`chat`、`fid` 和只读 `table()` 查询。它们从本轮起点读取；修改待写入数据请改 `newTables`。只有开场白的变量重新生成从全部注册表为空的起点开始，此时 `fid` 为 `null`，不读取原 INIT 或已有变量。`postUpdate` 的 `state` 对应成功后的目标层，具有非空 `fid` 和管理方法；其 `newTables` 包含数据库实际默认值。传入的两个表数据快照不会随随后管理操作改变。

`preUpdate` 返回值必须恰好包含全部真实注册表；用 `[]` 明确清空一张表。遗漏表、未知表、未知列、缺少完整业务键或未移除虚拟表会拒绝写入。已有行不能靠省略原有列伪装成新增行；新行省略的列交给 SQLite 默认值处理。生成列只读，写入后由 SQLite 重算。DVS 比较最终数据和完整起点，只为实际变化建立行版本，并建立目标层的完整索引。

`preUpdate` 的返回数据和默认更新在同一事务提交。`postUpdate` 使用管理方法产生后续事务，失败时默认更新已经保留；若其多项修改需要共同成功，请使用 `state.transaction()`。直接 Helper SQL、网络或界面副作用不受默认事务保护，自动重试也不承诺这些副作用只发生一次。

### 模型补丁格式

变量模型返回一个 JSON 对象，必需字段为 `Analysis`、`UpdateCommands` 两个数组，可选 `cot` 是检查结果。模型不编写 SQL，也不提供内部 `rid`、`fid`、行序号或拼接路径。

| 操作 | 要提供的字段 | 前提与结果 |
| --- | --- | --- |
| `add` | `reason, op, table, keys, value` | 行不存在；`value` 是新行业务字段对象，缺省列交给数据库 |
| `remove` | `reason, op, table, keys` | 行存在；移除当前目标中的该行 |
| `delta` | `reason, op, table, keys, field, value` | 行和数值字段存在；把有限数值增量加到原值 |
| `replace` | `reason, op, table, keys, field, value` | 行存在，字段已声明；替换该字段 |

每条命令的 `keys` 都须准确包含注册的全部业务键。复合键按字段名定位，顺序任意，字符串和数字不自动转换。`add.value` 若再次写入键字段，类型和值须与 `keys` 一致；不能写生成列。命令按数组顺序执行并逐项检查存在条件，同键替换应先 `remove` 再 `add`。

`Analysis` 每项提供 `reason, table, keys`，可选 `field`；每条命令需要同表、同键且覆盖该字段或整行的分析。两个空数组表示没有业务变化，仍会为回复建立完整数据关联。检查能拒绝错误定位，不能证明模型没有漏掉剧情变化。

真实表的顶层字段和键只接受其存储规则允许的值；数值须有限，整数及 `delta` 的原值和结果须在 JavaScript 安全整数范围。普通对象、数组写成 SQL TEXT，读取不自动解析。真实表顶层布尔不符合 Helper 绑定规则，会明确拒绝；JSON 对象内部的布尔可以保留。虚拟表按声明检查顶层 JSON 类型，不额外解释嵌套业务数值。

三种输出格式都检查同一补丁协议。`json_object`、`json_schema` 要求整个响应是一份 JSON；`text` 允许单份 JSON 外的包装，例如一个 JSON 代码块和开头闭合的 `<think>…</think>`，不能混入第二份答案、示例或无效围栏。DVS 不自动修复 JSON，不把推理字段或工具调用拼成补丁。`cot` 的值由本地忽略，不进入回调或 SQL，显示它不证明更新正确。


## 主动更新最新回复的变量

```js
await DVS.regen();
const current = await DVS.getState();
```

`regen()` 不重新生成正文，只处理最新 AI 回复的当前 swipe。普通回复从前一个 AI 回复的状态出发；只有开场白时从所有注册表为空的起点出发，忽略已有变量且不重跑 INIT。每次新更新读取固定正文及最近前置用户消息，再按配置追加较早 AI 正文。普通设定按酒馆扫描设置重新扫描，例如设置最近五条，就扫描截止目标 AI 回复的最近五条，其中包含目标正文。扫描只选择当前角色主世界书和附加世界书；历史正文数不决定扫描深度。作者在世界书中提供 `[DVS_RULES]` 规则条目、可选 `[DVS_VAR_COT]` 检查条目、`[DVS_DATA]` 数据条目和注册回调。

自动更新和手动 `regen()` 期间，酒馆输入框显示停止按钮，暂不能发送下一轮。停止按钮会取消变量请求；已提交的数据库修改不会撤销，错误会说明是否已提交及关联。请求和已开始的处理结束后恢复发送。

在模型请求或重试等待中停止，若本轮默认更新没有改变原数据，原先已确认的变量可立即通过 `getState()` 重新读取，无须刷新页面。没有旧变量的回复不会凭空获得变量；此前结果未确认，或本轮写入／关联结果无法确认时，读取保护仍保留。恢复读取不改变变量，不另发 `onUpdate` 通知。

变量处理期间若其他流程恢复了原生发送按钮，DVS 会继续保持请求中，直到本轮落定。开始、重试及处理进度显示在同一条 toastr 中；成功后关闭，最终失败则说明是否已经更新或沿用变量。用户停止会提示实际结果，切聊天等取消不在新聊天上显示旧任务提示。

作者状态栏可用以下接口让按钮同时响应自动和手动更新；中途挂载也应先读取当前状态。`onUpdate` 仍用于读取更新后的业务数据，不能代替进度订阅。

```js
function showUpdateStatus(status) {
  updateButton.disabled = status.phase !== 'idle';
  updateButton.textContent = status.phase === 'idle' ? '重新更新变量' : '正在更新变量…';
}
showUpdateStatus(DVS.getUpdateStatus());
const unsubscribeStatus = DVS.onUpdateStatus(showUpdateStatus);
// 状态栏卸载时调用 unsubscribeStatus()。
```

使用这些接口的作者界面需要与提供该接口的插件构建配套。

### 更新进度

`getUpdateStatus()` 返回当前注册、当前聊天的独立进度副本；`onUpdateStatus(callback)` 返回取消订阅函数，注册注销时清理。切聊天按新目标通知，不把旧聊天的进行中状态用于新聊天。监听失败不改变变量处理结果。

| 字段 | 含义 |
| --- | --- |
| `phase` | `idle` 空闲、`preparing` 准备、`requesting` 请求、`retrying` 等待重试、`processing` 处理补丁及后续步骤 |
| `attempt` | 当前尝试从 1 开始，首次请求前为 0；等待重试时是刚失败的编号 |
| `maxAttempts` | 本轮最多尝试次数，尚未读取配置时为 0 |
| `retryDelayMs` | 等待重试的配置间隔，其他状态为 0；不是实时倒计时 |

`idle` 时数字均为 0。界面在非 `idle` 时禁用更新按钮，等待重试可显示 `attempt + 1`。中途挂载要先读取状态，不能只依靠自己的点击 Promise 判断自动更新是否忙碌。

同一条回复在变量处理期间被插件或用户改写，DVS 仍按本轮读取的正文计算变量，不因改字取消或重新请求；追加状态栏标签和返回 JSON 时重新读取最新正文，保留改写内容。如果改写改变了剧情，本轮变量仍对应改写前已捕获的剧情。删除回复、再次重新生成将旧回复替换为新消息，或切换聊天、swipe 时，旧操作仍停止。保存与错误边界见[作者面板的显示与操作](#状态栏标签与刷新)。

同一次更新的失败自动重试复用这次选中的条目；再次调用 `regen()` 会重新读取、扫描，刷新页面后也一样，不依赖上次内存结果。普通设定只补充背景，不证明当前已发生事件、不覆盖起点值。

发送给变量模型的最新正文、历史 AI 正文和最近用户输入，会分别应用酒馆“发送给 AI”的正则，并遵守各条消息在完整原聊天中的深度设置；仅格式显示的规则不参与。过滤后的文本只用于本次请求，聊天原文不改写，详见[数据来源与排列](#主动更新最新回复的变量)。

`beforeGen` 返回原生“表名 → 行列表 → 业务字段”，只供提示词，不作更新底稿。模型通过 `table` 和完整 `keys` 对象定位；复合键按字段名和值分别提供，具体契约见[输出协议](#模型补丁格式)。正文 narrative 宏和 EJS 查询保持原格式。

### 状态栏标签与刷新

默认变量更新成功，且消息关联和实际值已确认后，DVS 等待 `postUpdate` 与本次清理结束，在当前叙事正文之后、返回 JSON 数据块之前保留唯一的标准标签 `<DVSPanelPlaceHolderImpl/>`。作者使用仅格式显示的酒馆正则将其替换成自己的状态栏；状态栏通过 `DVS.getState({messageId, swipeId})` 读取该回复的数据。界面、查询及卸载由作者负责。

每次处理完变量后统一编辑一次这条回复，整理标准标签并替换本次返回 JSON 数据块，仍复用酒馆助手自带的单楼层重渲染。不刷新页面，不重新生成正文，不改其他 swipe 或消息变量。模型失败后已确认沿用起点时不新增标签，但仍重渲染已有标签；更新失败继续报错。后处理失败保留已提交变量并处理状态栏，显示或正文保存失败另报，不重复执行变量更新。

再次变量请求的历史和扫描副本会移除标准标签，聊天文件仍保存原始标签；不删除其他 HTML。正文完成自动触发与主动 `DVS.regen()` 共用同一流程。

### 虚拟表输入与写库前计算

需要模型记录结构化输入、再由 JS 计算真实业务值时，在同一次注册中声明虚拟表。例如在现有注册选项中加入：

```js
virtualTables: {
  本轮结算: { keys: [], fields: { 行程: 'array', 持续补充: 'object' } },
},
preUpdate: (_state, newTables, oldTables) => {
  const input = newTables.本轮结算[0];
  // input?.行程和input?.持续补充是原生数组／对象，按作者规则计算真实字段。
  // oldTables是完整真实起点；newTables保留其它业务表及模型改动。
  delete newTables.本轮结算;
  return newTables;
},
```

`fields` 声明顶层 JSON 类型，支持 string、number、boolean、array、object、null。嵌套字段含义及计算规则由作者写入 RULES 并在回调中处理。`keys: []` 表示至多一行，以 `keys: {}` 定位；模型使用 `add` 建立行，之后可按已有操作替换字段。需要多行时，keys 使用已声明的 string／number 字段并提供完整键，不需要内部编号。

DVS 把声明与真实表结构一起交给模型，输出仍只有 Analysis／UpdateCommands。例如本轮结算可输出 `table: "本轮结算", keys: {}, op: "add", value: { 行程: [], 持续补充: {} }`，并配套同表同键的 Analysis。虚拟表每次请求从 [] 开始，不继承历史，不来自 beforeGen 的提示词副本，不建立数据库表或索引。

回调返回前必须删除全部虚拟表，包括空表。没有清除、返回未知真实字段或漏掉真实表都会明确报错。虚拟表不进入 SQL；真实表的完整键、已有列、生成列及事务检查继续有效。

虚拟表名不得与真实表名冲突，也不能使用 `rid`、`fid`、`_dvs_` 或 `__stsh_` 保留名／前缀。字段名遵守相同保留规则，至少声明一个字段；键字段须已声明为 string 或 number，不能重复。

### 更新结果与错误


调用等待提示词准备、模型请求、补丁计算、订正、默认事务、消息关联、实际值读回、后处理、周期清理和通知完成。默认提交后的后处理失败会报错，已提交结果仍保留。每次模型尝试是独立请求，重试不携带前次报错或输出，界面继续报告错误。补丁用 `table`、完整 `keys` 对象及适用的 `field` 定位注册业务数据，规则见[输出协议](#模型补丁格式)。有限重试耗尽时，普通回复建立新 fid 并沿用前一个 AI 回复的完整索引；开场白建立完整空状态。两种情况都报告变量更新失败。关联或执行结果无法确认时停止，不重发 SQL。支持范围见[本篇限制](#支持范围)。

| 失败 | 是否自动再请求模型 |
| --- | --- |
| 模型请求、JSON、补丁定位或操作前提失败 | 在配置次数内重试 |
| SQL／DDL 约束拒绝且已确认回滚 | 在配置次数内重试 |
| `beforeGen`、模板准备或 `preUpdate` 失败 | 停止，不自动重复失败的作者准备 |
| 基础服务、身份、存储异常或执行结果无法确认 | 停止，按实际结果交付，不重发 SQL |
| 默认提交后的关联、读回或 `postUpdate` 失败 | 保留成功部分并报错，不重做默认更新 |

单次超时只覆盖模型请求到完整响应体，不包含回调、SQL、聊天保存和后处理；取消不保证远端停止计费。每次重试重跑 `beforeGen`，补丁通过才执行 `preUpdate`，重试共用固定起点和本轮选择的世界书条目。失败沿用不调用 `postUpdate`，不能把它当成空补丁成功。

## 查看变量模型原始建议

变量处理结束后，正文尾部的“查看变量更新”默认折叠，点击后可分别展开思维链、实体分析和更新命令。思维链保留换行，分析按路径和原因列出，命令用 ✏️／➕／❌／📈 区分修改、新增、删除和增量，原因紧跟路径；值用等宽字体显示，对象或数组的紧凑 JSON 超过 50 个 UTF-8 字节时另起一行缩进显示 YAML。聊天正文仍保存本次最后一个可解析的完整原始 JSON，包括 cot；查看排版不会改写记录。它是模型原始建议，作者回调可能订正内容，失败沿用起点时也可能显示这次被拒绝的建议，不代表全部已写入。插件自动安装配套的显示和提示词正则：聊天文件保存 `<DVSUpdateData>...</DVSUpdateData>`，后续发送给 AI 时移除；DVS 自身变量历史也移除该块。正则只作用于 AI 输出，无深度限制，其他正则保留。插件只更新自己的两条原生全局正则，保留其他规则及其完整字段；规则一致时不重复保存，不重载聊天。

## 为角色卡准备 SQL

在角色卡绑定的 primary 或 additional 世界书中放置下列条目。DVS 读取禁用条目，推荐关闭 SQL 条目，避免它们进入模型提示词。每条内容可以有多条 SQL，通过 Helper `runSql` 执行；不要自行写 BEGIN／COMMIT／ROLLBACK。

条目 `[DVS_DDL]v1.0.0`：

```sql
CREATE TABLE "角色" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  角色名 TEXT NOT NULL,
  金钱 INTEGER NOT NULL DEFAULT 50 CHECK(金钱>=0)
);
CREATE TABLE "道具" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  持有人 TEXT NOT NULL,
  道具名 TEXT NOT NULL,
  数量 INTEGER NOT NULL DEFAULT 1
);
```

条目 `[DVS_INIT]welcome_0`：

```sql
INSERT INTO "角色"(rid,角色名,金钱) VALUES(randomblob(16),'阿呆',50);
```

初值需要使用玩家名字时，在 INIT 的 SQL 字符串中写 `'{{user}}'`，例如：

```sql
INSERT INTO "道具"(rid,持有人,道具名,数量) VALUES(randomblob(16),'{{user}}','手机',1);
```

DVS 在初始化时通过酒馆宏接口取得当前用户／Persona 名称，转义名字中的单引号后写入数据库。只处理 INIT 中精确的 `{{user}}`，不展开整段 SQL 的其他宏；源条目保持原样。已有初始化状态不重跑。

`rid` 与 `fid`：

- `rid` 为 16 字节 BLOB，标识一条历史记录。
- 正常生成的 `rid` 和楼层 `fid` 使用 UUIDv7。
- INIT 可以手工写 UUIDv7 的 BLOB，也可以为便利使用 `randomblob(16)`。
- 业务唯一键只在某个 fid 的有效集合中唯一。不要在整个历史业务表上为角色名等业务键建 UNIQUE。

开场白与 INIT 的对应：

| 开场白 | INIT 条目 |
| --- | --- |
| 默认开场白 | `welcome_0` |
| 额外开场白 | 依序 `welcome_1`、`welcome_2` |

- 若默认文本为空、酒馆移除该项，显示的第一个额外开场白仍使用 `welcome_1`。
- 有 INIT 时必须唯一，作者负责插入其完整初值。
- 允许没有对应 INIT，此时各注册表的初层为空，不自动收入 DDL 已写入的业务行；开场白 regen 从空数据生成初值，忽略已有变量。没有 INIT 时，开场白重新生成仍从空起点开始。
- 相同业务值应插入新的 rid。写死重复 rid 或改写其他开场白旧记录的后果由作者处理。

初始化时机：

- 打开新聊天立即初始化当前原生开场白。
- 切换到未初始化的开场白，会执行对应 INIT 并建立新的 fid 索引。
- 切回已有 fid，直接读原数据。
- 手工重排或导入的开场白不能保证自动识别来源，不应依靠文本猜编号。
- 自动处理新聊天开场白选择；完整正文成功后自动更新变量，也可主动重新更新最新回复当前 swipe。

INIT、必要索引结构和初始索引在同一次数据库事务中提交，聊天中的 fid 另行保存并读回。迁移或初始化 SQL 失败会停止并报告，不自动重试；已有数据库事实却缺少开场白关联时，也不会猜测应该重建初值。先核对实际数据，再决定作者侧处理。

## 角色卡升级

升级规则：

- 每个聊天自己的 `_dvs_version` 单行保存最近成功的 DDL 版本。
- 添加 `[DVS_DDL]v1.1.0` 后，DVS 使用 npm semver 选择比该聊天记录更高的条目，按升序执行。
- 每个版本的 SQL 与版本号在同一次 `runSql` 中提交。
- 某版本失败时停止后续版本，保留之前已成功的版本。
- 不自动降级。

版本格式：

- 必须是三段 SemVer `major.minor.patch`，支持预发布和构建元数据，例如 `1.10.0`、`2.0.0-alpha.2`。
- 不支持 `1.2`、前导零或版本范围。
- 构建元数据不影响优先级，两个同优先级条目会报歧义。

迁移中的新增或改名业务表、数据与索引关联，由作者 SQL 明确维护。DVS 保留 `_dvs_version`、`_dvs_gc_counter`、`_dvs_index_<业务表名>`，不要把这些名称作为业务表。

```sql
CREATE TABLE "新表" (
  rid BLOB PRIMARY KEY CHECK(typeof(rid)='blob' AND length(rid)=16),
  名称 TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS "_dvs_index_新表" (
  fid BLOB NOT NULL CHECK(typeof(fid)='blob' AND length(fid)=16),
  rid BLOB NOT NULL CHECK(typeof(rid)='blob' AND length(rid)=16),
  PRIMARY KEY(fid,rid)
) WITHOUT ROWID;
INSERT INTO "新表"(rid,名称)
SELECT randomblob(16),'升级初值' WHERE [[last_fid]] IS NOT NULL;
INSERT INTO "_dvs_index_新表"(fid,rid)
SELECT [[last_fid]],rid FROM "新表" WHERE [[last_fid]] IS NOT NULL;
```

这是新增业务表的完整迁移示例，需要同时在注册声明中增加 `新表: ['名称']`。

| 聊天情况 | `[[last_fid]]` | 结果 |
| --- | --- | --- |
| 已有聊天 | 固定 fid | 将新行关联到当前 fid |
| 全新聊天 | NULL | 只建表，不创建关联；由随后对应的 INIT 插入完整初值 |

作者应同步修改各开场白 INIT，包含新表的初始行。旧历史 fid 是否补齐，由作者迁移 SQL 决定。

`[[last_fid]]` 的规则：

- 它是保留文本标记。所有精确匹配的文本直接替换为固定 fid 的 `X'32位十六进制'`，无有效关联时替换为 NULL。
- 只放在 SQL 值位置，外面不加引号。
- 字符串、标识符和注释中的相同文本也会被替换。需原样保留的文字，避免写出完整标记。
- 迁移 SQL 不展开酒馆宏，源世界书不被修改。INIT 单独支持 SQL 字符串内的 `{{user}}`，见[准备 SQL](#为角色卡准备-sql)。

## 配置变量模型

参数面板的“额外历史 AI 正文数”允许 0，默认 2。当前待更新 AI 正文及最近前置用户消息不计入 N。

插件设置中的“DVS 变量模型设置”不依赖当前角色卡是否已注册 DVS。API 地址填写 `http` 或 `https` 基础地址，不要填写完整的 `/chat/completions` 路径；模型名可以直接输入，也可以获取模型列表后选择。无认证服务可以不填 API 密钥。保存配置前会校验输入，并通过酒馆原生扩展设置保存及读回；连接测试不是保存的前置条件。

普通参数保存在当前酒馆账户的扩展设置中。API 密钥保存在当前 SQLite 存储空间的 root 数据库，记录为本机明文；其他可信脚本、数据库查看器和备份可能读取。密码框始终以空值开始：已有密钥时留空表示保持，输入新值才替换；要删除时点击“保存时清除已存密钥”。存储空间切换后需重新读取当前空间的密钥状态。读取失败会显示状态未确认，不能据此假定没有密钥。密钥写入与普通参数保存是两个存储操作，界面分别报告已知结果；数据库后台保存仍可能尚未落盘。

“额外请求体（JSON）”接收 JSON 对象，留空等同 `{}`。DeepSeek 速填只更新当前草稿，不会自动保存或发送请求。地址、数值或 JSON 不符合输入规则时会提示并阻止保存或请求。测试最多发送三次固定内容的模型请求，可能产生费用；它不读取聊天或修改变量。模型列表为空时仍可手动填写模型名；模型接口或配置读取失败会显示错误，不能据此认定服务不支持所选格式。保存后的摘要只显示密钥是否存在，不显示明文。

角色卡作者可在开场白原文中加入精确标签 `<DVSConfig/>`。DVS 注册并启用后，会在合格角色卡开场白的标签位置显示同一套参数表单；没有标签时仍可从插件设置进入。标签应置于独立段落或普通正文中，不要放在代码块中。若需从模型提示词中移除标签，在角色卡正则中设置查找表达式 `/<DVSConfig\/>/g`，将来源设为仅 AI 输出、作用位置设为仅提示词，并省略“最大深度”。该正则只清理提示词文本，不负责生成面板；不要把它设置成仅格式显示。

### 参数与输出格式

| 参数 | 默认值 | 有效范围或含义 |
| --- | ---: | --- |
| 最大回复 token 数 | 65535 | 正整数，发给变量模型的输出上限 |
| 额外历史 AI 正文数 | 2 | 非负整数，不决定世界书扫描深度 |
| 温度 | 1 | 0–2 |
| 频率惩罚／存在惩罚 | 0 | 各为 -2–2 |
| top p | 1 | 0–1 |
| top k | 0 | 非负整数，0 不发送 |
| 最多请求次数 | 3 | 正整数，含首次请求，1 不重试 |
| 重试间隔 | 1000ms | 非负有限毫秒数 |
| 单次请求超时 | 300 秒 | 大于 0 的有限秒数，只约束模型请求 |

温度 1、惩罚 0、top p 1、top k 0 省略发送，由服务采用默认值；这不强制服务使用这些值。DVS 不继承正文模型当前的采样设置。非法输入会阻止保存和请求，合法值是否被服务接受以实际请求为准。

API 地址不能包含凭据、查询参数或片段，不自动补 `/v1`。额外请求体只能使用 JSON 对象和有限 JSON 值，不能覆盖 `model`、`messages`、`prompt`、`stream`、token 上限、采样、工具调用、`json_schema`、`chat_completion_source`、`custom_*` 或鉴权字段；密钥只填密钥框。`response_format` 由 DVS 按所选格式整体管理，`text` 时移除，不能用额外请求体绕过格式选择。

初始输出格式为 `text`，不发送 `response_format`，仍要求 DVS JSON 补丁；`json_object` 发送对象约束；`json_schema` 发送完整 DVS schema，使用 `strict: false` 以允许新增行省略默认列。三种格式最终都做本地协议和数据库检查，不根据模型名称自动推断支持，也不在失败后静默降级。

测试先检查连接，再分别检查 schema、object，选择本次最高通过格式。网络、认证、限流、超时或取消造成未完成时，不算格式不支持；测试只证明这次配置及请求，不保证以后输出正确。取消或超时只停止本次等待，不保证远端已停止生成或计费。

## 错误与保存

管理方法成功说明数据库已内存提交（当前 Worker 内已提交），SQLite 文件由 Helper 之后后台保存。聊天 fid 通过原生保存及固定文件读回确认。SQLite 与聊天文件不是同一事务。

| 情况 | 结果与处理 |
| --- | --- |
| 明确回滚 | 不保留失败写入 |
| 结果 unknown | 不重发 |
| 已提交但对象读回失败 | 报“数据库已提交、对象刷新失败”。相关对象禁止继续管理，请重新 `getState` 核对 |
| 初值已提交但聊天关联失败 | 不自动重跑 INIT。跨刷新无法保证恰好一次恢复，需要核对聊天与数据库 |
| 另一 Tab 已保存关联、本 Tab 仍缺 fid | 重新打开或刷新聊天后读取 |

完整入门卡见[青禾书店示例](../assets/dvs-minimal-card/README.md)；该卡只含世界书、开场白和注册脚本，不提供作者面板。

## 支持范围

DVS 用于单人聊天的普通生成、重新生成最新回复和新 swipe；完整 AI 正文成功后自动更新变量，停止或生成失败不启动。续写、冒充用户、群聊、工具递归和酒馆助手独立生成不在支持范围内。

历史状态只在当前聊天仍保留相应消息和 swipe 关联时可读，不能管理旧层。删除消息或 swipe 后，失效关联及没有引用的历史行会在成功变量更新达到清理周期时清理，不把数据库历史表视为永久审计记录。

完整备份恢复、聊天复制后自动取得独立身份、携带编号的角色或聊天导入，以及停用期间或酒馆外副本识别尚未提供。不要将复制或导入的聊天自动视为独立数据库，也不要仅复制 SQLite 文件就当作已完成角色、聊天和编号关系的恢复。数据保存、存储模式及插件更新见[使用与维护指南](helper-usage.md)。

提示词模板 Worker 后台编译方式的 DVS 最终正文注入未完成专项验证；约 10 MB、每秒一次写入与长期内存占用也没有专项性能结论。浏览器、模型或模板的其他版本不能由一份示例成功推定全部可用。
