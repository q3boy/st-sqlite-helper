# 林溪与青禾书店

一张最小 DVS 日常卡：林溪是24岁的书店店员，玩家是来客。只有基本人设、好感度、时间地点和随身物品，不含状态栏、地图、资源结算或自定义模型输出协议。运行内容只有世界书、一个开场白和一个 DVS 注册脚本。

## 导入和开始

1. 先按[安装与日常使用](../../references/helper-usage.md)准备 SQLite Helper 和酒馆助手，启用 SQLite 服务。这个示例用普通 DVS 宏，不要求 ST-Prompt-Template。
2. 在酒馆角色管理中导入 [card.json](card.json)。它由下面的源文件统一生成，不要手工修改导入包。
3. 核对角色名“林溪与青禾书店”及绑定的同名世界书。世界书有6条条目：DDL 和 INIT 关闭，人物设定、正文状态、更新规则、变量数据开启。
4. 在酒馆助手中核对附带的“青禾书店 DVS”脚本已启用，预设定变量 `dvs_enable` 为布尔值 `true`。如果导入时提示处理附带脚本，确认保留本卡的这一个脚本，不另装全局 DVS 服务脚本。
5. 打开插件的“DVS 模型配置”。还没有配置时面板直接显示“创建第一个模型配置”，已有配置时点「新增」；填写自己的地址和模型，密钥按服务需要填写，点「保存」。第一份保存的配置会自动用于“变量更新”；已有其他配置时，在“功能使用”的“变量更新”下拉框中选中它，选中即保存。「测试」会发送少量请求，可能产生费用。正文模型仍在酒馆自己的连接配置中选择。
6. 为这张卡打开一个新单人聊天，等脚本完成注册后检查下表初值。已有聊天不会因改写 INIT 自动重置。

| 表 | 业务键 | 开场白初值 |
| --- | --- | --- |
| 人物 | 姓名 | 林溪，好感度10 |
| 场景 | 编号 | 当前；2026-10-19 15:00；青禾书店 |
| 物品 | 名称 | 帆布包1个、书签2张；均为林溪随身物品 |

每张表还包含 DVS 用于关联历史版本的 `rid`。作者和模型用表中的业务键定位对象；不要在完整历史表中为这些业务键另建 SQL UNIQUE。

## 生成与检查结果

可以发送一句“我向林溪道谢，请她推荐一本适合雨天读的书”。酒馆先用当前状态生成正文，完整正文结束后 DVS 请求变量模型，再更新本条回复的数据。

回复末尾的“变量更新”面板显示模型的原始建议（读法见[作者手册](../../references/dvs-author-guide.md#查看变量更新面板)）；数据库中的实际值以查询为准，不将具体好感度变化当成固定答案。使用插件已有查看器可以查看文件、表和历史行；查看本条回复的有效状态，在酒馆助手脚本中运行：

```js
await waitGlobalInitialized('DVS');
const state = await DVS.getState();
console.log(await state.table('人物').get('林溪'));
console.log(await state.table('场景').get('当前'));
console.log(await state.table('物品').orderBy('名称', 'asc').rows());
```

同一张业务表保留多个历史行，查看器中直接列出全部行不等于当前楼层状态；`getState()` 按最近 AI 回复当前 swipe 的有效索引查询。内存查询成功与文件保存是两种证据。确认保存时等待后台处理、正常关闭服务并重新打开同一聊天，再查询这些值；开发模式可以在服务关闭后只读核对实际数据库文件。

生成一轮新正文后，可以点“变量更新”面板中的「重新更新」，或调用 `await DVS.regen()`，只重新计算这条正文的变量，不重新写正文。它仍从该回复之前的 AI 状态出发，重复执行不会从上一次更新结果继续累加；正文重新生成或新 swipe 同样按对应起点处理。**只有开场白时的 regen 从空状态开始，不重跑 INIT**，因此不能用它检查本例固定初值。详见[作者手册](../../references/dvs-author-guide.md#检查一次完整更新)。

本例没有开启可选的输入增强，六个世界书条目即可完成正文注入与后置变量更新。要在自己的卡中让模型先规划本轮剧情，再筛选资料，按[作者手册的完整示例](../../references/dvs-author-guide.md#可选正文资料筛选与剧情规划)增加配置；仅在模型设置中选择输入增强配置不会自动开启卡片开关。该功能产生的是正文参考，不提前改写数据库。

## 源文件怎样配合

| 文件 | 内容 |
| --- | --- |
| [index.yaml](index.yaml) | 内容组织、文件引用、条目开关和顺序、助手脚本变量 |
| [welcome.txt](welcome.txt) | 唯一开场白，与 INIT 的初值一致 |
| [worldbook/person.txt](worldbook/person.txt) | 唯一人物的静态设定 |
| [worldbook/ddl.sql](worldbook/ddl.sql) | 三张表、字段和业务约束 |
| [worldbook/init.sql](worldbook/init.sql) | 新聊天默认开场白的初值 |
| [worldbook/narrative.txt](worldbook/narrative.txt) | 正文宏状态输入 |
| [worldbook/rules.txt](worldbook/rules.txt) | 只更新已发生事件的规则 |
| [worldbook/data.txt](worldbook/data.txt) | 变量模型读取的起点数据宏 |
| [dvs.js](dvs.js) | 注册业务键、两个必需准备回调和卸载释放 |

改人物时同步设定、开场白、INIT、规则及查询用的业务键；改字段时还要同步 DDL 和相关规则。已有聊天需要新版本迁移，不能靠修改旧 DDL／INIT 重建；先学会[最小卡的改造流程](../../references/dvs-author-guide.md)，再按需阅读[接口与进阶用法](../../references/dvs-api.md)。

普通作者可以在酒馆的角色、世界书和助手脚本编辑器中修改对应内容，再使用酒馆原生角色卡导出功能保存自己的卡，不需要访问开发仓库。这里的 `card.json` 是这些源文件的生成结果；维护者统一重新生成后再分发，不把导入包手改成另一份来源。
