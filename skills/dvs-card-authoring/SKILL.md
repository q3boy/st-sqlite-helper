# DVS 卡片开发

交付作者需要的卡片文件与核对结果。采用用户已有的设定和文件组织，只设计确实会随剧情变化的数据；好感度、物品等是示例的选择，不是每张卡的必需系统。

## 按任务读取资料

先读用户提供的文件，判断本次是新卡、已有卡修改还是错误检查。已确定的要求直接沿用，只询问影响结果且无法从文件确定的信息。

| 当前任务 | 读取与使用 |
| --- | --- |
| 新卡或首次接入 | 读[作者手册](references/dvs-author-guide.md)，按需参考[最小卡源文件](assets/dvs-minimal-card/README.md)，将示例业务改为用户自己的内容 |
| 已有卡调整 | 对照实际设定、SQL、规则和脚本，查[接口参考](references/dvs-api.md)相应章节；涉及已有聊天的字段变化时必读“角色卡升级” |
| 更新或查询错误 | 对照[接口参考](references/dvs-api.md)中的对应方法、输入与错误；只有涉及原生数据库调用时再查[Helper 接口](references/helper-api.md)、[SQL 与保存](references/helper-sql.md)和[错误说明](references/helper-errors.md) |

参考指南中的导入、模型配置和酒馆运行步骤供交付说明使用，本 skill 不执行这些操作。接口以本包参考为准，来源见 `source.json`；需要包外酒馆助手能力时核对用户版本的官方资料，不推测方法名。

## 完成内容与数据接入

1. 把静态设定与动态状态分开。明确每个动态字段的含义、类型、单位、初值、更新依据，以及模型判断和代码计算的分工。固定公式由代码计算，模型只记录规则要求的事实。
2. 对照设定和开场白写 DDL、INIT 与业务键。真实表的 `rid` 使用 16 字节 BLOB 主键；业务键只在一份有效状态内唯一，不为历史表的业务键增加全表 SQL `UNIQUE`。SQL 条目使用准确的 `[DVS_DDL]v版本`、`[DVS_INIT]welcome_编号`，按参考登记开关及开场白对应关系。
3. 组织普通设定、正文状态、变量规则和起点数据条目。规则说明事件如何改变字段，实际起点由 DVS 宏提供；DVS 自带补丁协议，无需另写一套模型输出格式。条目名称、开关、激活条件、位置和顺序须能从文件核对。
4. 使用角色卡绑定的一个注册脚本，布尔变量 `dvs_enable: true`；等待 DVS 后以自身 `getScriptId()` 注册，按实际生命周期释放。必须提供 `narrativePrepare` 和 `beforeGen`；无额外业务处理时直接返回收到的 `tables`。虚拟表、订正和后处理只在本次确有用途时添加。
5. 已有卡只修改受影响内容。字段变化同步 DDL、各开场白 INIT、规则、相关回调和查询；已有聊天用更高版本的迁移，保留历史数据与关联。新聊天初始化和旧聊天迁移分别说明，不能用删除数据库或重跑 INIT 代替升级。

## 核对并交付

逐项核对设定、开场白、初值、表名、完整业务键、字段、世界书标签及脚本是否一致。按本次改动执行可用的语法、类型或 SQL 检查；没有运行条件的部分给出具体检查步骤。

正文和变量请求使用回调收到的起点，避免无条件调用 `getState()` 换成当前最新状态。重新生成普通回复和 `regen()` 从该回复之前的 AI 状态计算；开场白的 `regen()` 从空状态开始，不重跑 INIT。检查模型建议的表、键、字段和代码计算，具体业务数值判断只作观察。

只交付任务需要的可编辑文件。若附带生成的导入包，须与源文件同步；无法生成时明确交付源文件和后续打包说明。报告已做检查、未做检查及影响，区分内存查询、文件保存与真实酒馆验证，不把静态检查说成已运行成功。

范围止于卡片内容与 DVS 业务代码。状态栏、HTML/CSS 美化、插件构建发布、酒馆部署同步导入、浏览器操作、密钥或模型配置，以及真实角色聊天和数据库操作均不属于本 skill，也不调用其他 skill 代为执行。
