# 使用与维护指南

本文说明怎样安装和更新插件、选择存储模式、查看与清理数据，以及遇到故障时怎样处理。玩家、脚本作者和卡片作者的阅读路径见[使用导航](../../dvs-docs/references/usage-index.md)，脚本调用见[业务侧使用指南](helper-author-guide.md)。

## 安装与更新

酒馆sqlite助手（SQLite Helper）是酒馆前端扩展，必须安装并启用[酒馆助手 JS-Slash-Runner](https://github.com/N0VI028/JS-Slash-Runner)。

最低要求为 SillyTavern 1.18.0、酒馆助手 4.11.0。插件每次页面加载时自动检查；版本不足时，一个弹框列出所有需要升级的项目，插件设置栏只显示相同提示。当前页面不启动 SQLite Helper 和 DVS，原有启用设置保持不变。关闭弹框后本页不再自动提示；升级后刷新页面即可重新检查，不需要重新勾选启用。

正式安装地址为 [q3boy/st-sqlite-helper](https://github.com/q3boy/st-sqlite-helper)。安装前确认该仓库根目录包含 `manifest.json` 的完整扩展包；只有项目介绍时不能安装。在酒馆扩展管理的安装入口填写此仓库地址；无需克隆开发仓库或运行构建命令。

卡片作者可随卡附带[安装引导脚本](../../dvs-docs/references/installer-guide.md)，让缺少插件的玩家确认安装，或在正式 Git 版有更新时确认更新；支持 JSON 导入和 JS 打包两种方式。

仅使用 SQLite Helper 或普通 DVS 宏不要求安装提示词模板。使用 EJS／`dvs_state` 模板查询时才需要安装并启用 ST-Prompt-Template，具体写法见[DVS 作者手册](../../dvs-docs/references/dvs-author-guide.md)。

插件启动时统一关闭提示词模板的「后台编译（Worker）」并保存设置，避免编译等待阻塞消息渲染和变量更新。模板仍在页面内编译；未安装提示词模板或该选项已关闭时跳过。

- 扩展在酒馆主页面建立服务，通过助手发布 `SqliteHelper`，同时挂载管理栏和查看器。
- 业务脚本继续使用 `waitGlobalInitialized('SqliteHelper')`。
- 无需另装 SQLite 助手服务脚本。

当前源码配套公共 API 30、通信协议 27、管理结构 6。页面与执行 SQL、读写文件的 Worker 版本不配套时，业务收到 `SYS_VERSION`。此时须更新同一次完整构建，再刷新页面。

### 浏览器要求

| 能力 | 用途 |
| --- | --- |
| sql.js/WASM、IndexedDB 配置存储 | 需要实际加载和读写成功 |
| SharedWorker／普通 Worker／页面内运行 | 自动设置检测哪些方式可用；页面方式无需 Worker |
| OPFS 异步文件读写 | 游玩模式需要；不可用时可选兼容模式（IndexedDB） |
| `showDirectoryPicker` 和文件读写接口 | 制卡模式选择目录时需要，实际授权由用户完成 |

HTTP＋IP 不统一禁止运行；浏览器限制由实际检测和读写结果判断。启动或保存失败不会自动更换正在使用的方式，不会重发 SQL。

### 自动设置与工作模式

工作模式和存储模式保存在当前浏览器，不跟随酒馆服务器设置同步到其他浏览器。本浏览器还没有设置时（包括从旧版升级后第一次打开），SQLite Helper 和 DVS 都不启动。服务已开启时，页面载入后会自动弹出「自动设置」窗口；服务关闭时可在设置栏“模式选择”中随时点「自动设置」。

1. 自动设置窗口按共享、独立、页面内逐行检测，九宫格显示每种工作模式与存储模式的组合是否可用。检测期间可点「终止检测」，终止后原设置和原检测结果不变。
2. 检测完成后点「使用推荐设置并刷新」，插件保存推荐的工作模式和存储模式，确认成功后自动刷新当前页面，无需再点一次「保存」。保存失败时留在窗口显示原因，不刷新。
3. 刷新后服务按新设置启动；其他已打开的酒馆页面仍需各自刷新。从设置栏手动打开「自动设置」时也采用这一流程。

之后可随时点「查看检测详情」查看上次结果，或手动改选后保存。检测结果中不可用的选项不能选，悬停或点按可看原因。

| 工作模式 | 运行位置 |
| --- | --- |
| 共享 | SharedWorker 后台实例，同一浏览器的多个酒馆页面共用 |
| 独立 | 当前主页面持有普通 Worker，只支持单页面 |
| 页面内 | 在当前页面执行，较大操作可能短暂卡顿，只支持单页面 |

工作模式和存储模式都在保存后刷新生效；切换前关闭其他同源酒馆页面。DVS、业务脚本、角色卡 iframe 共用当前页面服务，不单独检测或启动实例。页面模式代码更新也需刷新，普通断线复用存活的页面内核。

普通 Worker 与页面模式的默认发送和保存防抖均为 100ms，SharedWorker 分别为 3000ms／1000ms。防抖不是保存期限；连续修改会重置等待。刷新可能丢失尚未发送或未保存的修改，不在刷新前补存或重发 SQL。

### 安装后的首次使用

1. 安装完整扩展后刷新酒馆页面，同一酒馆只启用一个 SQLite Helper 版本。
2. 在扩展设置展开“SQLite Helper”，确认“SQLite 服务”为开启。新配置默认开启，若先前关闭过，重新开启后需刷新。
3. 按[自动设置与工作模式](#自动设置与工作模式)完成自动设置、保存并刷新。选了制卡模式时，刷新后再按下文选择目录。换扩展目录不会隔离数据库。
4. 需要 DVS 自动更新变量时，按[DVS 模型配置](../../dvs-docs/references/dvs-author-guide.md#配置变量模型)填写参数。独立 Helper 脚本不需要配置变量模型。

误启用多个版本时，包含启动保护的版本会跳过重复启动，同一页面保留最先启动的插件。要指定使用哪个版本，请在酒馆扩展管理中停用其他版本后刷新；启动失败也需处理原因后刷新。旧版没有此保护，混用旧版仍可能冲突。

### 更新步骤

1. 阅读更新说明，保留重要数据的现有备份；插件尚不提供完整备份恢复，导出角色卡或聊天不等于备份 SQLite 数据。
2. 等待本轮修改完成并核对保存提示，再关闭服务，确认 Worker 已退出。设置保存成功不等于 Worker 已退出。关闭受阻时先处理界面显示的原因。
3. 完整包发布后，通过酒馆扩展管理更新正式扩展。不要混用不同构建的页面、Worker、资源或类型声明；更新期间不要加载或刷新，全部更新完成后再刷新所有相关页面。
4. 在“高级选项”核对页面和 Worker 构建一致，按需要重新开启服务并刷新。

旧 Worker 若因旧退出规则受阻，更新资源不会改变它。处理顺序：

1. 停止在线升级。
2. 结束旧连接会话，确认实例结束。
3. 加载新版。

不要另开 Worker 并行写同一目录。

## 启用服务与授权目录

### 存储模式

| 模式 | 数据位置 | 授权 |
| --- | --- | --- |
| 游玩 | 当前浏览器、当前酒馆站点的 OPFS，高性能 | 无需选择或授权目录 |
| 兼容 | 当前站点 IndexedDB 中的 SQLite 二进制，性能略差 | 无需目录授权 |
| 制卡 | 本地授权目录，适合制卡时通过其他工具读写 | 刷新后在“制卡高级设置”中选择目录；默认开启“外部修改后自动重新加载” |

- 存储模式与工作模式一起保存，刷新页面后生效，运行中不切换。启动失败会明确提示，保存不代表存储已经可用；各处数据保留且不自动迁移。
- 浏览器或站点变更也不会自动搬运数据。

### 启用或关闭服务

在酒馆扩展设置中展开“SQLite Helper”。“SQLite 服务”的开启／关闭保存到酒馆扩展设置。有修改还没写入存储时，控件下会提示“现在关闭服务或刷新页面可能丢失”。

| 操作 | 结果 |
| --- | --- |
| 开启 | 刷新本页面才启动服务，旧页面和旧代理不会自动恢复 |
| 关闭 | 停止接收新调用；已接收 SQL 和已开始的文件写入结束后退出 Worker；尚未开始的后台保存取消，未落盘修改可能丢失 |
| 关闭时工作仍在执行或保存 | 界面说明原因并保留 Worker；关闭受阻不能解释为写入已取消 |

其他 Tab 每 10 秒读取设置，已接受这段生效时间差。

### 授权制卡目录

- 展开“制卡高级设置”，点击“管理目录…”查看目录及可用状态。
- 首次选择建议使用专用空目录。
- 原目录失去权限时，点击“重新授权”并允许访问原目录。
- 浏览器限制的目录选择和权限确认须由用户亲自完成，代理不能代点或绕过。
- 插件还会核对权限和实际读写，浏览器允许访问不等于数据可用。

### 缺少授权时业务调用怎样处理

| 场景 | 行为 |
| --- | --- |
| 仅制卡模式缺少目录或权限 | 业务调用等待用户授权，默认每次 120 秒。等待期间不执行 SQL，也不开始计算写入发送前的等待时间 |
| 授权取消、拒绝、失败或超时 | 结束这次调用。后来授权成功不会恢复已结束的调用 |
| 打开聊天时的后台编号检查 | 缺权限时不自动弹窗 |
| 浏览器存储不可用 | 直接报告原因，不引导目录授权 |

### 切换目录

- 切换目录会改用新目录的数据，原文件保留，不自动复制。
- 插件等待本页面已接收 SQL 及已开始的文件保存结束，并取消旧实例未开始的后台保存。
- 切换错误未处理时，不报告切换成功。
- 旧代理不能转投新目录，业务须重新取得代理。

授权等待的业务行为见[公共接口契约](helper-api.md#未授权时的调用)。

## 查看数据与调试

### 外部修改后重新加载

制卡模式下，用外部工具保存修改后，可在“制卡高级设置”选择全局、当前角色或当前聊天点击“重新加载”，从目录中已保存的文件重新读取。

| 方式 | 触发条件 |
| --- | --- |
| 自动加载 | “外部修改后自动重新加载”开启时，每 2 秒检查已打开的库，mtime 变新或大小改变时加载 |
| 手动加载 | mtime 未变新且大小相同的修改，只能手动加载 |

- 普通查询不改变文件基准，插件自身保存会更新基准。
- 手动加载，或实际检测到外部变化后的重载，会丢弃尚未保存的内存修改。
- 未加载的库不因自动检测而打开。
- 开发者自行控制外部修改时机，先确认实际文件已经取得所需修改。业务 Promise 只确认当前内存事务提交，不确认文件保存，见[保存契约](helper-sql.md#事务和保存)。

### SQLite 数据库查看器

从酒馆菜单打开“SQLite 数据库查看”，查看已有全局、当前角色、当前聊天数据库和文件信息。

- 查看器只读：不补编号、不建库、不升级管理结构。
- 从未初始化时显示“尚未初始化”。
- 同一 Worker 首次内存提交后可以查看表数据，此时文件尚未创建，文件信息会明确说明“未创建”，不伪造保存时间或大小。新的 Worker 只按文件和登记事实判断。
- 表过大或整数不能准确表示时拒绝预览，不返回截断或舍入的数据。

切换角色或聊天会关闭查看器，重新打开才读取新对象。旧响应不会更新已关闭窗口。

表列表默认只显示业务表。查看系统表：

1. 在“全局”页表列表末尾勾选“显示系统表”。
2. 页面显示插件内部普通表及 SQLite 内部表，名称前带 ⚙️ 前缀，实际表名和 SQL 不变。

补充说明：

- 收起表列表时复选框也隐藏，重新展开可操作。
- 重新打开查看器恢复默认。
- 角色和聊天页始终隐藏系统表。
- 勾选不修改数据，也不保存设置。

### 业务调试记录

“维护与调试”中的“业务调试记录”开启／关闭控制 SQL、通信记录及右下角“调试”面板。

- 关闭会清空记录，重新开启不补历史。
- 记录容量有限，不能作为完整业务账本。
- 开关不改变 SQL 结果。
- 正式版默认关闭业务调试，仍可手动开启；内部诊断面板不显示。
- 调试入口和已打开的调试面板与原生输入区横向重叠时，会移到输入区上方，避免遮挡发送／停止按钮；输入区高度变化时跟随调整，宽屏互不重叠时仍在右下角。
- 窄屏扩展设置抽屉会为调试入口留出底部空间；设置内容可以滚动到底，两个入口仍可直接点击。

业务调试只用于观察，不代替写入结果或文件保存确认。

## 扫描与修复

聊天编号丢失或与原数据不一致时，“扫描与修复”可以恢复能够确定的关联，保留原业务数据；删除角色或聊天后，也可以清理用不到的数据库、空目录和管理记录。先只读扫描、查看建议并选择项目，再点“执行”查看逐步清单，最后点“确认执行”才会修改。

管理登记、角色／聊天库身份，以及能够保留内容的 DVS 系统表可以修复。版本或历史已丢失时不会猜造旧数据；工具会列出无法保留的内容，只有你另行确认损失后才会重建或“重新开始使用”。读取失败、目标归属未确定或未知结构无法安全处理时，保留原数据并显示原因。

### 扫描

1. 先停止生成，关闭其他酒馆标签页。处理期间不要在酒馆中删除、改名或导入角色和聊天。
2. 在“维护与调试”中点击“数据库清理与修复”，再点击“开始扫描”。服务须启用且当前存储可用，制卡模式还需目录授权。

扫描只读取当前模式的存储目录、管理记录和必要的酒馆信息，不修改任何数据，不跨存储寻找数据库。发现没有有效归属的聊天库时，才按候选查找对应聊天；普通无编号、没有插件文件的聊天不会因此获得新编号或数据库。查找失败或停止时保留相关数据，不把“没找到”当作可以删除。

### 读懂结果表

每一行是一个必须一起处理的最小单元，例如一个要恢复关联的聊天、一个无用文件、一个空目录（含其中的空子目录），或已删除角色和它下面的聊天库。默认勾选表示建议，所有建议都可以取消：

| 列 | 内容 |
| --- | --- |
| 执行 | 复选框决定是否处理；“—”表示当前暂时无法处理 |
| 操作 | 修复登记、修复结构、恢复关联、重新开始使用、清理残留或暂时无法处理 |
| 类型 | 系统库、角色库、聊天库、文件或其它（如空目录） |
| 对象 | 角色或聊天名称；具体文件坐标、路径和内部编号在“详细信息”中查看 |
| 说明 | 当前问题、将做什么及对数据的影响；展开“详细信息”可看具体原因和处理范围 |

已勾选的行带有醒目底色和左侧色条。误改勾选后可点“恢复默认”恢复尚未执行项目的系统建议。详情默认收起，正常的角色、聊天和数据库文件只显示数量。

| 常见行 | 默认 |
| --- | --- |
| 能够保留现有内容的管理登记结构问题 | 勾选，修复登记；完成后重新扫描 |
| 能确定归属且可保留内容的本库身份或 DVS 结构问题 | 提供结构修复；先备份，完成后重新扫描 |
| 能确定原数据归属的聊天关联缺失、非法或冲突；可补齐的相关登记 | 勾选，恢复关联并保留原业务数据 |
| 已确认没有用途的空目录、已删除聊天留下的残留、只剩管理记录的对象 | 勾选，可取消；共用数据保留 |
| 管理记录已确认角色删除，且其下没有聊天数据库 | 勾选；只有列表找不到旧角色文件名时不勾选 |
| 来源不明文件；角色已删除但保留聊天的整组；查找后仍没有对应对象的初始化登记 | 不勾选 |
| 已确认目标的数据缺失、损坏或历史丢失 | 不能冒充恢复；能够安全重新开始时提供单独操作，须确认具体损失 |
| 读取失败、查找未完成、归属不确定或不支持的结构 | 暂时无法处理，保留相关数据 |

没有管理登记的数据库不会自动删除：工具先查找可恢复关系，不能确认用途的文件默认保留。需要清理时展开详情，核对具体文件后自行勾选。已发现仍被聊天使用的数据，不会因取消关联修复而转为删除。浏览器写文件时的临时文件（`.crswap`）不列出、不删除。

工具按原文件位置、登记和现存数据库决定如何恢复，不要求你选择编号。唯一有效原登记对应的数据仍可用时优先恢复到它；另一份数据保留，不合并也不随修复删除。原数据仅需身份或结构修复时先处理并重扫，不因另有一份正常数据就放弃原数据。多个候选无法确定归属时不猜选。

管理库（`global.sqlite`）需要处理时，只列管理库项目，其他文件保留。已有存储的管理库加载失败时仍可进入扫描维护；这不改变新目录加载失败后保留原配置的行为。能无损修复的直接提供修复；其余检查可保留的业务表、设置与确定关联，列明损失后才允许重建。文件缺失或字节已读出但无法打开 SQLite 时，也可以在确认损失后重新建立管理库，角色／聊天库保留。未知管理版本、外部表依赖或原文件读取失败仍拒绝处理。完成后须重新扫描，才会列出新的关联和清理项目。

结构修复保留合法的作者成功版本和已有楼层历史，不运行作者初始化。缺失或非法的 DVS 清理计数可以归零；无效标识、完全重复或已确认没有业务行的索引可以移除。不会仅凭当前分支消息删除其他历史索引，也不能在没有作者索引声明时猜出哪些历史表丢失。

“重新开始使用”会明确显示影响：重置已确认的角色／聊天库将移除原文件并使旧代理失效，下一次正常业务写入才建立新库；角色库重置不删除其下聊天库，共享聊天库的全部引用共同受影响，酒馆消息保留。归属无法恢复时另有默认不选的新编号操作，它保留全部旧 SQLite 文件，将指定聊天或整个角色改用新的插件数据。选择整个角色时会列出该角色全部聊天，包括尚未使用过插件数据的聊天，并先备份聊天原文；聊天列表或原文有变化时须重新扫描。两种操作都不恢复旧内容，执行前以清单为准。

### 下载备份

“下载备份”按当前勾选且尚未执行的项目打包：加入将删除的原 SQLite 文件，保留相对路径；恢复聊天关联时还加入服务器上的聊天原文档；会修改管理登记时包含原 `global.sqlite`。只补聊天编号且登记已正确时，不打包整个全局库。

`global.sqlite` 中可能有 DVS 模型配置的 API 密钥，请妥善保管。任一文件读取失败时不生成不完整的包。下载不是当前关联修复或清理的执行前提，不改变选择，也不代表插件已经提供备份导入恢复。

管理表重建、目标库结构修复和重置有单独的备份门槛：在执行确认区生成并下载本次原文件备份，工具会先等待相关已接受修改保存、读回确认，再生成包含原 SQLite 和处理清单的 ZIP。提示“备份已生成并发起下载”不等于浏览器已经保存文件；请确认下载完成并妥善保存后，勾选“我已确认备份文件已保存”，才可继续执行。已缺失的文件无原文件可备份，界面须先确认缺失；有损操作还要勾选损失确认。单纯管理索引／视图修复不要求这一步，也不为此暂停全部业务。

### 执行

1. 点击“执行”：先在表下方列出将按顺序进行的每一步，这时还没有修改任何数据，可以“复制清单”。
2. 核对后点击“确认执行”才开始处理；点击“返回修改”或改变勾选会收起清单，需要重新点击“执行”。

项目逐项处理，关联恢复先于清理。每一步和每一行都显示实际结果，可以展开查看。处理前再次核对原记录、存储配置、文件和共享引用，扫描后发生变化时停止该项并要求重扫。

结构维护单独处理，不与旧清理清单连续执行。准备与执行各自暂停相关目标接收新业务，等待必要保存最长 10 秒；管理库重建涉及整个当前存储，角色／聊天库维护仅涉及该物理目标。等待超时或保存失败时停止本次维护并保留内存实例，不丢弃修改继续重建。执行时会比较完整文件与备份的摘要，发生变化就要求重扫并重新备份。准备与执行之间不会一直阻止使用；这是维护内部保存确认，不新增业务 `flush` 方法。

管理表重建成功后，原配置绑定和旧代理失效；目标重置也使受影响的旧引用失效。结果面板会保留完成说明，请重新扫描取得新清单。需要业务代理时重新取得，DVS 上下文仍需刷新时按提示刷新。所有结构修复均核对实际保存文件，不能直接在修复前的清理集合上继续。

恢复关联只调整聊天中插件自己的字段和必要管理登记，不改业务库内容。当前聊天复用酒馆原生保存，保留当前消息和其他元数据；非当前聊天按原文件位置读回完整文档后保存，原文件不存在时停止，不重建历史聊天。原登记已正确时不重写全局库。清理只删除确认清单内的插件记录、文件和空目录，不删除角色卡和聊天正文。

| 操作或情况 | 结果 |
| --- | --- |
| “停止扫描”或关闭窗口 | 已经开始的读取会结束，然后停止；结果标注为不完整 |
| “停止执行” | 已提交的一项照常结束，不再提交下一项。停止不能撤销已完成的删除 |
| 某项失败、被跳过或保存结果未知 | 已尝试的项目不能直接重复执行。先按提示解决权限、连接等原因，再重新扫描，按新的事实继续；未开始的独立项目可以继续 |
| 聊天关联已保存，但插件登记未完成 | 显示部分完成，保留已保存结果；重新扫描后继续，不重复发送旧写入 |
| 整组中角色库删除失败 | 角色已在管理记录中标为删除、其下聊天改为保留，这一修改不撤销；聊天库和记录保留，重新扫描后可再处理 |

扫描不保证所有结果来自同一瞬间，也不在后台定时扫描。需要重新取得代理或 DVS 上下文时刷新页面；恢复后应只读核对原业务数据，不重新运行初始化来证明恢复。

## 文件、升级与备份

数据库保存在 OPFS 专用 `st-sqlite-helper` 子目录、本地授权目录或 IndexedDB 的 `files` 仓库；IndexedDB 以相同相对路径作为 key。路径由角色编号 `char_dbid` 和聊天编号 `chat_dbid` 决定；它们不是楼层或分支编号：

| 数据范围 | 文件 |
| --- | --- |
| 全局 | `global.sqlite` |
| 角色 | `characters/<char_dbid>/char.sqlite` |
| 聊天 | `characters/<char_dbid>/chats/<chat_dbid>.sqlite` |

不要这样做：

- 手动改编号，或移动文件来让旧代理匹配新对象。
- 让外部程序与 Worker 同时修改文件。

相关行为：

- 角色编号只认当前存储 `global.sqlite` 中“角色卡文件名 → 编号”的登记。插件不读取、不写入、不清除角色卡上的编号字段，卡片上已有的旧字段被忽略。
- 使用酒馆“替换／更新”导入新版卡后，只要文件名不变，就继续使用该存储中原有的登记和数据，卡片带什么编号都不影响。
- 酒馆复制角色得到新文件名，就是新角色，首次使用时独立登记，不复制原角色的数据库。
- 正常使用中，首次写入或打开聊天时的后台准备会为没有登记的角色建立编号，建立前先确认角色文件仍在酒馆角色列表中；普通 `getHandles`、查询和查看器不分配编号。扫描确认的关联恢复可以根据现存聊天与数据库补回能够确定的登记，不是普通查询的隐式修复。
- 各存储空间各自登记，同一张卡可能使用不同的角色编号，切回原存储继续使用该存储中的原登记。
- 插件未运行时在酒馆内改名的角色，无法与原登记关联：新名字按新角色处理，原名字下的数据保留，交给扫描。
- 聊天编号保存在聊天文件中；聊天分支可以共享编号，分支隔离由业务处理。
- 聊天复制后的独立身份、导入聊天所带编号的处理，以及停用期间或酒馆外产生的聊天副本识别尚未提供。不能把复制、导入当作数据库迁移或隔离办法。
- 制卡模式中需要外部修改文件时，由开发者控制时机：先确认文件已经取得所需修改，再修改并保存，最后重新加载。
- 正常关闭不会强制保存所有内存修改。

### 管理结构

- 当前全局管理结构为版本 6，使用 `__stsh_` 前缀，维护 meta、roles、chats、targets 四张表。
- 版本只表示插件管理结构。
- 它不保存完整名字历史、每次 SQL 指纹，也不保存改名、删除、清理的完整过程任务。

不提供旧版管理结构的自动转换，不用初始化覆盖不受支持的版本。已知管理结构、确定的本库身份与 DVS 表问题从“扫描与修复”处理；无法恢复的设置、业务内容或历史必须明确列出，重建或重新开始均需额外确认。它们不替代完整备份恢复，具体操作见[扫描与修复](#扫描与修复)。

### 回退与备份

- 回退需要匹配的旧文件和旧构建，旧代码不能写新结构。
- 完整备份恢复尚未实现。临时文件备份不等于产品恢复能力，复制角色卡或导入聊天也不自动恢复对应数据库。

## 遇到故障时

1. 先看主提示，再展开“查看详细原因”。
2. “高级选项”提供版本、重新连接和安全重启。
3. 先检查目录、权限和配套版本。
4. 不要直接重做未确认写入，也不要删除数据库消除错误。

| 情况 | 处理及影响 |
| --- | --- |
| 环境版本检查未通过 | 按提示升级酒馆或助手。无法读取版本、助手等待超时等情况不等于版本过低，请检查酒馆连接及助手是否安装、启用且加载成功后刷新页面；同一页面不会自动重试 |
| 业务接口发布失败 | 环境检查通过后，发布接口仍可能抛错。展开详细原因，处理后刷新；管理界面保留不代表业务接口可用，控制台和诊断保留原因 |
| 服务停用 | 开启并刷新相关页面；旧代理不恢复，已接收写入不因此取消 |
| 尚未完成设置 | 点「自动设置」，检测完成后点「使用推荐设置并刷新」 |
| 原目录需要授权 | 重新授权原目录，继续使用原文件；不要静默换目录 |
| 目录可访问但数据不可用 | 检查读取、保存错误和空间；不能推断文件完整或自动建新库 |
| 页面与 Worker 版本不一致 | 更新完整配套构建并刷新；安全重启受阻先处理具体原因，不开第二个 Worker |
| 数据库尚未初始化 | 由业务执行必要首次写入；查询和查看器不会建库 |
| 原文件缺失 | 核对原目录和备份，保留错误信息；插件拒绝自动重建 |
| 后台保存失败 | 查看文件结果和内存是否仍可用，检查权限、磁盘空间及诊断；不要重发已经提交的 SQL，关闭或重载可能丢失未保存修改 |
| 提示 SQL 内存已提交但调用未完成 | 不重复提交，保留详细信息，停止依赖正常返回结果的后续流程 |
| 提示 SQL 已保存但调用未完成 | 保留详细信息，停止依赖正常返回结果的后续流程，不再次提交已保存 SQL；普通调用没有操作 ID |
| 改名或删除尚未确认 | 保留原对象和错误信息，按具体原因核对；不按当前选择猜目标，相关新调用受阻不表示原 SQL 已取消 |

重新连接只为后续调用准备，不重发已经发送的 SQL。写入执行结果未知时，保留输入并核对当前业务数据，不直接重做或补偿。

公共错误含义见[错误说明](helper-errors.md)。删除角色后，酒馆可能仍保留聊天文件；插件的数据清理不负责删除这些酒馆文件。
