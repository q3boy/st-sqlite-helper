# 生成拦截

## 制作生成拦截界面

例如玩家邀请新访客进入书店，先打开作者界面生成、调整并确认资料，再继续正文。DVS 负责条件判断、交互等待、结果保存和正文接续；作者负责界面、请求及结果含义。

在卡片已有的 `DVS.register` 中加入 `preNarrativeUi`，保持原业务键和准备回调。注册项的 `condition` 是交给输入增强模型判断的自然语言条件，数组顺序决定多个命中时的优先级。显式启用 `dvs.exts.pre_narr_ui`，并为输入增强选择模型配置；剧情规划可以独立关闭。接线与组件例子见[生成拦截接口](../../dvs-docs/references/dvs-api.md#生成拦截)和[原生 DOM 示例](../../dvs-docs/assets/dvs-pre-narrative-ui/README.md)。

| 作者实现 | 要完成的操作 |
| --- | --- |
| `mount(container, context)` | 显示候选与操作，处理等待和错误；从可选 `context.result` 恢复已保存结果 |
| `mountResult(container, result)` | 独立显示只读摘要，不发模型请求；按胶囊容器组织文字与布局 |
| `toPrompt(result)` | 把确认结果转为正文补充文本，不重新生成候选 |
| `buttonText` | 可选的胶囊重开按钮文案，例如“查看/重新生成 NPC” |

弹层由 DVS 承载，标题、内容、样式及取消按钮由组件提供。交互与摘要分别返回卸载函数，清理各自的框架实例、监听和定时器；异步操作遵守 `context.signal`。不引用插件内部框架实例。

## 组织组件请求

作者可以用普通对象组织多组同步或异步函数；`initial`、`regenerate` 只是示例名字，DVS 不限定它们。函数先完成取材和逻辑组装，统一发送处再展开消息中的 DVS 宏，随后调用 `context.requestModel()`。它复用输入增强模型配置，并按 DeepSeek／Gemini 规则附加输入增强 head/tail，作者无需重复拼接。

按请求用途使用 `context.prompt.prevNarrative()`、`userInput()`、`plotPlan()` 或对应宏。重新调整通常还需要当前候选与新要求；需要连续保留要求时，将本次交互历史按原顺序提供。哪些内容进入最终结果由业务决定，不因使用多轮请求就保存全部临时历史。

用 `context.worldbook.getEntries(['访客生成规则'])` 读取当前角色绑定世界书中的条目，名称去掉 DVS 标签。它返回全部精确同名条目，包括禁用或未激活的内容；不展开宏、执行 EJS 或删除筛选声明。把条目作为生成规则时，先移除不适用的 `[[DVS_FILTER:...]]` 等控制内容，再组装请求。返回顺序、字段与宏方法见[读取世界书条目](../../dvs-docs/references/dvs-api.md#读取世界书条目)。

请求返回 `{ content, finishReason }`，作者按业务格式解析后展示。请求失败时显示错误并保留可继续操作的候选，允许按界面需求重试或取消；只有最终确认才调用 `complete(result)`，结果必须是 JSON 值。

## 确认与正文交接

`complete` 把结果交给 DVS，不表示已经保存。DVS 确认消息保存后，才调用 `toPrompt` 并继续正文。

| 正文需要什么 | 使用方式 |
| --- | --- |
| 已确认的人设、购买明细或其他资料 | `toPrompt(result)` 返回文本 |
| 原样输出标签、采用确认结果等执行要求 | 注册项提供可选非空 `insist`，替换默认执行要求 |
| 确认后排除自动生成规则 | `narrativeEntriesSkip` 填去掉 DVS 标签的条目名，只屏蔽本轮正文 |

例如 NPC 已由玩家确认，可以屏蔽正文中的自动生成人设规则，并要求在正文末尾原样输出完整人设块，供原有变量更新读取。交互资料进入正文请求，不代表它会自动成为变量更新的事件材料；代码也不会因设置了 `insist` 就补写模型遗漏的标签。

取消交互停止本次正文，但保留已完成的规划、筛选和待完成交互。胶囊可继续或重新调整该项；确认保存后生成或重新生成正文。普通正文重生成复用已保存结果，顶部整套输入增强重做则重新处理各任务并只保存成果。具体保存、复用和屏蔽规则见[生成拦截接口](../../dvs-docs/references/dvs-api.md#生成拦截)。
