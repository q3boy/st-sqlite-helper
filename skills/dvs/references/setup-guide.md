# 接入与检查

## 新建卡片或接入 DVS

例如，你要做一张图书管理员日常卡，只记录时间地点和随身物品。人物身份、性格和建筑说明是静态设定，留在普通世界书；随故事变化的时间、地点和物品数量才进入 DVS。

1. 列出要保存的字段和起点值，说明每张表怎样定位一行。例如场景用固定编号“当前”，物品用名称；需要区分不同持有人时，物品改用“持有人＋名称”。这组定位字段就是业务键。
2. 写 DDL 建表和各开场白对应的 INIT 初值。每张真实表带 `rid` 主键；业务键在当前状态中唯一，不给完整历史表的业务键加 SQL `UNIQUE`。
3. 在索引登记 SQL、普通设定、正文状态、变量规则和变量数据。SQL 使用 `[DVS:DDL]v版本`、`[DVS:初始化]welcome_编号`；内容宏仍使用 `[[DVS_DATA]]` 等双括号写法。
4. 在一个 DVS 脚本中登记 `uniqueKeys`，提供 `narrativePrepare` 和 `beforeGen`。没有额外处理时，两者直接返回传入的表。脚本默认变量使用 `{ "dvs": { "enabled": true } }`。
5. 生成或导出卡包后，核对包内的世界书与脚本。先用专用新聊天检查 INIT，再用一句会改变物品数量的行动检查正文输入和更新后的实际数据。

直接从[最小卡](../assets/dvs-minimal-card/README.md)改起即可。它不需要状态栏、虚拟表或输入增强；只有自己的规则需要时再加。开场白、SQL、注册与世界书应描述同一份数据，完整接入步骤见[作者手册](../../dvs-docs/references/dvs-author-guide.md#从完整示例开始)。

## 压缩随卡分发的世界书正文

大段世界观、人物资料、DDL、INIT 和角色卡内的酒馆助手脚本都可以压缩。作者仍在 `index.yaml` 里引用明文源文件，在索引旁边新建可选的 `compress-list.yaml`，逐项写入源文件的相对路径和完整文件名：

```yaml
- 世界书/基础物品.sql
- 世界书/开场白/车辆.sql
- 世界书/地区设定.txt
- 脚本/状态栏.js
```

先用原有打包命令从当前索引生成 PNG 或 JSON 卡，再用插件包里的工具制作发布副本。例如：

```sh
node tools/dvs-card-compress.mjs 我的卡/index.yaml 我的卡.png 我的卡-发布.png
```

使用 `dvs` skill 时，脚本位于该包的 `scripts/` 下。例如在卡片工程根目录运行：

```sh
node ".agents/skills/dvs/scripts/dvs-card-compress.mjs" "index.yaml" "原卡.png" "发布卡.png"
```

按实际安装位置替换脚本路径。三个参数依次是索引、原始卡和发布副本。输入为 JSON 卡时，输出也使用 `.json`。

同一个脚本可用 Node.js 22.2 或更高版本，也可将命令开头的 `node` 换成 `bun`。用 `--list-file 路径` 指定另一份清单，相对路径从运行命令的目录算起。清单内的条目路径始终相对于索引目录。在本项目源码中可用 `bun run card:compress` 代替 `node tools/dvs-card-compress.mjs`，参数相同。工具从原始卡中取得各条最终正文，保留打包时的合集拆分和用户名替换结果。清单按文件选择，多个条目引用同一文件时都会压缩，同名条目可以分别选择。内联正文如需压缩，先将它移到文件。默认 PNG 只保留 `ccv3`，即使没有清单也会移除 `chara`。需要保留已有 `chara` 时加 `--save-chara`，其中选中的世界书条目也会压缩。只有 `chara` 的旧 PNG 需要加这个参数；它保留已有角色格式。

终端逐项显示压缩、移除或同步 `chara`、写入发布卡的进度。百分比是处理后大小除以原大小，例如 `25%, 128 KB -> 32 KB`。最后出现“完成”表示发布副本已写入。

默认使用 Brotli 压缩和 U20 文本编码，首行是 `DVS-BROTLI-U20`。面向只支持旧编码的插件时加 `--encoding base64`，首行改为 `DVS-BROTLI-BASE64`。插件按每条正文的首行选择解码方式。明文条目可以照常填写。玩家需安装支持还原的 SQLite Helper 插件；首次载入后，插件将绑定世界书中的压缩正文还原并保存到本地，编辑器和引用该书的其他聊天都能读取明文。再次发布时从当前明文重新打包。

首次解压时，弹窗按条目显示进度。解压和保存期间，“刷新”按钮置灰。全部世界书确认保存后，弹窗保留，点击“刷新”重新加载酒馆页面。如果弹窗列出解压失败的条目，请删除对应世界书，再从角色卡导入内嵌世界书。若仍失败，可重新导入角色卡或联系作者。如果提示保存确认失败，请检查酒馆连接，然后重新打开聊天。错误提示会保留到手动关闭。

清单也可以填写角色脚本的源文件（包括脚本文件夹中的脚本）。多个条目或脚本引用同一个文件时，工具分别压缩每处最终正文。命令行用 `[压缩脚本]` 显示正在处理的脚本文件。需要独立运行的安装、更新引导和世界书版本检查脚本请保留明文，省略其清单项即可。

首次打开聊天时，先处理酒馆弹出的内嵌世界书导入、角色正则启用，以及酒馆助手的角色脚本启用确认。玩家可以分别接受或取消。随后解压弹窗显示已解压的条目或脚本数量。保存时，进度条换成转圈提示，分别显示“正在保存世界书”或“正在将脚本写入角色卡…”。插件通过酒馆助手更新当前角色的脚本，读回酒馆里的角色卡确认保存后才提示刷新。点击刷新时，插件会等酒馆保存玩家的启用选择，再重载页面。导入用的 PNG 仍可用于分发。使用压缩脚本的卡需要支持脚本还原的插件版本，0.6.1 只支持世界书正文还原。

## 按现象检查问题

先确认看的是哪份卡片、哪个聊天和哪个 swipe，再按实际现象检查。不要一开始就删数据库或反复重跑写入。

| 现象 | 先检查什么 |
| --- | --- |
| 新聊天初值不对 | 实际导入的世界书、对应开场白的 INIT、脚本注册错误；改过源文件后是否重新生成并导入卡包 |
| 旧聊天看不到新表数据 | 更高版本 DDL 是否执行、`uniqueKeys` 是否包含新表、新行是否关联当前 fid |
| 正文没看到新字段 | `narrativePrepare` 是否返回字段、正文使用总表还是分表宏、条目是否激活、筛选是否排除了对应行 |
| 模型提出修改但实际值不同 | 更新记录是原始建议；继续检查 `preUpdate`、数据库约束和实际查询结果 |
| 状态栏停在旧值 | 是否首次读取、是否响应 `onUpdate`、重新注册后是否重建订阅、是否复用了旧 state |
| 源文件改了，酒馆还是旧内容 | 生成包是否更新、当前主世界书是否仍是旧版、脚本是否已重载 |
| 查询成功但重新打开后丢失 | 核对文件保存结果；内存查询成功不能证明落盘，按[保存与检查说明](../../st-sqlite-scripting/references/helper-author-guide.md)处理 |

交付时写清改动文件、检查过的输入和结果，以及尚未运行的部分。SQL 或脚本检查通过不等于真实酒馆已经成功；反过来，单次模型输出不符合剧情也不直接证明接口或数据库有故障。
