# 数据加工

## 加工正文数据与计算结果

先问结果用在哪里：只是给正文换一种说法，还是要写入并影响下一轮？前者用准备回调处理提示词副本；后者在更新回调中计算真实状态。模型负责判断已经发生的事实，明确的公式交给代码。

### 把数值转换成正文描述

例如人物表保存好感度，正文只需要看到“初识、熟悉”。在现有注册的 `narrativePrepare` 中增加派生描述，并移除正文不需要的数值：

```js
narrativePrepare: ({ tables }) => ({
  ...tables,
  人物: tables.人物.map(({ 好感度, ...row }) => ({
    ...row,
    关系描述: 好感度 >= 60 ? '熟悉' : '初识',
  })),
}),
beforeGen: (_state, tables) => tables,
```

这是注册选项片段，假定人物以姓名定位，好感度是数值列。阈值由作者决定。数据库仍保存数值，变量模型仍得到完整起点；“关系描述”只出现在本次正文数据中，不新增数据库列，也不增加 DDL 版本。

隐藏内部字段、去掉“未知”值、把多行说明整理为短句，都属于同一类操作。需要筛选的表必须保留完整业务键。若状态栏也要显示同样的阶段，可以复用同一个计算函数，从原始数值计算；不要为了显示方便维护两份独立的阶段数据。辅助方法见[预处理表数据](../../dvs-docs/references/dvs-api.md#预处理表数据)。

### 在写入前完成固定计算

例如装备表有基础防御、强化等级和最终防御，卡片规则规定：最终防御等于基础防御加上强化等级的两倍。让模型更新有剧情依据的输入字段，由 `preUpdate` 统一计算最终值：

```js
preUpdate: (_state, newTables) => ({
  ...newTables,
  装备: newTables.装备.map(row => ({
    ...row,
    最终防御: row.基础防御 + row.强化等级 * 2,
  })),
}),
```

三个字段必须已在真实表中声明，规则也要说明最终防御由代码计算。这里处理的是准备写入的结果，返回后由 DVS 写库；不需要额外虚拟表。使用数据库生成列时则交给数据库计算，回调不要给生成列赋值。

单位换算、固定舍入和业务限制也可放在这里，但限制如何处理由卡片规则决定。例如数量不足究竟拒绝本次结果，还是按实际余量扣除，要先写清楚，不能无声地换一种算法。回调应返回全部真实注册表，保留未改动的表和字段。输入与返回要求见[数据准备和更新回调](../../dvs-docs/references/dvs-api.md#数据准备和更新回调)。

### 用虚拟表记录本轮事件

如果固定计算还缺少输入，例如正文中发生了“甲把两本书交给乙”，可以让模型把交付双方、物品和数量写入虚拟表。虚拟表只是本次请求的数据，不保存为业务表。

步骤是：在注册中声明事件字段 → 在变量规则中说明怎样从已经发生的正文提取事件 → 用 `preUpdate` 从 `oldTables` 起点计算数量 → 把结果写回 `newTables` 的真实表 → 删除虚拟表后返回。完整的[库存收支示例](../../dvs-docs/references/dvs-api.md#虚拟表输入与写库前计算)给出了注册与回调片段。

`oldTables` 是本轮完整起点。重新计算时始终从它开始，不从上次计算结果继续扣减；也不要用回调中重新查询的“最新状态”替换它。没有事件时真实数据保持起点，计划中的交付不当作已发生。只有需要这些临时事实时才使用虚拟表，普通字段更新仍可直接使用模型补丁。

检查这类改动时，用几个明确输入核对代码结果：无事件、一次收入、一次支出、作者定义的上下限或舍入边界。派生显示检查正文副本与原值，结算检查真正返回的持久数据；两种检查不能互相代替。
