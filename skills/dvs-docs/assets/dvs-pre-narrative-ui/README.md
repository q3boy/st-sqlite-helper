# 生成拦截最小组件

[interaction.js](interaction.js) 是原生 DOM 组件示例：玩家可以编辑访客资料，也可以请求模型生成候选；确认后保存资料，取消则停止本次生成。胶囊展示最终资料，正文使用 `toPrompt` 返回的内容。

将示例中的 `exampleInteraction` 放在已有作者脚本的 `DVS.register` 调用之前，并把 `preNarrativeUi: [exampleInteraction]` 加入该调用。保持角色卡已有的业务键和准备回调。在脚本的 DVS 预设变量中显式启用 `exts.pre_narr_ui: true`，并在插件模型配置中为输入增强选择模型。此例的触发条件是邀请新访客进入书店，可以按角色卡场景修改。

`complete` 提交的是可序列化的最终资料；正文重新生成时 DVS 使用保存的资料再次调用 `toPrompt`。模型请求可能失败，示例保留当前候选并显示错误，玩家可以再次生成、编辑、确认或取消。

DVS 提供透明弹层，组件自行提供标题和取消按钮。取消保留已完成的规划和筛选；胶囊中的“继续交互”或“重新调整”只重开本项，已保存结果通过 `context.result` 传入。示例从旧 description 开始编辑，确认保存后由酒馆生成或重新生成正文；顶部整套输入增强重做仍只保存记录。

`exampleRequests` 是作者自己定义的函数对象，`initial`、`regenerate` 不是 DVS 保留名称。控件可直接调用函数，也可自行按属性名选择函数；支持异步函数读取世界书后再返回完整请求。`sendExampleRequest` 等函数返回后，对每条消息展开一次 DVS 宏再调用 `requestModel`。两种请求都带最近正文与本轮用户输入，重新生成另带当前候选和调整要求。

`narrativeEntriesSkip: ['自动访客生成']` 表示玩家确认并保存后，本轮正文不再使用该自动生成条目。请换成自己世界书中去掉 DVS 标签后的实际名称；未匹配时不处理。原有标签、原生激活和普通筛选保持各自规则，世界书原文不被修改。
