# 旧版 DVS 卡片升级

旧脚本配置、旧 API、旧世界书标签和旧消息胶囊继续兼容，不要求所有作者立刻转换。新卡使用本手册的新版写法；整理旧卡源文件时，优先用随包工具转换，再检查自己的工程。仅改标签和默认配置不会改变业务表结构，无需新增 DDL 版本、重跑 INIT 或改写历史聊天。需要增加持久字段时，另按[业务表升级](dvs-api.md#角色卡升级)操作。

### 使用独立转换工具

工具只接受酒馆同步工具的 `index.yaml` 源格式。它改写 `条目[].名称`，以及 `扩展字段.酒馆助手.脚本库` 中各脚本的旧 DVS 配置（包括脚本分组内的 `数据`），不读取或改写引用的正文、SQL、JS 文件，不接受 PNG／JSON 卡包，也不连接酒馆。先保留自己的源文件副本或版本记录；工具原地写回指定索引，不自动创建备份。

完整发布包提供 `tools/dvs-card-migrate.mjs`；独立 skill 中，只有 `dvs` 和 `dvs-card-migrate` 提供 `scripts/dvs-card-migrate.mjs`，三处是相同脚本。`dvs-docs` 只提供转换说明，不携带脚本。需要 Node.js；支持目标为 22.6 及以上，目前独立运行检查使用 26.8.1，未逐版本验证。脚本已包含依赖，无需开发仓库、Bun、npm 安装或网络。从相应包目录执行，路径有空格时加引号：

```sh
# 完整发布包
node tools/dvs-card-migrate.mjs "/path/to/card/index.yaml"
# 在 dvs 或 dvs-card-migrate skill 目录中执行
node scripts/dvs-card-migrate.mjs "/path/to/card/index.yaml"
```

每遇到一个旧 `[DVS_FILTER_RULES]` 条目，终端提供三选一：

| 输入 | 新名称 | 何时选择 |
| --- | --- | --- |
| `1` 或回车 | `[DVS:筛选规则]` | 默认保留共用规则，对世界书和变量行筛选都有效 |
| `2` | `[DVS:世界书筛选规则]` | 作者明确只给世界书筛选使用 |
| `3` | `[DVS:变量筛选规则]` | 作者明确只给变量行筛选使用 |

选择 2 或 3 是主动改变规则适用范围，工具不根据正文猜测、不复制规则。无交互环境须显式给出本次所有旧规则的选择；保持原行为用 `common`，其他值为 `worldbook`、`variables`：

```sh
node tools/dvs-card-migrate.mjs "/path/to/card/index.yaml" --filter-rules common
```

没有旧共用规则时不询问。需要选择而没有终端及参数时退出且不写文件；未知旧标签、同条目新旧混用、不支持的 YAML 写法或无法无损转换的组合也会报错。先处理提示，不把错误当成已完成。所有解析与选择完成后才写回，并读回核对。输出条目改名及配置转换摘要，不打印完整脚本变量；注释、条目顺序、无关字段和换行保留。再次运行已转换索引会报告无变化。

### 按完整标签组合核对

下表用共用筛选规则说明等价转换。范围词与用途词共同决定行为，不能只替换 `[DVS_NAR]` 为 `[DVS:正文]`，那样会丢掉原预处理范围。无 DVS 标签的普通条目无需改名。表中组合不受旧标签排列顺序影响。

| 分类 | 旧标签 | 新标签 | 用途 |
| --- | --- | --- | --- |
| 输入预处理 | `[DVS_FILTER]`，无其他范围标签 | `[DVS:正文,后处理;可筛选]` | 保留旧普通条目的默认正文和后处理范围；可筛选自带预处理。已有 NAR／VAR／SKIP 时须按完整组合判断 |
| 输入预处理 | `[DVS_FILTER_RULES]` | `[DVS:筛选规则]` | 条目筛选和表行筛选的公共规则，包含分析、检查要求 |
| 输入预处理 | `[DVS_PLOT]` | `[DVS:剧情规划]` | 剧情规划规则，包含分析、检查要求 |
| 请求范围 | `[DVS_FILTER_SKIP]`，未搭配其他范围标签 | `[DVS:正文,后处理]` | 跳过输入预处理，正文和后处理均可使用 |
| 请求范围 | `[DVS_NAR]` | `[DVS:预处理,正文]` | 可参与输入预处理和正文，不进入后处理 |
| 请求范围 | `[DVS_VAR]` | `[DVS:后处理]` | 仅用于后处理上下文 |
| 请求范围 | `[DVS_NAR]` ＋ `[DVS_FILTER_SKIP]` | `[DVS:正文]` | 仅用于正文，不参与输入预处理 |
| 请求范围 | `[DVS_VAR]` ＋ `[DVS_FILTER_SKIP]` | `[DVS:后处理]` | 仅用于后处理 |
| 请求范围 | `[DVS_NAR]` ＋ `[DVS_VAR]` | `[DVS:预处理,正文,后处理]` | 三轮请求均可使用 |
| 请求范围 | `[DVS_NAR]` ＋ `[DVS_VAR]` ＋ `[DVS_FILTER_SKIP]` | `[DVS:正文,后处理]` | 跳过输入预处理，正文和后处理均可使用 |
| 正文后处理 | `[DVS_RULES]` | `[DVS:变量规则]` | 变量更新规则 |
| 正文后处理 | `[DVS_DATA]` | `[DVS:变量数据]` | 变量请求的数据输入模板 |
| 正文后处理 | `[DVS_VAR_COT]` | `[DVS:变量COT]` | 变量更新的可选分析、检查要求 |
| 数据库 | `[DVS_DDL]v版本` | `[DVS:DDL]v版本` | 数据库结构迁移 |
| 数据库 | `[DVS_INIT]welcome_编号` | `[DVS:初始化]welcome_编号` | 开场白数据库初始化 |
| 元数据 | `[DVS_VERSION]` | `[DVS:版本]` | 主世界书内容版本 |
| 可筛选范围 | `[DVS_NAR][DVS_FILTER]` | `[DVS:正文;可筛选]` | 可参与预处理筛选和正文，不进入后处理 |
| 可筛选范围 | `[DVS_VAR][DVS_FILTER]` | `[DVS:后处理]` | 旧 VAR 单独范围不参与正文筛选，不能扩大为新可筛选条目 |
| 可筛选范围 | `[DVS_NAR][DVS_VAR][DVS_FILTER]` | `[DVS:正文,后处理;可筛选]` | 保留三阶段用途与筛选能力 |
| 跳过筛选 | `[DVS_FILTER][DVS_FILTER_SKIP]` | `[DVS:正文,后处理]` | SKIP 覆盖 FILTER；搭配 NAR 时只保留正文，搭配 VAR 时只保留后处理，两者都有则保留正文和后处理 |
| 后处理专用 | RULES／DATA／VAR_COT 搭配 NAR、VAR、FILTER 或 FILTER_SKIP | 对应变量规则／变量数据／变量COT | 旧专用用途优先，工具保留其后处理含义 |
| 预处理专用 | FILTER_RULES／PLOT 搭配 NAR、VAR 或 FILTER | 对应筛选规则／剧情规划 | 旧专用用途优先；若还含 FILTER_SKIP，工具报错，不写文件 |

元数据标签必须单独位于名称开头；多个专用用途冲突时应先由作者理清用途。旧筛选规则或剧情规则带 FILTER_SKIP 时原本不参与预处理，新用途自带预处理范围，工具拒绝自动转换；不能为了消除报错而启用原本未生效的规则。

这里只改条目名称。正文里的 `[[DVS_DATA]]`、`[[DVS_FILTER:条件]]`、`[[DVS_PLOT:start:字段]]`／`[[DVS_PLOT:end]]` 是内容宏，继续原样使用。作者回调、EJS 查询、业务键和 SQL 内容也不因标签改名而一起改名。

### 默认配置与玩家配置

旧默认配置按实际布尔值转换：

| 旧值 | 新字段与结果 |
| --- | --- |
| `dvs_enable` | `dvs.enabled`，必须是布尔值 |
| `dvs_input_inject === true` | `dvs.exts.tables_opt: true` 和 `dvs.config.lb_opt.llm_filter: true`；否则两项 false |
| `dvs_input_inject === true && dvs_plot === true` | `dvs.exts.plot_plan: true`；否则 false，保留旧总开关下实际生效的行为 |

转换移除这三个已转换的旧字段，保留其他作者变量。已有合法 `dvs` 时以它为准，不让旧字段覆盖它；已有新对象非法时报告错误。运行时读取旧玩家配置也使用同样规则。新配置的两项筛选与规划独立选择，不需要保留旧总开关的联动；基础扩展与新 API 见[配置接口](dvs-api.md#输入增强接口)。旧 `getInject/setInject` 仍可使用，但它的 filter 同时控制两种筛选，不能表达只开其中一种；不要误把自定义面板的联动当作新版 DVS 的限制。

索引里的配置是下次导入的作者默认值，不等于玩家正在使用的脚本变量。工具不接触在线配置，也不会用新默认值覆盖玩家选择。交付时说明脚本如何更新和重载，并让玩家核对实际启用项。

### 从源文件到交付包

1. 检查索引差异：条目数量、文件引用、启用／激活条件、插入位置与顺序保持原意，所有改名与默认配置符合上面的选择。确认宏正文和业务文件没有被批量替换。
2. 搜索自有打包脚本、升级脚本、测试和说明中精确匹配旧条目名的地方，按新名称更新。例如读取世界书版本的工具要找 `[DVS:版本]`；仅随本卡发布的构建脚本可直接跟随卡片修改，无需额外添加旧标签分支。DVS 自带版本检查仍同时识别新旧名称。
3. 需要分发新内容时，按自己的工具同步卡片内容版本和主世界书版本，再从源文件生成导入包。DDL 版本只随业务结构变化；这三种版本不要混用。读回导入包中的条目名称、内容引用结果及脚本默认配置，确认没有拿到旧包。
4. 更新卡片不保证玩家现用的主世界书同步更新。按[主世界书版本检查](dvs-author-guide.md#可选检查主世界书版本)保留玩家修改、更新关联并刷新页面，核对实际世界书与脚本变量。
5. 按受影响范围检查新聊天初始化和已有聊天读取、正文注入、变量更新及用到的筛选／规划。分别报告静态检查、工具测试、导入包检查和真实运行；转换命令成功不等于已完成酒馆验证。

工具不更新测试、打包工具、说明、版本号或导入包，不改数据库和聊天。将这些工程步骤按卡片实际情况完成即可，无需为一次写法升级增加全套业务系统或重测无关功能。
