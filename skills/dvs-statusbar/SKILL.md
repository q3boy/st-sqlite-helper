# 制作 DVS 悬浮状态栏

先读[制作悬浮状态栏](references/statusbar-guide.md#制作悬浮状态栏)，检查卡片的注册脚本、现有界面和待展示字段。沿用现有技术栈；没有界面时按用户需求选择简单实现，不为数据展示强加框架。

## 接入数据

1. 明确显示当前状态还是指定历史楼层。使用 DVS 查询有效状态，按完整业务键取数据；查询方法见[注册与查询](../dvs-docs/references/dvs-api.md#注册与查询)。状态栏不另建一份业务注册。
2. 界面准备好后等待 DVS 公共接口，并订阅注册状态。就绪时读取数据和当前进度，建立更新订阅；重新注册后重建这些订阅。按[注册状态与脚本关闭](../dvs-docs/references/dvs-api.md#注册状态与脚本关闭)处理生命周期。
3. 数据更新、聊天或 swipe 切换后重新取得状态，不复用旧目标的 state。异步结果只更新仍对应的界面；分别显示未就绪、无数据、读取失败，旧数据不能冒充新目标结果。
4. 卸载时移除本次界面、事件和订阅。悬浮界面自行挂载，不依赖正文里的状态栏占位标签。

## 界面与操作

显示字段、布局、配色和展开方式服从用户要求。数值转阶段等显示逻辑见[数据加工](../dvs-docs/references/data-processing-guide.md#加工正文数据与计算结果)，仅显示需要的描述时不写数据库。

只有用户需要时才加入修改值、重新更新等按钮；使用 DVS 对应方法，并按其状态显示进行中、结果和错误。接口见[修改与逻辑事务](../dvs-docs/references/dvs-api.md#修改与逻辑事务)及[主动更新变量](../dvs-docs/references/dvs-api.md#主动更新最新回复的变量)。界面不能通过直接 SQL 绕过 DVS 的楼层与历史管理。

## 交付

交付界面源文件、接入脚本和必要的打包说明。按可用环境检查首次显示、更新、切换及卸载；界面检查同时看布局和内容。说明哪些证据来自模拟、哪些来自真实酒馆。此 skill 不自动部署、导入或操作现有聊天数据。

需要完整接口或本场景以外的规则时，使用 `dvs-docs`，按问题查对应章节，不必通读全部手册。安装时保留配套资料包，见各包 `source.json` 的 `requires`。
